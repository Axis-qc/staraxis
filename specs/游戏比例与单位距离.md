# 游戏比例与单位距离文档

**目的**: 明确游戏中各种单位距离的设置，包括游戏比例、恒星大小、行星大小、轨道大小、星区大小等。

**更新日期**: 2026-01-06

---

## 核心概念

### 游戏单位系统

游戏使用**两套单位系统**：
1. **逻辑单位（Logic Units）**：用于游戏逻辑计算、数据存储
2. **渲染单位（Render Units）**：用于屏幕显示，与逻辑单位有转换关系

**注意**：当前系统中，逻辑单位和渲染单位之间的转换关系尚未完全统一，需要进一步规范化。

---

## 1. 星区大小（Sector Size / HexTile Size）

### 逻辑单位

- **星区（Sector）**：六边形区块单元，使用立方体坐标系统（`HexCoord`）
- **区块大小（blockSize）**：配置中的逻辑单位
  - 小型地图：`blockSize = 1.0`
  - 中型地图：`blockSize = 1.0`
  - 大型地图：`blockSize = 1.0`
  - **单位**：游戏单位（game units）
  - **位置**：`assets/i18n/world-block-scale-config.properties`

### 渲染单位

- **六边形半径（hexRadius）**：`50.0f` 像素
  - 从六边形中心到顶点的距离
  - **位置**：`lwjgl3/src/main/java/com/staraxis/game/client/ui/view/HexGridRenderer.java:16`
  - **说明**：这是渲染时的视觉大小，与逻辑单位 `blockSize` 的对应关系需要明确

### 星系规模（Galaxy Scale）

- **定义**：大地图的半径，以六边形星区数量为单位
- **预设值**（位置：`shared/src/main/resources/worldgen/map-presets.properties`）：
  - `small = 5`（半径为 5 个星区）
  - `medium = 10`（半径为 10 个星区）
  - `large = 20`（半径为 20 个星区）
- **计算方式**：
  - 如果使用区块规模配置：`radius = ceil(max(width, height) / 2.0)`
  - 如果使用预设：直接读取预设值

## 2. 轨道大小（Orbit Size）

### 逻辑单位

- **轨道半长轴（semiMajorAxis）**：游戏单位
  - **基础公式**：`baseScale = 1.0f + orbitIndex * 1.25f`
  - **随机抖动**：`scaleJitter = 0.85f + random * 0.3f`（范围 0.85-1.15）
  - **最终值**：`scale = baseScale * scaleJitter`
  - **位置**：`core/src/main/java/com/staraxis/game/core/world/stellar/orbit/OrbitParamSampler.java:21-23`
  - **示例**：
    - 第 0 轨道：`1.0 * (0.85-1.15) = 0.85-1.15` 游戏单位
    - 第 1 轨道：`2.25 * (0.85-1.15) = 1.91-2.59` 游戏单位
    - 第 2 轨道：`3.5 * (0.85-1.15) = 2.98-4.03` 游戏单位

- **轨道尺度（scale）**：向后兼容字段，等价于 `semiMajorAxis`
  - **位置**：`shared/src/main/java/com/staraxis/game/shared/world/stellar/orbit/Orbit.java:17`

### 渲染单位

- **恒星轨道半径（STAR_ORBIT_RADIUS）**：`24.0f` 像素
  - 用于渲染双星/三星系统的恒星位置
  - **位置**：`lwjgl3/src/main/java/com/staraxis/game/client/ui/view/stellar/StellarMarkerRenderer.java:28`

- **行星轨道半径（PLANET_ORBIT_RADIUS）**：`32.0f` 像素
  - 用于渲染行星围绕恒星的位置
  - **位置**：`lwjgl3/src/main/java/com/staraxis/game/client/ui/view/stellar/StellarMarkerRenderer.java:30`

- **轨道调试缩放（orbitDebugScale）**：`40.0f`（可通过系统属性 `staraxis.orbitDebugScale` 配置）
  - 用于调试渲染轨道路径
  - **位置**：`lwjgl3/src/main/java/com/staraxis/game/client/ui/screens/WorldScreen.java:94`

### 轨道稳定性检查

- **碰撞半径（collisionRadius）**：`0.1f` 游戏单位
  - 用于轨道稳定性检查
  - **位置**：`core/src/main/java/com/staraxis/game/core/world/stellar/StellarGenerator.java:80`

- **最小距离倍数（MIN_DISTANCE_MULTIPLIER）**：`2.0f`
  - 最小安全距离 = `collisionRadius * 2.0 = 0.2f` 游戏单位
  - **位置**：`core/src/main/java/com/staraxis/game/core/world/stellar/orbit/OrbitStabilityChecker.java:20`

## 5. 游戏比例关系

### 当前比例关系（渲染单位）

```
星区大小（hexRadius）: 50.0 像素
  ├─ 恒星轨道半径: 24.0 像素（约 48% 星区半径）
  │   └─ 恒星半径: 12.0 像素（约 24% 星区半径）
  └─ 行星轨道半径: 32.0 像素（约 64% 星区半径）
      └─ 行星半径: 6.0 像素（约 12% 星区半径）
```

### 逻辑单位与渲染单位的对应关系

**⚠️ 当前问题**：
- 逻辑单位（`blockSize = 1.0`，轨道 `semiMajorAxis`）与渲染单位（`hexRadius = 50.0` 像素）之间的转换关系**未明确定义**
- 需要建立统一的转换比例，例如：
  - `1.0 游戏单位 = ? 像素`
  - 或者：`1 星区 = ? 游戏单位 = ? 像素`

## 8. 待解决的问题

### 高优先级

1. **逻辑单位与渲染单位的转换关系**
   - 需要定义：`1.0 游戏单位 = ? 像素`
   - 或者：`1 星区（逻辑） = ? 游戏单位 = ? 像素（渲染）`

2. **恒星和行星的物理大小**
   - 当前只有渲染标记大小，没有逻辑物理大小
   - 建议：在 `Star` 和 `Planet` 类中添加 `radius` 或 `diameter` 字段

3. **轨道大小的统一**
   - 轨道半长轴使用游戏单位，但渲染时使用固定像素值
   - 需要建立：`轨道半长轴（游戏单位） → 渲染像素` 的转换

### 中优先级

4. **区块大小（blockSize）的实际用途**
   - 当前所有预设都是 `1.0`，需要明确这个值的实际作用
   - 是否应该影响星区之间的间距？

5. **星系规模与区块规模的协调**
   - 星系规模（半径）与区块规模（宽度×高度）的对应关系需要更明确

---

## 9. 建议的改进方向

### 方案 A：统一单位系统

1. 定义基础单位：`1 游戏单位（AU） = 100 像素`
2. 星区大小：`1 星区 = 1.0 AU = 100 像素`（当前 `hexRadius = 50` 需要调整）
3. 轨道大小：使用逻辑单位，渲染时按比例转换
4. 恒星/行星大小：添加逻辑半径，渲染时按比例转换

### 方案 B：保持当前系统，明确转换

1. 保持当前渲染大小不变
2. 定义转换比例：`1 星区（逻辑） = 50 像素（渲染）`
3. 轨道渲染大小根据逻辑半长轴动态计算
4. 恒星/行星大小根据类型定义逻辑半径，渲染时转换
