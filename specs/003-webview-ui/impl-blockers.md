## 当前阻塞

你选择的方案是 **JCEF（Chromium）+ Windows**，并且要求 **原生包随项目管理/随打包分发**。

因此在开始实现 WebView 前，需要先准备 **JCEF Windows 原生二进制包** 并放入项目目录（对应 `tasks.md` 的 T006）。

在缺少该包时：
- 可以继续做 UI 资源（`assets/ui/start-menu/index.html`）与桥接协议/代码结构准备。
- 但无法完成：JCEF 初始化、启动时加载页面、运行时验证、退出时清理验证。

## 你需要准备什么

- **Windows x64** 对应的 JCEF 原生发行包（通常是一个压缩包/目录），其内容一般包含：
  - `jcef`/`libcef` 等动态库
  - `locales/`、`resources/` 或类似资源目录
  - 其他运行时依赖文件（不同发行版略有差异）

## 放置位置约定

- 建议放在：`lwjgl3/natives/jcef-windows/`
- 要求：该目录在运行时可被 JCEF loader 找到，并在未来打包时被一起带上。

## 获取来源（不自动下载，仅提供选择建议）

你可以用以下任一方式获取 JCEF Windows 包：

- **方式 A（推荐）**：使用项目/团队内部已验证过的 JCEF 包（版本固定、最稳）
- **方式 B**：从 JCEF 的官方/社区发行渠道获取 Windows x64 包，并选择与“计划引入的 Java 依赖版本”兼容的发行版

### 版本选择原则

- **优先选择**：与你将要引入的 JCEF Java 依赖（T004）明确匹配的那一版原生包
- **避免**：随便拿一个 Chromium/JCEF 版本不匹配的包，否则常见报错是“找不到符号/接口不一致/启动失败”
