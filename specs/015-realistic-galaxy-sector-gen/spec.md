# Feature Specification: 015 - 真实比例六边形星区与内容分配

**Feature Branch**: `015-realistic-galaxy-sector-gen`  
**Created**: 2026-01-08  
**Status**: Draft  
**Input**: User description: "六边形星区的边长为1光年，“星系”大小由开局设置决定，星区内生成恒星系的概率同样由开局设置决定；地图生成顺序为：固定生成星系（随机位置或固定位置）→按开局比例在剩余星区分配→按分配生成恒星系/深空/星云等。"

## Clarifications

### Session 2026-01-08

- Q: 本期内容类型是否需要全量对齐《游戏大纲》区域类型？ → A: 本期仅支持 星系/星云/深空（子集），但数据结构与渲染接口必须预留可扩展（后续可加入风暴/深空资源区等）。
- Q: SectorContentType 在代码/数据驱动层面的表示方式采用哪种？ → A: 使用字符串 ID（数据驱动）：例如 star-system / nebula / deep_space，并由 JSON/数据表注册可用类型与渲染映射。
- Q: FR-010 中“生成并绑定一个恒星系对象”的具体范围是什么？ → A: 仅生成占位符：一个带 ID 的空对象，表示“这里有星系”，具体内容（如主星、行星）由其他功能或按需生成。
- Q: GalaxyPreset（预设）来源采用哪种方式？ → A: JSON 数据文件（可随游戏/Mod 加载，生成器读取并应用）。
- Q: FR-011 的映射接口输出形态选哪种？ → A: 返回只读快照/DTO（在 shared 定义 UniverseSnapshot/SectorSnapshot 等），客户端通过 adapter 转为渲染模型。

- Q: 多个预设星系/固定区域尝试占用同一 HexCoord 时如何处理冲突？ → A: 后来者覆盖（按加载顺序，最后一个声明占用的预设覆盖之前的占用）。
- Q: “星系大小”参数采用哪种定义？ → A: 六边形半径 R（圈数，生成 0..R 圈；总星区数 = 1 + 3R(R+1)）。
- Q: 当内容分配比例之和不为 1.0 时，系统应如何处理？ → A: 由开局设置 UI 保证比例和为 1.0，生成器可假设输入合法。
- Q: 当固定生成/预设占用导致剩余星区不足以按比例分配时，如何处理？ → A: 尽量分配，不足则截断（按固定内容类型顺序分配到用尽为止），并记录日志/调试提示。
- Q: 当需要“截断”时，内容类型的固定分配顺序是什么？ → A: 恒星系 → 星云 → 深空。
- Q: 内容分配的确定性规则采用哪种？ → A: 按 HexCoord 排序，并为每个星区使用 seed + HexCoord 派生随机（与遍历顺序/并行无关）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 开局生成六边形星区星系（真实比例） (Priority: P1)

玩家在开始新游戏时，系统根据“开局设置”的星系大小参数生成一个由六边形星区构成的星系，并且星区中心点的世界坐标严格遵循“边长=1光年”的真实比例。

**Why this priority**: 这是后续内容分配、恒星系生成、星图导航、比例尺与坐标系统验证的基础。如果星区与坐标比例不一致，后续内容将无法对齐。

**Independent Test**: 仅实现该故事即可通过调试/日志/可视化验证：星区六边形拓扑正确；任意相邻星区中心距离与 1ly 边长换算后的值一致（在可接受误差内）。

**Acceptance Scenarios**:

1. **Given** 玩家在开局设置中配置星系大小参数，**When** 点击开始新游戏并完成世界生成，**Then** 星系由六边形星区组成，且星区数量/范围与星系大小参数匹配。
2. **Given** 星区已生成，**When** 取任意一对相邻星区中心点的世界坐标并换算距离，**Then** 该距离与六边形边长=1光年所定义的相邻中心距离一致（误差阈值见 SC-002）。

---

### User Story 2 - 固定生成“核心星系/固定区域”，其余星区按比例分配内容类型 (Priority: P2)

玩家在开始新游戏时，系统先生成一组“固定生成的星系/核心区域”（可以是固定位置或随机位置，但必须可复现），随后在剩余星区中按开局设置的比例参数对内容类型进行分配（例如：恒星系/星云/深空）。

**Why this priority**: 该流程决定了“地图生成顺序”和内容密度分布，是后续恒星系生成的输入。

**Independent Test**: 固定种子下生成可复现；统计结果与配置比例匹配；且固定生成区域不会被二次分配覆盖。

**Acceptance Scenarios**:

1. **Given** 玩家配置了“固定生成星系”的策略（随机或固定位置）与随机种子，**When** 生成星系，**Then** 固定生成的星系/核心区域会首先被标记并占用一批星区，且同配置+同种子下可复现。
2. **Given** 玩家配置了内容分配比例（例如恒星系/星云/深空），**When** 在“剩余星区”执行分配，**Then** 分配结果的比例接近配置值，且不会覆盖已被固定生成占用的星区（误差阈值见 SC-003）。

---

### User Story 3 - 根据分配结果生成恒星系/星云/深空，并可用于渲染验证 (Priority: P3)

玩家进入星图界面时，系统能将不同类型星区（恒星系/星云/深空）的标记渲染到正确位置；当玩家按下 F3 时，可在调试面板看到坐标与比例尺，验证真实比例与星区间距一致。

**Why this priority**: 避免“只有生成逻辑、没有实际渲染接入”。同时复用 014 的坐标系/比例尺调试能力，证明真实比例落地。

**Independent Test**: 仅实现该故事可在星图界面看到星区内容类型分布与恒星系标记；按 F3 能显示坐标/比例尺并用于测距验证。

**Acceptance Scenarios**:

1. **Given** 星系已生成且进入星图界面，**When** 渲染星区标记，**Then** 不同内容类型的星区可被区分显示，且位置与星区中心世界坐标一致。
2. **Given** 玩家按下 F3 打开调试，**When** 读取当前相机比例尺与两相邻星区的屏幕像素距离，**Then** 结合比例尺换算得到的世界距离与 1ly 规则一致（误差阈值见 SC-002）。

---

### Edge Cases

- 当星系大小配置非常小（例如仅 1 个星区）时，星区生成是否仍满足六边形拓扑约束？
- 当预设星系/固定生成占用星区过多导致“剩余星区不足”时，系统如何处理（尽量分配，不足则截断；并记录日志/调试提示）？
- 当内容比例之和不为 1 时，系统如何归一化或拒绝配置？
- 当恒星系比例为 0% 或 100% 时，生成结果是否分别为全空/全满且可复现？
- 当星系大小配置非常大时，是否会导致生成时间过长或内存占用不可接受？
- 当玩家未指定种子时，系统是否仍能生成且记录本次种子用于复现？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供“开局设置”参数：星系大小，定义为六边形半径 R（圈数，生成 0..R 圈；总星区数 = 1 + 3R(R+1)）。
- **FR-002**: 系统 MUST 提供“开局设置”参数：内容分配比例（本期至少包含：恒星系/星云/深空），比例取值范围为 0.0~1.0，且开局设置 UI MUST 保证比例之和为 1.0（生成器可假设输入合法）。
- **FR-003**: 系统 MUST 支持指定随机种子以保证星系生成结果可复现（同配置+同种子 -> 同结果）。

- **FR-004**: 系统 MUST 以六边形网格方式生成星区拓扑，并能为每个星区分配唯一标识。
- **FR-005**: 系统 MUST 定义六边形星区的边长为 1 光年（1ly），并将该真实比例转换为世界坐标单位用于定位。
- **FR-006**: 系统 MUST 为每个星区计算其中心点世界坐标（3D 世界坐标中使用 XY 平面即可，Z 默认为 0）。

- **FR-007**: 系统 MUST 按“地图生成顺序”执行：
  1) 固定生成星系/核心区域（位置可为固定或随机，但必须可复现）；
  2) 在剩余星区内按开局设置比例分配内容类型；
  3) 根据分配结果生成对应内容（恒星系/星云/深空等）。

- **FR-008**: 系统 MUST 支持通过 JSON “游戏文件预设”配置一组特殊星系/固定区域（Preset Special Galaxies，支持随游戏/Mod 加载），并在生成顺序的第 1 步优先应用。
  - 每个预设至少包含：星系标识、占用星区集合的生成规则（固定 HexCoord 或随机 HexCoord）。
  - 随机 HexCoord 必须可复现（受随机种子影响）。
  - 预设之间若发生 HexCoord 占用冲突，采用“后来者覆盖”：按预设加载顺序，最后一个声明占用的预设覆盖之前的占用。
  - 后续内容分配不会覆盖这些已占用星区。
- **FR-009**: 系统 MUST 在剩余星区内按比例分配内容类型，并能输出每个星区的内容类型；分配 MUST 具备确定性：按 HexCoord 排序，并为每个星区使用 seed + HexCoord 派生随机（与遍历顺序/并行无关）；当剩余星区不足以满足目标分配数量时，系统 MUST 采用“尽量分配，不足则截断”的策略，并记录日志/调试提示；截断时固定分配顺序为：恒星系 → 星云 → 深空。
- **FR-010**: 系统 MUST 根据内容类型为星区生成对应内容数据：
  - 恒星系：生成并绑定一个恒星系对象（本期为占位符：仅含唯一 ID 与所属星区引用；不生成主星/行星等细节内容）；
  - 星云：生成星云标记/属性并绑定；
  - 深空：标记为空旷区域并绑定。

- **FR-011**: 系统 MUST 提供星区中心世界坐标与星区/内容数据（恒星系/星云/深空）的映射接口，供星图渲染与拾取使用；接口输出 MUST 为只读快照/DTO（在 shared 定义 UniverseSnapshot/SectorSnapshot 等），客户端通过 adapter 转为渲染模型（避免直接暴露生成器内部对象，满足 C/S 分离）。

### Key Entities *(include if feature involves data)*

- **Galaxy（星系）**: 由多个六边形星区组成；受开局“星系大小”配置控制。
- **Sector（星区）**: 六边形网格单元；包含唯一 ID、六边形坐标（HexCoord）以及中心点世界坐标（WorldCoordinate 或等价表示）。
- **SectorContentType（星区内容类型）**: 本期支持：恒星系 / 星云 / 深空（用于分配与渲染）。类型在数据驱动层以字符串 ID 表示（例如：`star-system` / `nebula` / `deep_space`），并由 JSON/数据表注册可用类型与渲染映射；后续可扩展加入：风暴区域、深空资源区等。
- **StarSystem（恒星系）**: 仅在内容类型为恒星系时生成；隶属于某个星区。
- **Nebula（星云）**: 仅在内容类型为星云时生成；隶属于某个星区。
- **DeepSpace（深空）**: 仅在内容类型为深空时存在；表示该星区为空旷。
- **GameStartSettings（开局设置）**: 包含星系大小、固定生成策略参数、内容分配比例、随机种子等。
- **GalaxyPreset（星系预设）**: 来自游戏文件的预设定义；包含预设星系/固定区域的放置规则（固定 HexCoord 或随机 HexCoord），用于在生成顺序中优先占用星区。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在默认配置下，生成星系并进入星图界面的总耗时不超过 3 秒（以本地单机为基准）。
- **SC-002**: 相邻星区中心点的世界坐标距离与“边长=1ly”的理论值误差不超过 1%（用于验证真实比例映射）。
- **SC-003**: 在星区数量 N ≥ 200 时，内容类型分配占比与配置比例的偏差不超过 ±10%，且固定生成占用的星区不被覆盖。
- **SC-004**: 在相同随机种子与相同开局设置下，连续生成 3 次星系结果应完全一致（星区布局、内容分配与恒星系分布一致）。

## Assumptions

- 开局设置中“星系大小”“内容分配比例”“固定生成策略（随机/固定）”将被提供（可能需要扩展 UI/配置结构）。
- 世界坐标单位与 014 保持一致：逻辑世界距离基准单位为 km；因此 1ly 需要换算为 km（用于定位星区中心）。
- 星图渲染层能消费星区中心坐标与内容类型/恒星系存在性以绘制标记；具体渲染细节不在本 spec 中规定。
