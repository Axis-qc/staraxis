# Spec: 014 - 基础坐标系与比例尺

**版本**: 1.0
**状态**: 初稿

## 1. 功能描述

为游戏建立一个统一的基础三维“世界坐标系”（World Coordinate System），并定义一套与摄像机缩放级别联动的动态比例尺系统。该坐标系需要支持星系级别的巨大数值范围，并作为未来世界生成与内容定位的统一基准。

同时，提供一个可通过 F3 快捷键调用的调试悬浮窗（Debug Overlay），用于实时显示坐标与比例尺信息。

- **坐标系定义**：使用右手坐标系，其中 XY 构成水平面（例如行星轨道平面），Z 轴为垂直于该平面的轴。
- **比例尺规则**：摄像机在“最大放大（看得最近）”的缩放级别时，屏幕上的 1 像素（1px）对应游戏世界中的 1 公里（1km）。当摄像机缩放时，比例尺随之线性变化。
- **大数值支持**：坐标系必须支持星系级别的大坐标，并保证近景渲染与拾取仍具备足够精度。

## Clarifications

### Session 2026-01-08

- Q: 世界坐标系用于“巨大数值（星系级别）”时，内部数值表示方式选哪一种？ → A: 选 B：分层坐标（WorldCoord 大尺度整型网格 + LocalOffset 局部浮点偏移）。
- Q: “完成后要接入实际渲染”的最小可验收渲染产物是什么？ → A: F3 开启时渲染世界坐标轴 + 坐标轴网格，并显示比例尺 UI（DebugOverlay）。
- Q: XY 网格间距如何跟随比例尺/zoom 变化？ → A: 自动调整，目标使相邻网格线在屏幕上保持约 100px 间距。
- Q: 坐标轴/网格以什么为中心绘制？ → A: 以世界原点 (0,0,0) 固定。
- Q: 固定在世界原点的网格绘制范围如何限定？ → A: 自适应范围：根据相机视锥/屏幕可见世界跨度绘制到可见范围 + 余量（约 1.2x）。
- Q: F3 的坐标轴/网格用哪种渲染方式实现？ → A: 世界空间调试线框渲染（DebugDraw/LineRenderer/自定义线段批次）。
- Q: WorldCoord 的网格单元大小选多少？ → A: 选 B：每格 = 1,000,000 km。
- Q: 最大缩放“1px=1km”对应的 zoom 定义是什么？ → A: 选 A：规定 zoom=1.0 为最大放大（看得最近），且此时满足 1px=1km。
- Q: 比例尺线性变化的精确定义是“与 zoom 成正比”还是“与 zoom 成反比”？ → A: 选 A：`kmPerPixel = zoom * 1km`（zoom 越大，看得越远）。
- Q: 比例尺单位自动转换的具体阈值是多少？ → A: 选 B：多级单位切换（> 10,000 AU → ly; > 1,000,000 km → AU; < 1 km → m）。

## 2. 用户场景与测试

### 场景 1: 玩家在游戏中查看坐标与比例尺信息

- **前提**: 玩家处于任何可以自由缩放视角的游戏场景中（如星图、恒星系视图）。
- **步骤**:
  1. 玩家使用鼠标滚轮或快捷键进行缩放操作。
  2. 玩家按下 F3 键。
  3. 调试悬浮窗出现。
  4. 玩家再次按下 F3 键。
  5. 调试悬浮窗消失。
- **验收标准**:
  - `AC-1.1`: 按下 F3 键可以稳定地切换调试悬浮窗的显示和隐藏。
  - `AC-1.2`: 悬浮窗必须清晰地显示当前摄像机中心点的世界坐标（X, Y, Z）。
  - `AC-1.3`: 悬浮窗必须显示当前的摄像机缩放级别（zoom level）。
  - `AC-1.4`: 悬浮窗必须显示当前的比例尺，格式为 `1px = N [unit]`（例如 `1px = 500.00 m` 或 `1px = 10.50 km`）。单位应根据数值大小自动切换（如 m, km, AU）。
- `AC-1.4.1`: 当 F3 开启时，场景中必须可见三维世界坐标轴（X/Y/Z）与 XY 平面网格；关闭 F3 后这些调试渲染元素必须消失。
- `AC-1.4.2`: XY 网格需随比例尺/zoom 自动调整间距，使相邻网格线在屏幕上约 100px 间距（允许小幅浮动以使用“漂亮数”步长）。
- `AC-1.4.3`: XY 网格绘制范围需自适应：至少覆盖相机当前可见世界范围，并额外增加约 1.2x 的绘制余量；缩放与移动过程中不应出现明显“网格边缘露馅”（屏幕内缺线）。
- `AC-1.4.4`: 坐标轴与网格必须确实通过世界空间线框/线段方式绘制到场景中（非仅 UI 画线）；开启 F3 后应能在游戏画面内直接看到线框元素随相机缩放正确呈现。
  - `AC-1.5`: 当摄像机缩放到最大放大（看得最近）级别时，比例尺应显示为 `1px = 1.00 km`。
  - `AC-1.6`: 当玩家放大（zoom in）时，比例尺 `N` 的值应平滑减小；当玩家缩小（zoom out）时，`N` 的值应平滑增大。

## 3. 功能需求

- `FR-1`: **世界坐标系服务**: 必须建立一个全局或上下文唯一的服务/管理器，用于处理世界坐标与屏幕坐标之间的转换，并作为未来世界生成的统一坐标基准。
- `FR-2`: **分层坐标表示**: 坐标必须采用分层表示：
  - `WorldCoord`：用于表示大尺度位置（星系级），采用整型网格坐标，每个网格单元的大小定义为 1,000,000 km；
  - `LocalOffset`：用于表示当前网格单元内的局部偏移，采用浮点数表示（支持高精度近景渲染）。
- `FR-3`: **比例尺计算**: 坐标服务必须能够根据当前摄像机缩放级别（zoom level）计算出正确的比例尺（单位：km/px）。
- `FR-4`: **线性缩放**: 比例尺的变化必须与摄像机的缩放级别呈线性关系，具体公式为 `km_per_pixel = zoom * 1.0`（其中 `zoom=1.0` 时为 `1km/px`）。
- `FR-5`: **最大比例尺定义**: 必须定义一个常量或配置，明确最大放大（看得最近）缩放级别下的比例尺为 `1km/px`。
- `FR-6`: **调试悬浮窗 (F3)**: 必须实现一个 UI 组件作为调试悬浮窗，可通过 F3 键全局切换其可见性。
- `FR-6.1`: **F3 调试渲染（世界空间）**: 当 F3 开启时，必须通过“世界空间调试线框渲染”（例如 DebugDraw/LineRenderer/自定义线段批次）在世界空间实际渲染以下调试元素（用于验证坐标变换与比例尺接入渲染链路，而非仅逻辑计算）：
  - 世界坐标轴（X/Y/Z 轴，颜色可约定：X=红、Y=绿、Z=蓝），以世界原点 (0,0,0) 为基准绘制
  - 坐标轴网格（位于 XY 平面，以世界原点为基准；网格间距需随比例尺/zoom 自动调整，目标使相邻网格线在屏幕上保持约 100px 间距；网格绘制范围需自适应：根据相机视锥/屏幕可见世界跨度绘制到“可见范围 + 余量”（约 1.2x），保证近景可读且远景不过密）
- `FR-7`: **信息展示**: 调试悬浮窗必须实时显示以下信息：
  - 摄像机世界坐标（分层坐标形式展示，同时提供换算后的 km 值用于阅读）
  - 摄像机缩放级别 (zoom)
  - 当前比例尺（格式化字符串）
- `FR-8`: **单位自动转换**: 比例尺显示时，必须支持多级单位的自动格式化，具体阈值如下：
  - `> 10,000 AU` 时，切换到**光年 (ly)**
  - `> 1,000,000 km` 时，切换到**天文单位 (AU)**
  - `< 1 km` 时，切换到**米 (m)**
  - 其他情况默认使用 **公里 (km)**。

## 4. 成功标准

- `SC-1`: **功能可用性**: 100% 的游戏时间内，F3 调试悬浮窗均可按预期正常开关和刷新数据。
- `SC-2`: **大坐标稳定性**: 在星系级别的巨大坐标范围内，坐标显示与换算不会出现跳变/抖动导致的明显 UI 异常；近景移动在 UI 层面保持平滑。
- `SC-3`: **数据准确性**: 在最大放大（看得最近）缩放级别，比例尺的显示值与 `1km/px` 的误差不应超过 0.1%。
- `SC-4`: **性能**: 调试悬浮窗的开启或关闭不应对游戏帧率（FPS）产生可感知的（>5%）影响。

## 5. 关键实体与数据

- **`CoordinateService`（或类似名称）**: 负责坐标转换和比例尺计算的核心服务。
- **`WorldCoord`**: 大尺度整型网格坐标（用于巨大数值范围）。
- **`LocalOffset`**: 局部浮点偏移（用于近景高精度）。
- **`DebugOverlay` (UI 组件)**: 负责显示调试信息的 UI 界面。
- **`Camera`**: 缩放级别（`zoom`）是比例尺计算的核心输入。

## 6. 假设

- `A-1`: 游戏中的世界距离基准单位为公里（km），但内部可采用分层坐标表示以兼顾范围与精度。
- `A-2`: “线性变化”指屏幕像素代表的物理距离与摄像机 `zoom` 成正比。
- `A-3`: 调试悬浮窗的 UI 风格和布局无需精细设计，仅要求信息清晰可读即可。
