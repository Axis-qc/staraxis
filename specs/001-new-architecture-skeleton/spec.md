## User Scenarios & Testing *(建议填写；不强制编写单元测试)*

### User Story 1 - 启动即进入主菜单 (Priority: P1)

作为玩家，我启动客户端后应立即进入主菜单界面，并看到 6 个入口按钮：

- 新游戏
- 加载游戏
- 多人游戏（未来规划）
- 舰船设计器
- 设置
- 退出游戏

**Why this priority**: 主菜单是所有后续流程的入口；先把 UI 层跑通，才能在此基础上逐步接入世界/模拟/存档等系统。

**Independent Test**: 运行桌面启动入口，观察是否出现游戏窗口并展示主菜单；按钮与文字是否正确。

**Acceptance Scenarios**:

1. **Given** 客户端未启动，**When** 启动客户端，**Then** 打开一个游戏窗口并展示主菜单 UI。
2. **Given** 主菜单已展示，**When** 观察主菜单，**Then** 必须能看到 6 个入口按钮且文案与顺序允许调整。

---

### User Story 2 - 主菜单按钮可点击并有明确反馈 (Priority: P2)

作为玩家，我点击主菜单按钮应获得明确反馈，避免“点了没反应”。

**Why this priority**: 本阶段不接入模拟层与业务流程，按钮反馈用于验证 UI 交互链路与输入处理已打通。

**Independent Test**: 逐个点击按钮，确认会出现明确提示或发生预期行为。

**Acceptance Scenarios**:

1. **Given** 主菜单已展示，**When** 点击“退出游戏”，**Then** 客户端退出。
2. **Given** 主菜单已展示，**When** 点击“新游戏/加载游戏/多人游戏/舰船设计器/设置”，**Then** 弹出“开发中”提示。

---

### Edge Cases

- 当字体/皮肤资源缺失时，应给出可识别错误提示，而不是静默黑屏。
- 当窗口尺寸变化时，主菜单布局应保持可用（按钮仍可点击且不重叠到不可用）。

## 游戏文件结构设计 *(仅本功能相关)*

> 本节只描述为实现“Scene2D 主菜单 UI 骨架”所需的最小文件结构与资源落盘位置。

## 游戏基础框架设计（本阶段范围）

> 本阶段的“基础框架”仅覆盖 UI 层与桌面启动链路，目标是把“窗口启动 + Scene2D 展示主菜单 + 点击反馈（开发中/退出）”跑通。
>
> 明确不包含：模拟层、世界状态、日结算、指令队列、存档系统、网络/通信等。

### 组件与职责边界

- **桌面启动壳**
  - 负责启动应用窗口与输入事件分发。

- **UI 集成层（Scene2D UI）**
  - 负责创建主菜单舞台（`stage`）与 UI 组件（按钮、弹窗）。
  - 负责处理按钮点击并触发：
    - 退出应用
    - 弹出“开发中”提示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 能启动桌面游戏窗口，并在启动完成后展示主菜单。
- **FR-002**: 系统 MUST 使用 LibGDX Scene2D 渲染主菜单 UI。
- **FR-003**: 主菜单 MUST 显示 6 个入口按钮：新游戏、加载游戏、多人游戏（未来规划）、舰船设计器、设置、退出游戏。
- **FR-004**: 点击“退出游戏” MUST 退出客户端。
- **FR-005**: 点击“新游戏/加载游戏/多人游戏/舰船设计器/设置” MUST 弹出“开发中”提示。
- **FR-006**: 本功能 MUST NOT 引入或依赖模拟层与通信层系统（例如 `WorldState`、模拟主循环、网络消息）。

### Key Entities *(include if feature involves data)*

- **主菜单按钮集合**: 主菜单页面中的 6 个入口按钮。
- **提示弹窗**: 用于显示“开发中”的 UI 组件。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 启动客户端后 3 秒内，玩家可见主菜单与 6 个入口按钮。
- **SC-002**: 6 个按钮均可点击并产生反馈，其中“退出游戏”退出客户端，其他按钮显示“开发中”提示。
- **SC-003**: 在完全离线环境下，主菜单仍可正常加载与交互。
