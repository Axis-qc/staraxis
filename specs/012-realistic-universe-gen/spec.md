# 功能规格书：无缝宇宙生成（4X 大战略）

**功能分支**: `012-realistic-universe-gen`  
**创建日期**: 2026-01-07  
**状态**: 草稿  
**输入**: 用户描述: "无缝 4X 大战略，星系由随机生成的合理恒星系组成，但需要支持预设特殊恒星系（太阳系、半人马座 α 等）进行固定生成"

## 背景与目标

根据《游戏大纲.md》中对 4X 太空战略的整体定位，以及《术语对齐.md》中对“星系 / 星区 / 恒星系”的定义，本功能旨在提供一个**无缝**的银河级地图生成方案：

1. **随机性与真实性并存**：大部分恒星系通过科学合理的概率模型随机生成；
2. **可预设特殊恒星系**：允许设计团队在特定坐标固定生成已知恒星系（如太阳系、半人马座 α、织女星系等）；
3. **统一术语**：严格使用“星系 (Galaxy) / 星区 (Sector) / 恒星系 (StarSystem)”等项目内统一术语；
4. **无加载缝隙**：玩家从宏观星系层到恒星系层再到行星层无需加载读条，保证沉浸式体验；
5. **支持未来扩展**：符合《宪章》关于模块化、扩展性与 Mod 支持的要求。

## 用户场景与测试 *(强制)*

### 用户故事 1 - 探索随机恒星系 (优先级: P1)

作为玩家，当我在星系地图上点击任意 **星区 (Sector)** 并进入其中的 **恒星系 (StarSystem)** 时，我希望看到一个基于天文统计模型随机生成、结构合理的恒星系，以便体验未知探索的乐趣。

**独立测试**：使用同一随机种子生成星系多次，进入多个随机星区，验证恒星数量、行星分布均满足物理约束且具有差异性。

**验收标准**：

1. **给定** 玩家选择随机星区，**当** 进入恒星系视图，**则** 至少存在 1 颗恒星，且恒星数量不超过 3 颗。
2. **给定** 恒星系生成完成，**当** 检查行星轨道，**则** 行星轨道顺序、距离符合开普勒定律近似分布。

---

### 用户故事 2 - 访问预设恒星系 (优先级: P1)

作为玩家，当我前往坐标 (X,Y) 对应的 "太阳系" 星区时，我希望进入的恒星系与现实太阳系结构一致（1 颗 G 型恒星 + 8 颗行星等），从而获得熟悉而可信的体验。

**独立测试**：在配置文件中启用 `solar-system` 预设，生成星系后直达指定坐标，核对恒星系数据。

**验收标准**：

1. **给定** 预设列表包含 `solar-system`，**当** 进入对应星区，**则** 恒星名称为 "Sun"，行星名称及顺序与现实一致。
2. **给定** 预设列表包含多个特殊恒星系，**当** 生成星系，**则** 所有预设恒星系均在指定坐标生成且不会与随机生成冲突。

---

### 用户故事 3 - 无缝缩放体验 (优先级: P2)

作为玩家，我希望在星系层、恒星系层与行星层之间缩放时没有加载屏幕，以保持沉浸感。

**独立测试**：在低端与高端硬件上执行连续缩放，并监测帧率与加载提示。

**验收标准**：

1. **给定** 玩家位于银河级视图，**当** 连续缩放至行星地表，**则** 过程中不出现显式加载提示或画面冻结超过 1 秒。
2. **给定** 玩家在恒星系内高速移动，**当** 进入行星轨道，**则** 相机过渡流畅且帧率保持 ≥30 FPS。

---

### 边缘场景

- 当随机生成结果在预设坐标产生冲突时，系统应优先保留预设恒星系并重新采样邻近星区。
- 若玩家关闭所有预设恒星系选项，星系应完全随机生成且不影响性能。
- 对于超远摄视角同时渲染数百星区时，系统应采用 LOD 或批处理策略防止性能骤降。

## 功能需求 *(强制)*

| 编号 | 需求描述 |
|------|----------|
| **FR-001** | 系统**必须**基于 `GalaxyScaleConfig` 在大地图生成指定半径的 **星系 (Galaxy)**，由六边形 **星区 (Sector)** 组成。 |
| **FR-002** | 系统**必须**在生成流程中先生成所有**预设恒星系 (PresetSystem)**，其坐标既可指定固定星区，也可标记为"随机星区"（随机选择一个可用星区）。 |
| **FR-003** | 系统**必须**在完成预设恒星系生成后，再按 `starDensity` 参数概率为剩余的 `galaxy` 类型星区生成随机 **恒星系 (StarSystem)**；若星区已存在预设恒星系或被标记为 `no_generate`，则跳过随机生成。 |
| **FR-003** | 系统**必须**使用科学合理的天体统计模型（恒星质量分布、行星轨道分布等）随机生成恒星系，确保物理真实性。 |
| **FR-004** | 系统**必须**支持通过配置文件 `preset-systems.json` 列出需固定生成的恒星系（名称、坐标、详细天体数据）。 |
| **FR-005** | 系统**必须**在生成过程中检测坐标冲突：若随机结果占用了预设坐标，需重新采样该星区或其邻区，直至无冲突。 |
| **FR-006** | 系统**必须**保证从星系层到行星层的相机缩放与场景切换无显式加载画面；必要时使用后台流式加载并平滑过渡。 |
| **FR-007** | 系统**必须**为 Mod 提供注入接口：允许 Mod 通过数据文件新增/替换预设恒星系而无需修改代码。 |
| **FR-008** | 系统**必须**支持种子 (Seed) 控制，确保同一种子在相同版本中生成的星系一致，便于存档与多人同步。 |
| **FR-009** | 系统**必须**遵循 `.specify/memory/constitution.md` 的模块化与分层原则：生成逻辑位于服务器核心模块，客户端仅接收同步数据并渲染。 |

## 关键实体

- **Galaxy**: `radius` (星区半径), `sectorList` (星区数组), `seed` (生成种子)
- **Sector**: `q,r` (六边形坐标), `sectorType`, `starSystem?`
- **StarSystem**: `name`, `starList`, `planetList`, `presetId?`
- **PresetSystem**: `id`, `coordinate`, `starData`, `planetData`

## 成功标准 *(强制)*

| 编号 | 指标 |
|------|------|
| **SC-001** | 使用相同种子多次生成，预设恒星系位置与结构 100% 一致，随机恒星系统计指标（恒星数、行星数）方差 <5%。 |
| **SC-002** | 在中端硬件（参考 GTX 1650 + i5 10400）上，从银河视图无缝缩放至行星表面平均帧率 ≥ 45 FPS，最低帧率 ≥ 30 FPS。 |
| **SC-003** | 进入包含 1000+ 星区的银河地图耗时 ≤ 5 秒；进入单个恒星系视图耗时 ≤ 2 秒（后台加载）。 |
| **SC-004** | 通过 Mod 注入的自定义预设恒星系在不修改源码的情况下可被加载并正确生成，成功率 100%。 |

## 假设与依赖

- **假设**：服务器端拥有足够内存进行一次性星系生成或分块懒加载。
- **依赖**：现有 `GalaxyScaleConfig`, `StarSystem` 数据结构及渲染管线需已就绪。

## 版本与兼容性

- **面向版本**：Alpha 0.4.0 及以上。
- **兼容性**：不需要兼容旧存档；后续版本如调整生成算法需提供数据迁移脚本。
