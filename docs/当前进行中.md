## 工作笔记

### 迁移策略
- **不做旧代码兼容过渡**：新版确认无依赖后直接删除旧文件，不在新旧之间做兼容层
- **单向兼容**：支持读旧版数据，但写入必须用新版本格式；禁止产生旧版本数据

### 模块职责
- **权威状态仅在 game**：所有改变游戏结果的逻辑只允许在 game 模块执行
- **纯渲染数据不塞进 game 状态**：轨道环顶点、光晕参数等 100% 视觉辅助数据由 client 自行维护
- **快照是 DTO 不是缓存**：`EntitySnapshot` 等快照类仅用于跨模块/跨进程传输，不承担 CPU 端数据缓存职责

### 代码规范
- **数据驱动优先于硬编码**：权重表、配置参数等优先用 JSON 数据文件，避免代码里写死
- **布局不同则不强行抽象**：数据布局不同（如 6 float vs 7 float）的重复代码收益有限，标记 TODO 即可
- **现取现算优先**：不提前算好存快照，除非有明确的性能瓶颈证据。调 `public` 方法共享算法比塞数据进状态更干净
