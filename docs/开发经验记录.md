## 一、架构设计原则

### 1.1 模块职责硬边界

- **权威状态仅在 game**：所有改变游戏结果的逻辑只允许在 game 模块执行。client/webnet 只读快照，不碰 `WorldState`。
- **外部只能读两份快照**：`RealTimeWorldState`（每 tick 更新，动态实体 + 时间）+ `DailySettlementState`（每 20 tick 更新，恒星基线 + 国家资产 + 玩家映射 + 可见性 + 情报等级）。
- **`EntitySnapshot` 是双缓冲共享数据单元**：桌面模式下渲染器直接读双缓冲，不是单纯传输 DTO。一份数据同时服务桌面渲染和网络传输。
- **webnet 是同进程协议转换器**：与 game 同 JVM，出站读双缓冲转 DTO 发 WebSocket，入站收包后调 `CommandBus.submit(cmd)`。不跨进程、不 RPC、不碰 WorldState。

### 1.2 数据流规范

- **纯渲染数据不塞进 game 状态**：轨道环顶点、光晕参数等 100% 视觉辅助数据由 client 自行维护。game 不关心"这个环有几条边"。
- **现取现算优先**：不提前算好存快照，除非有明确的性能瓶颈证据。调 `public` 方法共享算法比塞数据进状态更干净。
- **不做旧代码兼容过渡**：新版确认无依赖后直接删除旧文件，不在新旧之间做兼容层。
- **单向兼容**：支持读旧版数据，但写入必须用新版本格式；禁止产生旧版本数据。
- **数据驱动优先于硬编码**：权重表、配置参数等优先用 JSON 数据文件，避免代码写死。

### 1.3 分层解耦

- **纹理注册器与业务系统分离**：`SpriteRegistry` 是底层基础设施，只做 key→纹理映射，不感知舰船/恒星/行星等业务语义。业务系统通过 key 引用纹理，不接触文件路径。
- **布局不同则不强行抽象**：数据布局不同（如 6 float vs 7 float）的重复代码收益有限，标记 TODO 即可，不要强行提取公共基类。

## 二、Scene2D + 矢量 UI 踩坑录

### 2.1 InputListener 只写 touchDown/touchUp 不写 keyDown/keyTyped → 键盘事件静默丢弃

- **情景**：`VectorTextField` 自定义了 `handleKeyDown`/`handleKeyTyped`，但只在 `InputListener` 重写了 `touchDown`/`touchUp`。
- **根因**：Scene2D 的 `Stage` 分发键盘事件时调用的是 `InputListener.keyDown(InputEvent, int)` / `keyTyped(InputEvent, char)`，未重写则事件被静默丢弃。`handleXxx` 自定义方法不会被自动调用。
- **修复**：在 `InputListener` 中显式重写三个方法并转发：
  ```java
  addListener(new InputListener() {
      public boolean keyDown(InputEvent e, int kc) { return handleKeyDown(kc); }
      public boolean keyUp(InputEvent e, int kc) { return focused; }
      public boolean keyTyped(InputEvent e, char c) { return handleKeyTyped(c); }
  });
  ```
- **教训**：Scene2D 的自定义 Actor 如果要用键盘输入，**必须重写 InputListener 的三个键盘方法**，自定义 `handleXxx` 只是内部函数，Stage 不知晓。

### 2.2 ShapeRenderer 的 alpha 在 batch.end() 后被忽略 → 透明线变成全不透明

- **情景**：用 `ShapeRenderer.ShapeType.Line` 画半透明边框，`sr.setColor(r,g,b,alpha)` 设置了 alpha 值，但绘制出来始终全不透明。
- **根因**：`SpriteBatch` 在 `batch.end()` 后关闭了 `GL_BLEND`。`ShapeRenderer` 默认不重新开启混合，导致 alpha 被 OpenGL 忽略，颜色以全不透明输出。
- **修复**：在 ShapeRenderer 绘制前显式启用混合：
  ```java
  batch.end();
  Gdx.gl.glEnable(GL20.GL_BLEND);
  Gdx.gl.glBlendFunc(GL20.GL_SRC_ALPHA, GL20.GL_ONE_MINUS_SRC_ALPHA);
  // ... ShapeRenderer 绘制 ...
  batch.begin();
  ```
- **教训**：`batch.end()` → ShapeRenderer → `batch.begin()` 模式下，ShapeRenderer 的透明绘制**必须手动开启 GL_BLEND**。SprtieBatch 内部会关闭它。

### 2.3 VectorScrollPane 内容高度为 0 → 滚动无效

- **情景**：`VectorScrollPane` 包裹一个 Table（container），Table 没有显式设 height（初始 0），滚轮滚动后立即回弹。
- **根因**：`updateLayout()` 原代码 `content.setSize(max(content.getWidth(), w), content.getHeight())` 把高度设为 `content.getHeight() = Table.getHeight() = 0`，`validate()` 不改 Table 的 size。`getContentHeight()` 返回 `max(0, viewH) = viewH`，`clampScrollOffset()` 中 `contentH > viewH` 不成立 → scrollYOffset 被 clamp 回 0。
- **修复**：对 `Layout` 接口的控件，取 `getPrefWidth()`/`getPrefHeight()` 作为真实内容尺寸，因为 Table 的 prefHeight 在 validate 后反映子元素累加高度。
- **教训**：Table/Group 的 `getHeight()` 可能为 0（未 pack / 未设 size）。滚动面板的内容尺寸必须取 Layout 的 pref 值，不能依赖当前 size。

### 2.4 UI 平移动画 + 裁剪相互干扰

- **情景**：`VectorScrollPane` 用 `localToStageCoordinates` 计算裁剪区域，但 UI 容器应用了平移动画（`shiftX`）导致坐标偏移，裁剪区域错位。
- **教训**：Scene2D 裁剪以舞台坐标为准，涉及动画位移的控件必须确认裁剪计算走 `localToStageCoordinates` 而非直接 `getX()`/`getY()`。
- **注意**：`ShapeRenderer` 的 `setTransformMatrix` 不影响 `HdpiUtils.glScissor`，裁剪区域始终用舞台坐标。

### 2.5 圆形渐变/发光多层叠加的性能与视觉注意

- **教训**：多同心圆/方框叠加实现渐变虽然是 libGDX 中的常用技巧，但层数过多（>6）时每帧绘制调用量激增。2-4 层的视觉效果与 8 层几乎没有肉眼可察差异，但性能差很多。

### 2.6 Label 设置 setTouchable 后依然可穿透

- **情景**：`VectorLabel` 设了 `setTouchable(Touchable.enabled)` 但没有注册任何 InputListener。点击 label 区域时事件穿透到底层。
- **根因**：Scene2D 的 `Actor.hit()` 检查 `isTouchable()` 和 `isVisible()`，但 label 没有 InputListener 消费事件，事件会继续冒泡。如果 label 下有其他 Actor 也会被命中。
- **教训**：如果只是想阻挡事件穿透，需要在 label 上加一个空的 InputListener（`addListener(new InputListener(){})`），或者重写 `hit()` 返回 this。仅设 `Touchable.enabled` 不足以保证遮挡。

## 三、命令系统与鉴权模式

### 3.1 鉴权与执行分离原则

- **错误写法**：`if (!nationId.equals(ship.ownerNationId)) return;` — 正向校验"必须匹配"
- **问题**：
  1. `ship.ownerNationId` 为 null 时抛 NPE
  2. `nationId` 为 null 时抛 NPE
  3. 无主实体被静默拒绝
  4. 无日志输出，调试困难
- **正确写法**：`if (ship.ownerNationId != null && !ship.ownerNationId.equals(nationId)) return;`
  - 短路保护避免 NPE
  - 无主实体（`ownerNationId == null`）默认开放操作权限
  - 鉴权是"有 owner 且不匹配才拒绝"的负向校验
- **教训**：静默丢弃是反模式。鉴权失败应明确拒绝或日志记录，禁止 `return;` 不打招呼。

### 3.2 客户端守卫是可选层不是必须层

- **情景**：`ShipMoveController` 的守卫 `if (shipSnap != null && shipSnap.ownerNationId != null)` 因 `ownerNationId` 为 null 阻挡了命令提交。
- **教训**：客户端守卫服务于"提前拦截不合理操作，提升响应速度"而非"作为安全的唯一保障"。game 层的 Handler 才是真正的安全边界。客户端不应因其守卫逻辑而阻碍合法（或边界合法）操作的提交。守卫应偏向放行，game Handler 偏向拦截。

### 3.3 handler 接收到的参数可能为 null

- **教训**：Command 的 DTO 中所有关联 ID 字段（`nationId`、`shipId`、`targetId` 等）都可能为 null，Handler 处理时必须做 null 安全校验。不要假设调用端传了完整数据。

## 四、硬编码清理模式

### 4.1 阶段性常量提取优于一次性大改

- **策略**：每个文件内部提取常量到头部的 `private static final`，不跨模块批量改。每次只清理一个模块，清理完编译验证，不改逻辑不改行为。

### 4.2 `GenPhase` 枚举模式

- **场景**：加载进度条等"阶段-比例-标签"三元组数据。
- **模式**：定义枚举，每个枚举值绑定 `float progress` + `String label`，一处修改全局同步。比散落 `0.05f`/`"生成星系..."` 字符串干净。

### 4.3 已存在常量优先复用

- **常犯**：`% 20` 这种隐含"每秒 20 tick"的魔法数 → 应复用 `SimulationClock.TICKS_PER_SECOND`。
- **常犯**：`/ 1_000_000L` 裸除法 → 用 `TimeUnit.NANOSECONDS.toMillis()`。

### 4.4 硬编码扫描方法

- 用 `grep_search` 搜 `[0-9]+\.[0-9]+[fF]`（浮点魔法数字）、`"[a-z_]+"` 散落字符串、`if.*==.*[0-9]` 数字比较
- 不搜单元测试（`test/`）、构建脚本（`.gradle`）、配置文件（`.json`/`.yaml`）
- 跨模块重复（如 `TemperatureColor` vs `SpectralType` 色温表）标记为候选合并但不急于推进

## 五、双快照模式要点

### 5.1 双缓冲更新时机

- `RealTimeWorldState`：每 tick 更新一次（20 ticks/s），内容为动态实体（舰船位置）+ 时间元信息
- `DailySettlementState`：每 20 ticks 更新一次（1 tick = 1 game day），内容为恒星基线 + 国家资产 + 玩家映射 + 可见性 + 情报等级
- 外部模块以**轮询**方式读取，game 不主动推送

### 5.2 快照是共享数据单元不是 DTO

- 桌面模式下 client 渲染器直接读取双缓冲中的 `EntitySnapshot` 做渲染
- 同一份数据同时服务桌面渲染和网络传输
- 快照写入端（game）与读取端（client/renderer）在同一进程内

## 六、Java / Gradle 实战

### 6.1 Gradle 编译验证

- 单模块编译：`./gradlew :模块名:compileJava`（如 `:ui:compileJava`）
- 多模块编译：`./gradlew :模块名:compileJava :模块名2:compileJava`
- PowerShell 中退出码检查：`... 2>&1; "EXIT=$LASTEXITCODE"` — `EXIT=0` 成功
- Gradle 输出通过 `Select-String` 过滤会有编码问题，建议用 `--console=plain -q` 配合 `"EXIT=$LASTEXITCODE"`

### 6.2 Java 空安全

- `String.equals(null)` 返回 false，不会抛 NPE；但如果是 `null.equals(xxx)` 则 NPE
- 安全的 equals 写法：`Objects.equals(a, b)`，或者 `a != null && a.equals(b)`
- 鉴权/匹配逻辑优先用 `ownerNationId != null && !ownerNationId.equals(nationId)` 短路模式
- Command 的 ID 字段全是对象类型（`Long`/`String`），可能为 null，Handler 必须防御

### 6.3 Scene2D 坐标体系要点

- `Actor.getX()/getY()` 是父容器相对坐标
- `localToStageCoordinates(Vector2)` 转换到舞台绝对坐标
- `HdpiUtils.glScissor` 需要用舞台坐标
- `ShapeRenderer.setTransformMatrix` 不影响裁剪区域
- `ShapeRenderer` 的 `begin()` 默认重置 `transformMatrix`（与 `SpriteBatch` 不同行为）

## 七、调试与问题排查

### 7.1 界面问题排查链路

1. 先看 JSON 配置是否正确（`assets/ui/gameui/`）
2. 再用 `F3` 调试面板查看 Actor 边界、坐标、鼠标位置
3. 打开 DevConsole（~键）输入 `uitest` 跳转到测试场景
4. 确认事件链路：输入设备 → `Gdx.input.setInputProcessor`（InputMultiplexer）→ Stage → hit() → InputListener
5. ESC 键用 `Gdx.input.isKeyJustPressed` 轮询，不依赖 InputProcessor，不受焦点影响

### 7.2 快照数据调试

- 快照数据写入后 client 端读取不到时，检查：
  1. `publishRealtimeSnapshotIfNeeded()` 是否被调用
  2. `RealTimeWorldState.isReady()` 返回 true 才可读
  3. 双缓冲交换时机：写端写入 swap，读端读 snapshot 指针
  4. 动态实体快照（`RealtimeEntitySnapshot`）使用 `ISnapshotProvider<...>` 接口获取

### 7.3 中文输入法与按键冲突

- **现象**：WASD 移动画面间歇性回抽
- **根因**：中文输入法拦截/延迟按键事件，`isKeyPressed()` 返回值不稳定
- **验证**：切换英文输入法后消失
- **待修复**：窗口创建时强制禁用 IME（`Gdx.input.setOnscreenKeyboardVisible` / native 层 IME 禁用）
