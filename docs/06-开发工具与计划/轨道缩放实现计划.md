## 一、问题

`AstroGenerator.generatePlanetsForSystem()` 中以 `starRadius * 6` 作为第一轨道基准：

```java
double currentOrbitGU = primaryStar.radiusGU * FIRST_ORBIT_MULTIPLIER; // * 6
```

实际轨道量级：

| 恒星类型 | 半径(GU) | 第1轨道 | 第7颗(~x1.6^6) | System View 边界 |
|---------|---------|--------|----------------|-----------------|
| M红矮星 | 2,000 | 12,000 | ~201,000 | 远平面 3M ✓ |
| G黄矮星 | 7,000 | 42,000 | ~705,000 | target ±1M ✓ |
| RED_GIANT | 35,000 | **210,000** | **~3.5M** | **超远平面 3M ✗** |
| BLUE_GIANT | 35,000 | **210,000** | **~3.5M** | **超远平面 3M ✗** |

**根因**：用恒星物理半径(radiusGU)做轨道基数。巨星半径是普通星的 5-17 倍，轨道等比放大必然越界。真实宇宙中恒星膨胀到巨星时，行星系统尺度并不会等比膨胀（太阳变红巨星后地球轨道仍为 1 AU），所以 `starRadius * 6` 本身就不物理。

---

## 二、方案：systemRadiusGU 替代 starRadius 作为轨道基准

### 核心思路

为每类恒星定义 `systemRadiusGURange`（恒星系半径），代表该恒星**行星系统可延伸的范围**。轨道生成改用此值而非恒星物理半径，这与真实宇宙更一致——行星系统尺度由恒星形成时的原行星盘大小决定，而非恒星当前的物理半径。

### 设计细节

#### 2.1 轨道基准规则

```
第一轨道 = systemRadiusGU × random(0.03, 0.08)    // 3%~8%
→ 每颗行星累进 × random(1.4, 2.0)                 // 间距倍数不变
→ 上限: 不超过 systemRadiusGU × 0.9               // 90% 截断
→ 下限: max(currentOrbit, starRadius × 2.0)       // 防止行星落入恒星
```

> **审查后调整**（相对原草案 v1）：
> - 上限 `0.85` → **`0.9`**：重力井计算已独立于最远行星，轨道本身可更接近 systemRadius 边界
> - 下限 `starRadius × 2.5` → **`starRadius × 2.0`**：玩家希望行星数量更多，放宽后每颗多释放约 30% 空间

#### 2.2 各类型 systemRadiusGURange

重力井公式 `gravityWellRadiusGU = systemRadiusGU × 1.5`，玩家明确最大重力井直径 900k GU（半径 450k GU），因此 `systemRadiusGU` 上限统一 ≤ **300,000**。

| 类型 | systemRadiusGURange | 第一轨道(~) | 上限(×0.9) | 预期行星数 |
|------|-------------------|------------|-----------|----------|
| M_MAIN_SEQUENCE | 60,000 ~ 120,000 | 1.8k~9.6k | 54k~108k | 5~8 |
| K_MAIN_SEQUENCE | 100,000 ~ 200,000 | 3k~16k | 90k~180k | 5~7 |
| G_MAIN_SEQUENCE | 150,000 ~ 280,000 | 4.5k~22.4k | 135k~252k | 5~7 |
| A_MAIN_SEQUENCE | 200,000 ~ 300,000 | 6k~24k | 180k~270k | 4~6 |
| B_MAIN_SEQUENCE | 250,000 ~ 300,000 | 7.5k~24k | 225k~270k | 4~6 |
| RED_GIANT | 250,000 ~ 300,000 | 同 B(下限60k~80k主导) | 225k~270k | 4~6 |
| BLUE_GIANT | 280,000 ~ 300,000 | 同 B(下限60k~80k主导) | 252k~270k | 4~6 |

关键设计点：
- **没有旧存档**限制，所有类型可自由调整
- 巨星/蓝白星 systemRadius ≤ 300k，重力井 ≤ 450k（玩家指定的 900k 直径上限）
- M型至G型范围按恒星质量比例自然缩放，紧凑且行星密集
- 第一轨道公式(3~8%) 对 `B/RED_GIANT/BLUE_GIANT` 被下限 `starRadius×2.0` 覆盖，`firstOrbitFraction` 对此类恒星不生效（由下限主导）

## 三、改动清单

### 文件 1：`assets/star/star-types.json` — 7 个恒星类型追加 systemRadiusGURange

每个类型新增：
```json
"systemRadiusGURange": [下限, 上限]
```

详见 【二.2】 节数值表。关键设计要点：
- RED_GIANT 的 systemRadius(250k~300k) 远小于其物理半径扩张量级，因为恒星膨胀时行星系统尺度不会等比放大
- 所有类型上限 ≤ 300k，确保重力井 ≤ 450k（玩家指定 900k 直径上限）
- `firstOrbitFraction(0.03~0.08)` 参数在 `B/RED_GIANT/BLUE_GIANT` 类型中被下限 `starRadius×2.0` 覆盖（由半径大的恒星自然决定）

### 文件 2：`game/.../astro/def/StarTypeDef.java` — 新增字段

新增：
```java
/** 恒星系半径范围（GU），用于轨道生成的基准。 */
public List<Double> systemRadiusGURange;
```

### 文件 3：`game/.../astro/AstroGenerator.java` — 核心逻辑重写

**3.1** `generateSystemAtPosition()` 中生成时抽取 `systemRadiusGU`，传给行星生成和重力井计算：

```java
// generateStar() 返回后：
StarTypeDef type = assets.getStarType(primaryStar.starTypeId);
double systemRadiusGU = randomDouble(type.systemRadiusGURange.get(0), type.systemRadiusGURange.get(1));
generatePlanetsForSystem(system, primaryStar, systemRadiusGU);
// 重力井基于 systemRadius（势井范围与系统整体挂钩，而非最远行星）
system.gravityWellRadiusGU = systemRadiusGU * 1.5;
```

> 注意：`systemRadiusGU` 是生成时的局部变量，不持久化到实体中。系统范围由 `StarSystem.gravityWellRadiusGU` 体现。

**3.2** `generatePlanetsForSystem()` 签名和实现改为：

```java
// 旧：private void generatePlanetsForSystem(StarSystem system, StarBody primaryStar)
// 新：
private void generatePlanetsForSystem(StarSystem system, StarBody primaryStar, double systemRadiusGU) {
    ...
    // 旧：double currentOrbitGU = primaryStar.radiusGU * FIRST_ORBIT_MULTIPLIER;
    // 新：
    double firstOrbitFraction = randomDouble(0.03, 0.08);
    double currentOrbitGU = systemRadiusGU * firstOrbitFraction;
    double maxAllowedGU = systemRadiusGU * 0.9;
    double minOrbitGU = primaryStar.radiusGU * 2.0;

    for (int i = 0; i < planetCount && currentOrbitGU <= maxAllowedGU; i++) {
        // 应用下限保护（防止行星落入恒星）
        if (currentOrbitGU < minOrbitGU) currentOrbitGU = minOrbitGU;
        ...
        // 原有轨道字段赋值、周期计算不变
        ...
        currentOrbitGU *= separationFactor;
    }
}
```

**3.3** `generateSystemAtPosition()` 中移除旧的基于最远行星的重力井计算（改为 3.1 的 `systemRadiusGU * 1.5`）。

**3.4** 移除不再使用的 `FIRST_ORBIT_MULTIPLIER` 常量。

### 文件 4（可选）：`assets/planet/orbit-presets.json`

`firstOrbitGURange` 当前未被代码使用（代码硬覆盖为 starRadius*6），可添加注释标记为"保留取值区间参考"，不动 JSON 结构。

## 七、验证标准

- [ ] 所有恒星类型的重力井半径 ≤ 450k GU（满足玩家指定 900k 直径上限）
- [ ] 红巨星/蓝巨星外圈行星不再超出 System View 可见范围（最大 < 270k GU）
- [ ] M 型红矮星系紧凑（最外轨道 < 108k GU）

- [ ] 《3 颗以下》的极端 RNG 概率 < 5%（仅在最坏组合 + 连续 ×1.7+ 时出现）
- [ ] 编译无错误
