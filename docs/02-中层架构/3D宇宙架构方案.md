# 3D 宇宙架构方案

> **版本**：1.0（草案）
> **日期**：2026-06-27
> **状态**：方案设计阶段，待用户确认

---

## 0. 核心结论（TL;DR）

将 StarAxis 世界从 **hex 二维网格** 升级为 **真实 3D 宇宙空间**。采用**Galaxy/System 双视图**：拉远自动切换星系全景，拉近自动加载恒星系细节。全部实体坐标落在 **10万 x 10万 x 10万 GU 正方体内**，无极端坐标，无需 CRR。

| 维度 | 旧（hex 2D） | 新（3D 宇宙） |
|------|-------------|--------------|
| 坐标系 | hex axial (q,r) + local GU | 3D Cartesian (x,y,z) GU，10万³ 盒子 |
| 空间分区 | 六边形星区 | 八叉树 (Octree) |
| 视图模型 | 单一视图 | **Galaxy/System 双视图（手动切换）** |
| 世界生成 | 六边形网格 + 星区类型 | 螺旋臂星系 + 恒星系 |
| 天体运动 | 无（静态） | 开普勒轨道力学 |
| 渲染 | 2D ShapeRenderer 圆/三角 | 3D PerspectiveCamera + 程序化 Mesh |
| 缩放 | 无缩放需求 | Q/E 缩放（场景内），点击/ESC 切视图 |
| 实体图标 | 填色圆/三角 | 几何体（八面体/球体/锥体） |

## 1. 坐标系

### 1.1 权威坐标

- **单位**：GU（Game Unit），游戏自定义长度单位，**不绑定真实物理比例**
- **轴向**：右手坐标系，X 轴向右，Y 轴向上（星系盘面法线），Z 轴向前
- **原点**：星系中心 (0, 0, 0)
- **数据类型**：`double`（float64）

> **设计决策**：真实太空极其空旷（行星间距是行星直径的数亿倍），1:1 还原将导致任何视图中只见虚空。GU 采用**游戏化压缩比例**，保证任意缩放层级都有充实画面。

#### 1.1.1 GU 基准定义

**GU 是 `game` 模块世界坐标系的原子长度单位，纯数值，不绑定任何视觉或物理概念。**

```
GU 的定义：
  世界坐标系中两个实体距离为 1 时，差值为 1 GU。
  GU 本身没有"等于多少米/像素/机身长度"，它只是坐标轴上的刻度。
```

**实体尺寸分配**（game 模块以 GU 为刻度给每个实体类型赋值）：

```
舰船（小型）   半径 1 GU
舰船（大型）   半径 5 GU
岩石行星       半径 5 ~ 15 GU
气态巨星       半径 40 ~ 80 GU
恒星           半径 50 ~ 400 GU
行星轨道       半径 500 ~ 20,000 GU
恒星间距       ~2,000,000 GU
星系半径       ~500,000,000 GU
```

> **渲染层职责**：`client` 模块拿到 `EntitySnapshot.radiusGU` 后，自行决定将其映射为多大的屏幕球体。例如行星 `radiusGU=10`，渲染时可以画一个半径 10 个视觉单位的球——视觉单位完全由渲染层定义，game 模块不关心。

> 轨道间距和星际间距在此基础上**等比或非等比压缩**，见 1.3 节。

#### 1.1.2 速度参考

所有运动计算基于 GU / 游戏秒（game second），由 `SimulationTime` 统一驱动：

| 对象 | 典型速度 | 说明 |
|------|---------|------|
| 行星公转 | — | 由轨道周期 T 决定，不直接设速度 |
| 快速舰船 | ~20 GU/s | 穿越自身长度（~1 GU）仅 0.05s，穿越行星（~10 GU）约 0.5s |
| 慢速舰船 | ~3 GU/s | 穿越行星约 3s |
| 商用舰船 | ~8 GU/s | 折中 |
| 星际航行 | — | 恒星间距 ~2×10^6 GU，需超光速（FTL）机制 |

> 注意：1 GU/s 已经能让舰船每秒穿越自身长度。行星尺度（~10 GU）下移动感良好。但恒星系尺度（~2×10^4 GU）需要 ~5.5 小时穿越——星际必须依赖 FTL 跳跃/航道。

### 1.2 位置结构

```java
// 替代 GlobalPosition + SectorCoord
public class SpacePosition {
    public double x;  // GU，星系绝对 X
    public double y;  // GU，星系绝对 Y（垂直盘面）
    public double z;  // GU，星系绝对 Z
    public long parentSystemId; // 归属恒星系 ID（0 = 深空）
}
```

### 1.3 距离压缩原理

真实太空的密度极端稀疏。以太阳系为例：

```
地球半径：       6,371 km
地月距离：     384,400 km     ≈ 60 × 地球半径
日地距离： 149,600,000 km     ≈ 23,500 × 地球半径
```

如果 1:1 还原，在能看到整个地球的视图中，月球在 60 个地球半径外——**屏幕外**。太阳在 23,500 个半径外——完全不可见。

**压缩策略**：

| 层级 | 策略 | 说明 |
|------|------|------|
| 天体尺寸 | **保留直观比例** | 行星 5~80，恒星 50~500，气态巨星 > 岩石行星 |
| 恒星系内轨道 | **等比缩放** | 木星轨道 ≈ 5× 地球轨道，保持相对比例正确，整体压缩 |
| 恒星间距 | **直接拉近** | 星际虚空无所谓，恒星挤到一起让星图充实 |

```mermaid
graph TD
    subgraph 真实
        A1["地 '●'"] -->|"1 AU"| A2["火 '●'"] -->|"3.5 AU"| A3["木 '●'"]
    end
    subgraph 游戏（轨道等比压缩）
        B1["地 '●'"] -->|"1,000 GU"| B2["火 '●'"] -->|"3,500 GU"| B3["木 '●'"]
    end
    subgraph 游戏（星际直接拉近）
        C1["太阳系"] -->|"真实 4 光年<br/>游戏 200 万 GU"| C2["比邻星"]
    end
```

> 一句话：**轨道比例对就行，星际之间全是虚空直接拉近**。

### 1.4 尺度参考

> 整个游戏空间 = **100,000 × 100,000 × 100,000 GU 正方体**，原点在中心。所有实体坐标落在此范围内，数值可控，float 精度充裕。

| 对象 | GU 值 | 说明 |
|------|------|------|
| 空间边界 | ±50,000 | 10万³ 正方体 |
| 星系半径 | ~50,000 | 填满半个盒子 |
| 恒星间距（平均） | ~2,000 ~ 5,000 | 可容纳数万颗恒星 |
| 恒星系半径 | ~10,000 | 最外行星轨道 |
| 行星轨道 | 200 ~ 10,000 | 内行星数百，外行星数千 |
| 恒星半径 | 20 ~ 200 | 按光谱类型 |
| 行星半径 | 3 ~ 40 | 岩石行星小，气态巨星大 |
| 舰船半径 | 1 ~ 3 | 小型 1，大型 3 |

### 1.5 Galaxy/System 两个独立场景

不做同一空间的缩放切换，改为**两个完全独立的渲染场景**（类似 Stellaris 模式）：

- **Galaxy View（星系视图）**：以 (0,0,0) 为中心渲染整个星系，所有恒星分布在 ±50,000 范围内
- **System View（恒星系统视图）**：同样以 (0,0,0) 为中心渲染当前选中的单一恒星系

两个场景**共用 100,000³ GU 坐标系**，但**位置完全独立**。星系中恒星在 (24652, 0, -2181)，进入该系统后星球的轨道中心是 (0, 0, 0)，而非 (24652, 0, -2181)。

#### 切换方式

| 操作 | 触发 |
|------|------|
| 星系 → 系统 | Galaxy View 中点击/选择一颗恒星 |
| 系统 → 星系 | System View 中按 ESC 或点击返回按钮 |

> 注意：切换不是基于相机距离的自动缩放。星系视图的相机永远在宏观距离，系统视图的相机永远在本地距离。

#### 为什么可行

两个场景分别使用了 100,000³ 坐标系的不同区域，无需做坐标变换：

```
Galaxy View（星系视图）：
  渲染范围：全空间 ±50,000 GU
  渲染内容：所有恒星（光点/小方块）、螺旋臂结构、星云背景
  相机位置：距原点几万 GU，俯瞰整个星系

System View（恒星系统视图）：
  渲染范围：全范围 ±50,000 GU（利用 LOD 控制性能）
  渲染内容：本系统天体（恒星球体+辉光、行星球体、
            轨道环、舰船图标、空间站）+ 远处恒星光点
  相机位置：距原点几千 GU，围绕系统中心观察

System View 中的 LOD 策略：
  - 0 ~ 10,000 GU：全精度渲染（球体+轨道+辉光）
  - 10,000 ~ 30,000 GU：降级为低面数球体 + 取消辉光
  - 30,000 ~ 50,000 GU：降级为像素点（同 Galaxy View）
  - > 50,000 GU：不渲染（超出坐标系边界）
```

两个场景在渲染层完全解耦，切换时重置相机参数和目标即可。

### 1.6 浮点精度

```
10万³ 盒子内，最远坐标 ±50,000 GU：
  double → 最小可分辨 ~5e-11 GU，模拟层完全充裕
  float  → 最小可分辨 ~0.005 GU → 舰船（1 GU）位置精确无抖动

无需 CRR，无需对数深度缓冲，标准 OpenGL 渲染管线即可喵。
```

## 2. 轨道力学

### 2.1 设计原则

- **二体近似**：行星只绕其主恒星运动，不计算行星间引力
- **确定性**：给定时间 `t` + 轨道根数 → 唯一位置，无累积误差
- **离散更新**：不每 tick 计算，而是查询时按模拟时间直接计算
- **静态天体**：恒星不运动（星系尺度下恒星固有运动可忽略）

### 2.2 轨道根数

```java
public class OrbitalElements {
    public double semiMajorAxis;     // a，半长轴（GU）
    public double eccentricity;      // e，偏心率 [0, 1)
    public double inclination;       // i，轨道倾角（弧度，相对星系盘面）
    public double longitudeOfAscendingNode; // Ω，升交点经度（弧度）
    public double argumentOfPeriapsis;      // ω，近心点幅角（弧度）
    public double meanAnomalyAtEpoch;       // M0，历元平近点角（弧度）
    public double epoch;             // t0，历元时间（游戏秒）
    public double period;            // T，轨道周期（游戏秒）
}
```

> **轨道周期 `T` 是游戏设计值**，不由开普勒第三定律推导（因为轨道距离已被压缩，真实引力常数不适用）。生成时根据轨道位置赋予合理周期：

| 轨道位置 | 典型半长轴 | 典型周期 | 视觉效果 |
|---------|-----------|---------|---------|
| 内行星（热区） | ~500 GU | ~300 s（5 分钟） | 肉眼可见移动 |
| 宜居带 | ~1000 GU | ~600 s（10 分钟） | 缓慢但可察觉 |
| 外行星（冷区） | ~5000 GU | ~3000 s（50 分钟） | 几乎静止，但缩放可见 |
| 远端行星 | ~20000 GU | ~12000 s（3.3 小时） | 需要时间加速才见移动 |

> 所有周期由世界生成时确定，同一 seed 必定产生相同周期，保证确定性。

### 2.3 位置计算

```
给定当前模拟时间 t：
  1. 计算平近点角 M = M0 + 2π × (t - t0) / T
  2. 求解开普勒方程 M = E - e·sin(E) → 偏近点角 E（牛顿迭代，通常 3-5 次收敛）
  3. 计算真近点角 ν = 2·atan2(√(1+e)·sin(E/2), √(1-e)·cos(E/2))
  4. 计算轨道平面位置：
       r = a·(1 - e·cos(E))  // 径向距离
       x_local = r·cos(ν)
       y_local = r·sin(ν)
       z_local = 0
  5. 通过 3-1-3 欧拉旋转 (Ω, i, ω) 变换到星系坐标系
```

### 1.6 星系坐标 vs 系统坐标

星系视图中的一个恒星系（如 `sys_1024`）在星系图中位置是 (24652, 0, -2181)，但进入 System View 后所有行星轨道以**本场景原点 (0,0,0)** 为参考。

这意味着：

```
game 模块中恒星系数据结构的坐标字段含义明确：
  - galaxyX, galaxyY, galaxyZ：星系图中的绝对位置
  - 行星轨道根数：半长轴 a 以系统中心 (0,0,0) 为基准，与星系坐标无关

System View 渲染时：
  - 恒星在 (0,0,0)
  - 行星在各自轨道位置（如轨道半径 1500 GU → 绕 (0,0,0) 公转）
  - 无需将星系坐标偏移带到系统场景中
```

两个场景唯一共享的信息是：
1. 同一个坐标系（100,000³ GU）
2. 玩家当前选中的 `systemId`
3. 当前场景的模拟时间 `t`

### 2.4 性能策略

- 预计算轨道周期表：每个行星的轨道周期在生成时确定，不变
- 缓存热路径：当前时间的 E/ν 值，仅时间推进后失效
- 远距离降级：不在 System View 的行星不计算位置，使用上次缓存值
- 舰船/人造天体不使用轨道力学（由 AI/玩家指令控制移动）

## 3. 空间分区（Octree）

### 3.1 结构

```
GalaxyOctree
├── 根节点：包裹整个星系（边长 ~10^9 GU）
├── 最大深度：12 层
├── 叶节点：边长 ~2.4×10^5 GU（可容纳数十个恒星系）
└── 每节点存储：
    ├── 子节点引用（8 个或 null）
    ├── 实体 ID 列表（仅在叶节点）
    └── 包围盒 AABB
```

### 3.2 操作

| 操作 | 说明 |
|------|------|
| `insert(entity)` | 根据 SpacePosition 插入到对应叶节点 |
| `remove(entityId)` | 从叶节点移除 |
| `move(entityId, newPos)` | 实体移动时更新（舰船等动态实体） |
| `queryFrustum(camera)` | 视锥体剔除，返回可见实体 ID 列表 |
| `querySphere(center, radius)` | 球形范围查询（传感器/武器射程） |
| `queryKNN(center, k)` | K 最近邻查询 |

### 3.3 与旧 WorldSector 的对比

| 旧 WorldSector | 新 Octree |
|---------------|-----------|
| 固定 hex 分区 | 自适应空间细分 |
| 2D 平面 | 3D 体积 |
| 6 邻接 | 26 邻接（3D 网格） |
| 星区类型承载内容 | 叶节点纯索引，内容由实体系统管理 |

## 4. 世界生成

### 4.1 生成阶段

```
Phase 1：星系骨架生成
├── 输入：worldSeed, galaxyType（螺旋/椭圆/不规则）, starCount
├── 行为：生成螺旋臂参数、恒星位置分布
└── 输出：List<StarPosition>（每个恒星的 3D 坐标 + 光谱类型）

Phase 2：恒星系生成（延迟）
├── 输入：StarPosition, systemSeed
├── 行为：生成行星数量、轨道根数、行星类型
└── 输出：StarSystem（含 OrbitalElements[] + PlanetData[]）

Phase 3：行星内容生成（延迟）
├── 输入：PlanetData, planetSeed
├── 行为：生成地形、资源、初始殖民条件等
└── 输出：Planet
```

### 4.2 螺旋臂星系

使用对数螺旋公式生成恒星分布：

```
θ(r) = θ₀ + (1/tan(pitch))·ln(r/r₀)

其中：
  r     = 距星系中心距离
  θ     = 方位角
  pitch = 螺旋臂倾角（~12° 为典型值）
  θ₀    = 螺旋臂起始角（每条臂偏移 2π/N）
```

恒星密度在臂上高、臂间低，中心 bulge 区域密集。

### 4.3 确定性保证

- 所有随机使用 `worldSeed + 生成路径` 派生的 `SplittableRandom`
- 生成路径示例：`worldSeed → systemId → planetIndex`
- 保证同 seed 产生完全相同的星系

## 5. 渲染管线（原生 OpenGL / LibGDX）

### 5.1 渲染架构

```
ClientGame.render()
├── 更新模拟 + 快照
├── 判断当前视图（Galaxy / System）
├── 3D 世界渲染（NativeWorldRenderer）
│   ├── Galaxy View
│   │   ├── 星空背景
│   │   ├── 恒星（点精灵批量绘制）
│   │   └── 星云 billboard
│   └── System View（全量 LOD 渲染）
│       ├── 0~10k GU：恒星球体+辉光、行星球体、轨道环、舰船
│       ├── 10k~30k GU：低面数球体、无辉光、无轨道细节

### 6.1 EntitySnapshot 改造

```

### 6.2 实体类型与图标映射

| EntityType | 渲染图标 | 说明 |
|------------|---------|------|
| `STAR` | 发光球体 + billboard 辉光 | 恒星，Galaxy View 为像素点 |
| `PLANET` | 纯色球体 | 颜色由行星类型决定（岩石=灰褐/气态=橙黄/海洋=蓝） |
| `SHIP` | 八面体 / 锥体 | 按舰船分类：战斗机=小锥、驱逐舰=扁八面体、母舰=大菱形体 |
| `STATION` | 立方体 + 环 | 空间站，按类型变体 |
| `ASTEROID` | 不规则小球 | 小行星带粒子 |

### 6.3 没有实体的纯视觉元素

| 元素 | 渲染方式 |
|------|---------|
| 轨道线 | 半透明圆环，每个行星一条 |
| 星云 | Billboard 纹理或体积粒子 |
| 势力边界 | 半透明彩色球壳（System View） |
| 传感器范围 | 虚线球壳 |
| 武器射程 | 虚线球壳（红色） |

### 7.2 状态机（保留）

```
Loaded（内存常驻） → Abstract（后台低频结算） → Dormant（持久化/卸载）
```

转换触发条件：
- 玩家相机进入/离开某个恒星系的兴趣半径
- 玩家舰队进入/离开某个恒星系

### 7.3 Octree 与分片的关系

- Octree 负责**空间索引**（快速查询"哪些实体在视野内"）
- 分片负责**生命周期管理**（哪些恒星系需要完整加载到内存）
- 两者独立但配合：Octree 查询到 systemId → 查找 StarSystem → 判断是否已加载

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| System View 全量渲染性能 | 全范围 ±50,000 内天体多时 draw call 高 | LOD 三级降级：球体→低面→光点，远处天体开销极小 |
| 开普勒方程迭代性能 | 大量行星时 CPU 开销 | 缓存 + 远距离跳过 + 预计算表 |
| Galaxy View 恒星太多 | 数万恒星的 draw call | 点精灵一次 draw call 渲染全部恒星 |
| 渲染复杂度 | 开发周期 | 几何图标最小美术量；无 CRR/对数深度需求 |

---

## 10. 不做的

- **无缝缩放**：改为 Galaxy/System 双视图，简单可靠
- **CRR**：10万³ 盒子内 float 精度足够，不需要
- **对数深度缓冲**：不需要
- **1:1 真实比例**：太空太空旷
- **N 体引力** / **PBR** / **行星地表** / **web 3D**
