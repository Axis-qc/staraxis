# 世界生成流程

> 目标：定义世界生成的权威顺序、阶段划分与接口边界，确保生成过程的确定性、可扩展性与可维护性。

## 0. 核心原则（必须遵守）

- **服务端权威**：世界生成完全在服务端执行。
- **确定性**：整个流程必须是确定性的，输入相同的 `worldGenConfig`（含 `worldSeed`），必须产出完全相同的世界状态。
- **分阶段**：严格区分“分配阶段”（分配ID与类型）和“生成阶段”（生成具体内容），以支持数据驱动与 Mod 扩展。

## 1. 生成输入

- **`worldGenConfig`**：包含所有世界生成参数的配置对象，是整个流程的唯一输入（详见《世界生成参数口径.md》）。

## 2. 生成阶段（Phases）

### Phase 1：星区网格生成 (Sector Grid Generation)

- **输入**：`worldGenConfig.sectorCount`
- **行为**：根据星区数量，生成一个六边形网格，并为每个星区（SectorHex）分配一个唯一的 `sectorId`。
- **输出**：一个包含所有 `sectorId` 的基础星区网格数据结构。

### Phase 2：星区类型分配 (Sector Type Allocation)

- **输入**：基础星区网格、`worldGenConfig` 中的星区类型分布参数（`starSystemDensity`, `nebulaRatio` 等）。
- **行为**：
  1.  **预设分配**：首先处理预设的恒星系（如玩家母星系、关键剧情星系）。
  2.  **随机分配**：对剩余的星区，根据配置的比例参数，为每个 `sectorId` 分配一个 `sectorTypeId`（例如 `star-system`, `nebula`, `deep-space`）。
- **输出**：一个 `Map<sectorId, sectorTypeId>` 的数据结构，定义了每个星区的“宏观类型”。

### Phase 3：内容生成 (Content Generation)

- **输入**：`Map<sectorId, sectorTypeId>`
- **行为**：遍历所有星区，根据其 `sectorTypeId` 调用相应的**子生成器（Sub-Generator）** 来填充具体内容。
- **子生成器接口边界（口径）**：
  - **`StarSystemGenerator`**：
    -   输入：`sectorId`, `worldSeed`
    -   行为：在该星区内生成恒星、行星、轨道等，并调用 `PlanetGenerator`。
    -   输出：一个完整的 `StarSystem` 对象。
  - **`PlanetGenerator`**：
    -   输入：`planetId`, `starSystemSeed`
    -   行为：根据行星类型，生成其核心属性和地表划分（大陆/海洋/次级地貌）。
    -   输出：一个完整的 `Planet` 对象。
  - **`NebulaGenerator`** / **`StormGenerator`** / **`ResourcePointGenerator`** 等：
    -   遵循类似的接口，根据 `sectorId` 和种子生成对应的环境效果或资源点。
- **输出**：一个完整的、包含所有细节的权威世界状态树（World State Tree）。

## 3. 约束与扩展

- **Mod 支持**：Mod 可以通过以下方式介入：
  -   提供新的 `worldGenConfig` 预设。
  -   添加新的星区类型和对应的子生成器。
  -   替换或装饰（Decorate）现有的子生成器。
- **性能**：对于大规模世界，Phase 3 的内容生成可以是“延迟生成”的。即，只在玩家首次接近或需要相关数据时才实际执行该星区的子生成器，而不是在游戏开始时一次性生成所有内容。
