# 世界生成参数口径

> 目标：统一开局设置中与世界生成相关的参数分类、命名与约束口径，便于数据驱动与 Mod 扩展，并为服务端权威生成提供确定性基础。

## 0. 基本前提（必须遵守）

- **服务端权威生成**：世界生成在服务端执行并产出权威世界状态；客户端只接收快照/事件进行呈现。
- **确定性**：相同 `worldSeed + worldGenVersion + worldGenConfig` 必须生成相同世界。
- **分阶段**：分配阶段（只分配类型ID）与生成阶段（实际生成细节）必须分离。

## 1. 参数分类（建议）

### 1.1 规模参数

- 星区数量（六边形网格规模）
- 星域数量（宏观区域划分，可选）
- 恒星系密度（星区中包含恒星系的期望比例）

### 1.2 星区类型分布参数

- 深空比例
- 星云比例
- 风暴比例
- 深空资源比例

> 注：恒星系星区由“恒星系密度”与预设分配共同决定。

### 1.3 资源参数

- 稀有资源出现率
- 资源点密度（星系内/深空）

### 1.4 遗迹/文明遗产参数

- 遗迹点密度
- 文明遗产注入比例（来自上一局的遗迹池）

## 2. 参数命名口径（建议）

- 使用英文 `camelCase`。
- 配置对象建议命名为 `worldGenConfig`，并显式包含：
  - `worldSeed`
  - `worldGenVersion`

示例字段：
- `sectorCount`
- `regionCount`
- `starSystemDensity`
- `deepSpaceRatio`
- `nebulaRatio`
- `stormRatio`
- `deepResourceRatio`
- `rareResourceRate`
- `systemResourcePointDensity`
- `deepSpaceResourcePointDensity`
- `relicDensity`
- `heritageInjectionRatio`

## 3. 参数约束（必须明确）

### 3.1 比例约束

- 所有“互斥分配”的比例参数总和不得超过 1。
- 若允许重叠类型（例如星云+资源），必须在配置层显式声明 `allowOverlaps` 以及重叠规则。

### 3.2 合法范围

每个参数必须定义：
- `default`
- `min`
- `max`

### 3.3 派生与归一化规则（口径）

当比例总和不足 1 时：
- 未分配部分默认归入 `deepSpaceRatio`（深空），或由 `fallbackSectorTypeId` 指定。

当比例总和超过 1 时：
- 生成器必须拒绝该配置并返回明确错误（而不是隐式归一化），避免玩家误解。
