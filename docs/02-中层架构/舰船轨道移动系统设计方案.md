# 舰船轨道移动系统设计方案

> 基于真实轨道力学的自动机动系统：玩家点目标，系统自动计算变轨执行。
> 推进器等级决定移动能力：化学推进→仅轨道机动，聚变推进→可自由移动，曲速→无视重力井。

---

## 1. 目标

- 玩家无需理解轨道力学，**点目标 → 自动变轨 → 到达**
- 推进器等级约束移动方式，形成自然的技术爬坡
- 性能可承受万级舰船同时轨道传播
- AI 与玩家使用同一套机动规划器
- 与现有 `OrbitSolver` / `OrbitalElements` 复用

---

## 2. 舰船机动参数

移动系统直接读取 `ShipBody` 上的数值字段，不经过任何中间层。
这些数值由舰船设计/组装系统在建造时根据引擎配置计算并灌入，移动系统只消费。

| 字段 | 含义 | 单位 |
|------|------|------|
| `systemSpeedGUps` | 星系内移动速度（轨道机动/自由移动用） | GU/游戏秒 |
| `galaxySpeedGUps` | 跨星系移动速度（FTL 跳跃用，>1 可跨星系） | GU/游戏秒 |
| `canFreeMove` | 是否可直飞（true = 不用轨道机动，直接飞向目标） | boolean |
| `fuelConsumptionPerMin` | 主动推进时燃料消耗率 | t/游戏分钟 |
| `fuelPerJump` | 单次曲速跳跃消耗（0 = 不能跳跃） | t |

## 3. 舰船轨道状态模型

### 3.1 ShipBody 新增字段

```java
// ShipBody.java — 新增字段

// --- 机动参数（由舰船设计/组装时灌入，移动系统只读） ---

/** 星系内移动速度（GU/游戏秒）。0 = 无法自行推进。 */
public double systemSpeedGUps;

/** 跨星系移动速度（GU/游戏秒）。<=1 = 不能跨星系。 */
public double galaxySpeedGUps;

/** 主动推进时燃料消耗率（t/游戏分钟）。 */
public double fuelConsumptionPerMin;

/** 单次曲速跳跃消耗（t）。0 = 不能跳跃。 */
public double fuelPerJump;

/** 是否可直飞（true = 不用轨道机动，直接飞向目标）。 */
public boolean canFreeMove;

// --- 轨道状态（移动系统运行时维护） ---

/**
 * 当前轨道根数（轨道机动模式用）。
 * null = 舰船当前不处于开普勒轨道（自由移动或惯性滑行）。
 */
public OrbitalElements orbitalElements;

/**
 * 当前正在执行的机动计划（自动规划/执行）。
 * null = 无活跃机动。
 */
public ManeuverPlan activeManeuverPlan;

// --- 燃料系统 ---

/** 当前剩余推进剂质量（t）。 */
public double fuelMass;

/** 最大推进剂容量（t），用于 UI 显示百分比。 */
public double maxFuelMass;
```

### 3.2 舰船移动模式判定

```
舰船.updateMovement(dt):
  if orbitalElements != null:
    // 在开普勒轨道上 → 求解轨道位置
    posWorldGU = OrbitSolver.solve(orbitalElements, currentTime)
    
  if activeManeuverPlan != null:
    // 有机动计划 → 检查当前时间是否到达点火节点
    executeNextManeuverNode(currentTime)
    
  if canFreeMove && orbitalElements == null:
    // 直飞模式（使用 systemSpeedGUps 作为速度，不经过轨道计算）
    updateFreeMovement(dt, systemSpeedGUps)
    
  if velWorldGU != null && orbitalElements == null:
    // 惯性滑行（无轨道，无主动推进）
    posWorldGU = posWorldGU.add(velWorldGU.scale(dt))
```

## 4. 自动机动规划器（核心）

### 4.1 边界

规划器不修改任何状态。它**只做计算**，返回 `ManeuverPlan` 或 null。调用方（移动系统或上层）读取计划后写入 ShipBody。

```
OrbitalManeuverPlanner.plan(ship, targetPos, targetOrbit, currentTime)
  → 读 ship.systemSpeedGUps / fuelConsumptionPerMin
  → 计算转移轨道
  → 返回 ManeuverPlan（含预计消耗和到达时间）
    或 null（不可达）
  → 不修改任何状态
```

### 4.2 ManeuverPlan

```java
package staraxis.game.space.orbit;

/**
 * ManeuverPlan（机动计划）
 *
 * 自动规划/执行的变轨计划。
 * 由 OrbitalManeuverPlanner 根据起点和目标自动生成。
 */
public class ManeuverPlan {

    /** 计划状态。 */
    public enum Status { PENDING, IN_PROGRESS, COMPLETED, FAILED }

    public final String planId;
    public final Status status;

    /** 机动节点序列（按时间顺序执行）。 */
    public final List<ManeuverNode> nodes;

    /** 总推进时间（游戏分钟）。用于燃料计算。 */
    public final double totalBurnMinutes;

    /** 预估燃料消耗（吨）。 */
    public final double estimatedFuelCost;

    /** 预计到达时间（游戏秒）。 */
    public final double estimatedArrivalTime;

    /** 当前执行到的节点索引。 */
    public int currentNodeIndex;

    public ManeuverNode getCurrentNode() { ... }
    public void advanceToNextNode() { ... }
}

/**
 * ManeuverNode（机动节点）
 *
 * 一次轨道机动的"脉冲"（或连续推力段）。
 */
public class ManeuverNode {

    /** 执行此机动的时间（游戏秒）。 */
    public final double executionTime;

    /** 机动后的轨道根数（脉冲后的新轨道）。 */
    public final OrbitalElements resultOrbit;

    /** 本节点推进持续时间（游戏分钟）。用于燃料消耗计算。 */
    public final double burnDurationMinutes;

    /** 机动类型描述（显示用）。 */
    public final String label; // "霍曼转移点火", "平面修正", "制动捕获" 等
}
```

### 4.3 玩家操作流程

```
玩家选中舰船 → 右键点击目标（行星/空间站/太空点）
  ↓
判定目标位置、是否在重力井内
  ↓
OrbitalManeuverPlanner.plan(ship, target, ...)
  └─ 不可达 → 报告理由（燃料不足 / 速度不够 / 目标超出范围）
  └─ 可达 → 返回 ManeuverPlan
  ↓
生成预览数据（预计到达时间、燃料消耗）
  ↓
玩家确认
  ↓
ship.activeManeuverPlan = plan  ← 写入舰船状态（由指挥/UI 层执行）
  ↓
移动系统逐 tick 执行计划（只改 ship 自身）
```

## 5. Tick 执行流程

### 5.1 舰船移动总 pipeline

移动系统每 tick 遍历 ShipBody，**只修改舰船自身状态**（位置、轨道根数、燃料），不碰 WorldState 中其他数据。

```
ShipMovementSystem.update(worldState, dtGameHours):
  for each ShipBody in worldState:
    ├─ 有 activeManeuverPlan?
    │   ├─ 当前时间 >= 下一个机动节点 → 执行脉冲
    │   │    ├─ 读 ship.fuelConsumptionPerMin 计算燃料
    │   │    ├─ 更新 ship.orbitalElements, ship.fuelMass
    │   │    └─ 推进节点索引
    │   └─ 全部完成 → 清除 ship.activeManeuverPlan
    │
    ├─ ship.orbitalElements != null?
    │   └─ ship.posWorldGU = OrbitSolver.solve(orbitalElements, currentTime)
    │
    ├─ ship.canFreeMove && ship.orbitalElements == null?
    │   └─ 直飞：更新 ship.posWorldGU, ship.fuelMass
    │
    └─ 无轨道无推进 → 惯性滑行：ship.posWorldGU += vel * dt
```

### 5.2 性能分析

```
每 tick 轨道传播（核心操作）:
  OrbitSolver.solve() ≈ 100-150 次浮点运算

10,000 艘舰船:
  10,000 × 150 = 1.5M 浮点运算/tick
  @20 tick/s = 30M ops/s ≈ CPU 单核的 ~0.06%

机动节点执行（偶尔发生）:
  仅当玩家下达指令或 AI 规划时触发
  频率极低（游戏分钟到小时级别）
  单次 < 1μs
```

**结论：万级舰船轨道传播性能开销可忽略。**

## 7. 行星轨道模型统一

当前有两套并行的轨道数据：

| 数据 | PlanetBody | OrbitalElements |
|------|-----------|-----------------|
| 半长轴 | `semiMajorAxisGU` (double) | `semiMajorAxis` (double) |
| 偏心率 | `eccentricity` (double) | `eccentricity` (double) |
| 倾角 | `inclinationDeg` (度) | `inclination` (弧度) |
| 升交点 | `longitudeOfAscendingNodeDeg` (度) | `longitudeOfAscendingNode` (弧度) |
| 近点角 | `periapsisArgDeg` (度) | `argumentOfPeriapsis` (弧度) |
| 平近点角 | `meanAnomalyDegAtEpoch` (度) | `meanAnomalyAtEpoch` (弧度) |
| 周期 | `orbitalPeriodDays` (天) | `period` (秒) |

### 统一方案

`PlanetBody` 新增 `toOrbitalElements()` 方法，**运行时转为 `OrbitalElements` 使用**，平铺字段保留用于序列化和配置定义：

```java
// PlanetBody.java — 新增
public OrbitalElements toOrbitalElements() {
    return new OrbitalElements(
        semiMajorAxisGU,
        eccentricity,
        Math.toRadians(inclinationDeg),
        Math.toRadians(longitudeOfAscendingNodeDeg),
        Math.toRadians(periapsisArgDeg),
        Math.toRadians(meanAnomalyDegAtEpoch),
        0.0,  // epoch
        orbitalPeriodDays * SimulationTime.SECONDS_PER_DAY
    );
}
```

这样舰船进入行星轨道时，可以从行星的 `toOrbitalElements()` 获取基准轨道，再做微调。

## 8. 简化燃料系统

### 核心公式

```
可用推进时间（分钟） = fuelMass / fuelConsumptionPerMin
```

`fuelConsumptionPerMin` 是 ShipBody 上的直接字段，由舰船设计/组装时根据引擎配置计算并灌入。所有引擎共享同一燃料舱。

### 燃料消耗场景

| 动作 | 消耗逻辑 |
|------|---------|
| 轨道机动（一次脉冲点火） | 按点火持续时间×当前引擎消耗率扣减 |
| 自由移动（推进器全开） | 按实际推进秒数×当前引擎消耗率扣减 |
| 曲速跳跃 | 一次性消耗固定量（曲速引擎不按时间计） |
| 轨道滑行/惯性飞行 | **不消耗燃料** |

```java
/**
 * 执行一次推进，消耗燃料。
 *
 * @param ship 舰船
 * @param burnDurationMinutes 推进持续时间（游戏分钟）
 * @return 是否成功（燃料不足返回 false）
 */
public static boolean consumeFuelForBurn(ShipBody ship, double burnDurationMinutes) {
    double needed = ship.fuelConsumptionPerMin * burnDurationMinutes;
    if (ship.fuelMass < needed) return false;
    ship.fuelMass -= needed;
    return true;
}

/**
 * 使用曲速引擎执行一次跳跃（消耗固定燃料）。
 */
public static boolean consumeFuelForJump(ShipBody ship) {
    if (ship.fuelMass < ship.fuelPerJump) return false;
    ship.fuelMass -= ship.fuelPerJump;
    return true;
}

/**
 * 获取剩余可用推进时间。
 */
public static double getRemainingBurnTimeMinutes(ShipBody ship) {
    if (ship.fuelConsumptionPerMin <= 0) return 0;
    return ship.fuelMass / ship.fuelConsumptionPerMin;
}
```

### 各引擎典型参数

| 引擎类型 | 基准消耗率 (t/min) | 典型燃料容量 (t) | 备注 |
|---------|-------------------|----------------|------|
| 化学推进 | 5.0 | 200 | 可连续推进 40 分钟 |
| 离子推进 | 0.1 | 50 | 可连续推进 500 分钟 |
| 聚变推进 | 0.5 | 300 | 可连续推进 600 分钟 |
| 反物质推进 | 0.05 | 100 | 可连续推进 2000 分钟 |
| 曲速引擎 | 50.0/次跳跃 | 500 | 约 10 次跳跃 |

燃料舱是所有引擎共享的。安装多个引擎时，燃料存量不变，但可根据场景切换消耗率不同的引擎。例如携带反物质引擎（0.05 t/min 巡航）+ 曲速引擎（50/次跳跃），日常移动用反物质，远距离用曲速。

### 机动规划时的燃料检查

```
OrbitalManeuverPlanner.plan():
  1. 确定本次任务使用哪个引擎
  2. 计算总机动时间 = 各节点点火时间之和
  3. 计算预估消耗 = 总机动时间 × 该引擎消耗率
  4. if 预估消耗 > fuelMass → 报告"燃料不足"，返回不可达
  5. else → 返回可执行计划
```

## 9. 跨星系 FTL 跳跃

跨星系跳跃使用舰船安装的**曲速引擎**，速度和燃料消耗由引擎数据定义。

### 与引擎系统的集成

`FTLTravelSystem.initiateFTL()` 只修改舰船和跨系统事件表，不碰 WorldState 中其他数据：

1. 校验实体为 `ShipBody`
2. `ship.galaxySpeedGUps <= 1` 或 `ship.fuelPerJump <= 0` → 不能跳跃
3. `ship.fuelMass < ship.fuelPerJump` → 燃料不足
4. 计算旅行时间，扣减燃料，写入事件表

```java
double distance = fromPos.distanceTo(toPos);
double travelTimeSeconds = distance / ship.galaxySpeedGUps;
long travelTimeTicks = Math.max((long) Math.ceil(travelTimeSeconds), 10);
ship.fuelMass -= ship.fuelPerJump;
// 写入事件表供 stage1 到达处理（事件表是跨系统移动专用的数据结构）
```

### 引擎参数示例

| 引擎 ID | 类型 | galaxySpeedGUps | fuelPerJump | 典型间距 200 万 GU 耗时 |
|---------|------|----------------|-------------|----------------------|
| `warp_mk1` | WARP | 1,000 | 30 | ~2,000 游戏秒 ≈ 33s |
| `warp_mk3` | WARP | 5,000 | 50 | ~400 游戏秒 ≈ 7s |
| `warp_mk5` | WARP | 20,000 | 100 | ~100 游戏秒 ≈ 2s |

没有安装曲速引擎的舰船无法跨星系移动，只能在本星系内做轨道机动。

## 11. 与现有系统的兼容

### 替换的内容
- `ShipMovementSystem.update()` — 从"遍历→筛选→路由→物理更新"改为"轨道传播→机动执行→自由移动"的三阶段 pipeline
