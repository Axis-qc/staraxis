## 1. 项目概览

### 1.1 项目简介

StarAxis（星轴）是一个基于 libGDX 框架开发的太空战略游戏，采用 4X（探索、扩张、开发、消灭）玩法，结合宏观大战略管理与微观舰船手控战斗。

**核心特性**：
- 确定性模拟：所有游戏逻辑在权威服务端执行，保证状态一致性
- 数据驱动设计：游戏内容通过配置文件定义，支持 mod 扩展
- 分层架构：严格分离权威逻辑、展示层和网络层
- 多端支持：原生客户端（LibGDX）、Web 控制台、AI 接口

### 1.2 技术栈

| 层次 | 技术栈 | 说明 |
|------|--------|------|
| **权威模拟层** | Java 17+, Gradle | `game` 模块，纯 Java 实现 |
| **原生客户端** | LibGDX, LWJGL3, OpenGL | `client` + `lwjgl3` 模块 |
| **UI 框架** | Scene2D, JSON UI | `ui` 模块，声明式 UI |
| **网络服务** | Java, Vert.x/WebSocket | `webnet` 模块 |
| **Web 前端** | Vue 3, TypeScript, Three.js | `web` 模块（AI 控制台） |
| **构建工具** | Gradle, npm | 多模块构建 |

### 2.2 模块详细职责

#### 2.2.1 `game` - 权威模拟层

**职责**：
- 维护权威世界状态 `WorldState`
- 推进模拟时间 `SimulationTime`
- 执行玩家/AI/系统命令
- 运行各模拟系统（移动、殖民、经济、战斗等）
- 发布只读快照 `RealTimeWorldState`、`DailySettlementState`

**核心类**：
```java
StarAxisGameRuntime      // 游戏运行时主入口
WorldState               // 权威世界状态
CommandBus               // 命令总线
SimulationTime           // 模拟时间管理
TimelineSystem           // 时间线系统
```

**关键约束**：
- 除模拟层外，其他层不得直接写 `WorldState`
- 外部控制必须转换为 `Command`
- 渲染层优先读取 `RealTimeWorldState`

#### 2.2.2 `client` - 原生客户端

**职责**：
- 持有原生渲染器 `NativeWorldRenderer`
- 管理输入系统、相机系统、选择系统
- 本机 Host 模式下持有并推进 `StarAxisGameRuntime`
- 将玩家输入转换为命令

**核心类**：
```java
ClientGame               // 客户端应用入口
NativeWorldRenderer      // OpenGL 世界渲染器
InputProcessor           // 输入处理
```

**运行模式**：
- **本机 Host**：直接持有 `StarAxisGameRuntime`，同进程调用
- **远程 Client**：连接服务器，接收网络同步帧

#### 2.2.3 `lwjgl3` - 桌面启动器

**职责**：
- 创建 LWJGL/libGDX 应用窗口
- 加载平台配置和图标
- 启动 `ClientGame`

**核心类**：
```java
Lwjgl3Launcher           // 桌面启动入口
StartupHelper            // 启动辅助工具
```

#### 2.2.4 `ui` - UI 组件库

**职责**：
- 提供 Scene2D UI 组件
- 声明式 JSON UI 系统
- 国际化支持
- 设置管理

**核心类**：
```java
Gui                      // UI 根容器/服务定位器
UiParser                 // JSON UI 解析器
UiFactory                // UI 控件工厂
I18nService              // 国际化服务
FontProvider             // 字体管理
```

**设计模式**：
- 服务定位器模式：`Gui` 作为 UI 层服务容器
- 声明式 UI：通过 JSON 定义界面结构
- Action 分发：通过 `dispatchAction()` 上抛交互意图

#### 2.2.5 `webnet` - 网络服务层

**职责**：
- 管理联机世界/房间/会话
- 提供 HTTP/WebSocket API
- 账号、token、权限管理
- AI 工具网关

**核心类**：
```java
WebNetServer             // 网络服务器主类
GameSessions             // 游戏会话管理
SnapshotBroadcaster      // 快照广播器
WebPlayerWebSocketHandler // WebSocket 处理器
```

**API 模块**：
- `auth/` - 认证与授权
- `api/` - REST API 路由
- `websocket/` - WebSocket 处理
- `game/` - 游戏会话管理

#### 2.2.6 `web` - Web 控制台

**职责**：
- AI 聊天控制台
- 世界/房间管理界面
- 登录/账号界面
- 摘要与日志展示

**技术栈**：
- Vue 3 + TypeScript
- Vue Router 路由管理
- Pinia 状态管理
- Three.js（历史保留，非主要渲染）

## 3. 运行时架构

### 3.1 核心数据流

```text
┌─────────────────────────────────────────────────────────────────┐
│                         数据流架构                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐         │
│  │   输入层    │    │   命令层    │    │   模拟层    │         │
│  │  (Input)    │───▶│ (Command)   │───▶│ (Simulation)│         │
│  └─────────────┘    └─────────────┘    └──────┬──────┘         │
│                                               │                 │
│                                               ▼                 │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐         │
│  │   渲染层    │◀───│   快照层    │◀───│  世界状态   │         │
│  │ (Renderer)  │    │ (Snapshot)  │    │(WorldState) │         │
│  └─────────────┘    └─────────────┘    └─────────────┘         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 状态发布机制

#### 3.2.1 高频实时快照 `RealTimeWorldState`

- **发布频率**：每 Tick 发布
- **内容**：实体位置、速度、朝向等动态数据
- **用途**：原生客户端渲染、高频同步
- **机制**：双缓冲 `RealTimeWorldStateBuffer`

```java
// 发布流程
StarAxisGameRuntime.update(dt)
  → TimelineSystem.advanceOneTick()
  → commandBus.executeCommands()
  → shipMovementSystem.update()
  → publishRealTimeSnapshot()
    → realTimeBuffer.swapPublish()
```

#### 3.2.2 低频基线快照 `DailySettlementState`

- **发布频率**：每 60 游戏秒或事件触发
- **内容**：行星地表、国家资产、公开实体基线
- **用途**：低频同步、减少网络压力
- **机制**：脏标记驱动 `DailySettlementStateBuffer`

### 3.3 命令系统

#### 3.3.1 命令总线 `CommandBus`

```java
CommandBus
  ├── register(CommandType, Handler)
  ├── submit(Command)
  └── executeCommands(WorldState, dt)
```

#### 3.3.2 命令类型

| 命令 | 说明 |
|------|------|
| `SetPlayerTimeStepCommand` | 设置玩家时间步长 |
| `SetSystemTimeScaleCommand` | 设置系统时间缩放 |
| `ColonizePlanetCommand` | 殖民行星 |
| `MoveShipCommand` | 移动舰船 |

#### 3.3.3 命令执行流程

```text
玩家输入/网络请求
  → 转换为 Command 对象
  → CommandBus.submit(command)
  → CommandBus.executeCommands(worldState, dt)
  → Handler.execute(worldState, command, dt)
  → WorldState 更新
```

**设计目标**：
- 支持 mod 通过 JSON 声明对界面的 add/override 修改
- 无需修改源代码即可定制 UI

---

## 10. 开发指南

### 10.1 代码规范

- 字段写法必须一致，文档中字段统一用 `fieldName`（解释）格式
- 所有代码必须带注释
- 禁止删除已有注释，仅允许修改/补充
- 新建方法或字段前先检索代码库，避免重复实现
- 禁止硬编码与硬枚举，避免魔法数字与散落字符串

### 10.2 核心原则

1. **单机权威与本地世界状态**
2. **确定性模拟要求**
3. **数据驱动设计**
4. **实体-ID 索引模型**

### 10.3 通信边界

- 通信流向固定：`game` → `webnet` → `web`
- 禁止 `web` 与 `game` 直接交互
- 权威状态仅在 `game`；`web` 仅缓存展示态

### 10.4 开发工作流

1. **开始工作前**：查看 `0-docs/当前进行中.md`
2. **工作结束时**：更新 `0-docs/当前进行中.md`
3. **任务完成时**：将任务从"进行中"移到日志
