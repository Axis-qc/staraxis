# StarAxis 架构设计\n\n## 1. 架构结论\n\n当前主架构是原生 LibGDX 客户端。\n\n主启动链路：\n\n```text\n:lwjgl3:run\n  -> staraxis.lwjgl3.Lwjgl3Launcher\n  -> staraxis.ClientGame\n  -> staraxis.game.StarAxisGameRuntime\n  -> staraxis.ui.*\n```\n\n核心原则：\n\n- `lwjgl3` 只负责桌面平台启动和窗口配置。\n- `client` 是原生客户端应用层，负责 LibGDX 生命周期、主循环、输入、渲染组织、UI 初始化和游戏运行时连接。\n- `ui` 是原生 Scene2D UI 层，负责菜单、设置、HUD、控件、JSON UI、皮肤和字体。\n- `game` 是纯 Java 游戏核心层，负责模拟、世界状态、命令、时间、生成、存档和规则。\n- `assets` 存放只读本体资源和配置。\n- `gamedata` 存放用户数据、设置、存档、Mod、账号和日志。\n- `web` / `webnet` 作为历史或辅助链路，不是当前主客户端架构。\n\n## 2. 模块职责\n\n### `lwjgl3`\n\n桌面平台层。\n\n职责：\n\n- 创建 LWJGL3 / LibGDX 桌面窗口。\n- 处理平台启动兼容性。\n- 在 Gdx 初始化前读取窗口相关设置。\n- 设置窗口标题、分辨率、全屏、VSync、FPS 限制、图标和 OpenGL 配置。\n- 启动 `ClientGame`。\n- 负责桌面打包和平台发行相关任务。\n\n边界：\n\n- 不写游戏规则。\n- 不持有世界状态。\n- 不直接构建具体游戏 UI。\n\n### `client`\n\n原生客户端应用层。\n\n职责：\n\n- 实现 LibGDX `ApplicationListener`。\n- 创建和管理主 `Stage`、相机、输入、渲染器和 Screen 流程。\n- 初始化 `ui` 层服务。\n- 初始化或连接 `game` 运行时。\n- 将 UI action 转换为游戏命令。\n- 将 `game` 状态转换为渲染和 UI 可消费的视图数据。\n- 管理客户端本地调试开关、生命周期和资源释放。\n\n当前状态：\n\n- `ClientGame` 目前只完成日志桥接和清屏。\n- `UiPreviewApp` 已演示 UI 初始化方式，可作为正式接入 UI 的参考。\n\n### `ui`\n\n原生 Scene2D UI 层。\n\n职责：\n\n- 管理 `Gui` 根容器。\n- 提供主菜单、设置界面、测试界面、弹窗和通用控件。\n- 加载 UI Skin、字体、i18n 文本和 JSON UI。\n- 通过 `Gui.dispatchAction()` 上抛用户意图。\n\n边界：\n\n- UI 不直接修改 `WorldState`。\n- UI 不推进游戏模拟。\n- UI action 由 `client` 接收后转换为命令或界面切换。\n\n### `game`\n\n纯 Java 游戏核心层。\n\n职责：\n\n- 维护世界状态和游戏规则。\n- 负责世界生成、星区、恒星系、行星、舰船、国家、情报、可见性、经济、存档等系统。\n- 负责模拟时间推进。\n- 负责命令校验和执行。\n- 提供运行时接口给 `client` 或辅助服务调用。\n\n边界：\n\n- 不依赖 LibGDX。\n- 不依赖 UI。\n- 不依赖 Web / WebNet。\n- 不做渲染。\n\n### `assets`\n\n只读本体资源目录。\n\n内容：\n\n- UI skin、字体、i18n。\n- JSON UI 配置。\n- 星体、行星、资源、情报等游戏配置。\n- 图片、特效、世界资源。\n\n规则：\n\n- 可随游戏发行。\n- 作为默认资源和默认配置来源。\n- 不存放玩家存档和运行期数据。\n\n### `gamedata`\n\n运行期和用户数据目录。\n\n内容：\n\n- 设置。\n- 存档。\n- 账号。\n- 玩家国家。\n- Mod。\n- 日志。\n\n规则：\n\n- 不作为源码模块。\n- 不应放入构建产物。\n- 路径应与 `assets` 区分。\n\n### `web` / `webnet`\n\n辅助或历史链路。\n\n定位：\n\n- `web` 是 Vue/Three.js Web 客户端。\n- `webnet` 是 HTTP/WebSocket 宿主。\n- Web 快照和插值架构不作为当前原生客户端主线。\n- 后续若保留，应作为调试、远程控制、Web 预览或独立发行路线处理。\n\n## 3. 原生客户端数据流\n\n### 启动阶段\n\n1. `Lwjgl3Launcher` 创建日志目录。\n2. `Lwjgl3Launcher` 读取启动前设置。\n3. `Lwjgl3Launcher` 创建 LWJGL3 窗口。\n4. LibGDX 调用 `ClientGame.create()`。\n5. `ClientGame` 初始化日志、资源、Stage、UI、输入和游戏运行时。\n6. 客户端进入主循环。\n\n### 主循环阶段\n\n1. `ClientGame.render()` 获取 `deltaTime`。\n2. `client` 推进或调度 `game` 运行时。\n3. `game` 按模拟时间更新世界状态。\n4. `client` 将世界状态转换为渲染数据。\n5. 渲染层绘制世界。\n6. `ui` 绘制 Scene2D 界面。\n7. 输入事件通过 UI 或输入系统转为 action / command。\n\n## 4. `game` 与 `ui/client` 边界\n\n### `game` 可以做\n\n- 生成世界。\n- 保存和读取权威状态。\n- 校验命令。\n- 推进模拟。\n- 计算经济、移动、可见性、情报和结算。\n\n### `game` 不应做\n\n- 调用 LibGDX API。\n- 创建 Stage、Actor、Texture、Camera。\n- 读取 UI 控件状态。\n- 处理平台窗口。\n\n### `ui` 可以做\n\n- 展示菜单和面板。\n- 显示设置和状态。\n- 抛出 action。\n- 管理 UI 资源。\n\n### `ui` 不应做\n\n- 直接改世界状态。\n- 直接推进模拟时间。\n- 直接执行游戏命令。\n\n### `client` 负责连接两者\n\n- 接收 UI action。\n- 构造 game command。\n- 调用 game runtime。\n- 将 game 状态转为 UI/渲染需要的数据。\n\n## 5. 当前优先补齐事项\n\n1. 在 `ClientGame` 中接入正式 UI 初始化流程。\n2. 统一设置文件路径，当前 launcher 预读取路径与 UI 设置仓库路径需要对齐。\n3. 在 `ClientGame` 中接入 `StarAxisGameRuntime` 生命周期。\n4. 建立原生渲染层与 `game` 状态之间的视图模型。\n5. 明确 Web/WebNet 是否保留为辅助调试链路。\n\n## 6. 构建与运行\n\n- 原生客户端运行：`gradlew.bat :lwjgl3:run`\n- 原生客户端打包：`gradlew.bat :lwjgl3:jar`\n- UI 预览入口：`UiPreviewLauncher` / `UiPreviewApp`\n- Web 辅助链路：`gradlew.bat runWeb`\n
