## 1. 设计约束（来自底层架构文档）

- **game 权威**：`WorldState` 常驻 `game` 运行时内存，`simulationTick` 驱动实时系统；跨日后生成 `DailySettlementState` 供 UI / 控制台展示。
- **ID 索引模型**：所有实体用 ID 索引；跨 tick 不持有权威对象引用。
- **唯一写入口**：玩家输入、AI 工具调用、网络请求都必须转换为 `Command`，通过 `game` 运行时命令入口提交。
- **渲染只读**：`client`、`ui`、`web`、`webnet` 都不得直接写权威 `WorldState`。
- **主画面原生渲染**：主游戏画面由 `client`/`lwjgl3` 使用 libGDX/OpenGL 渲染。
- **web 控制台定位**：`web` 后续是 AI 控制台 / 管理控制台，不再作为 Three.js 主游戏画面客户端。
- **webnet 网关定位**：`webnet` 后续是联机网络管理与控制网关，负责账号、权限、房间、AI/API、原生联机同步，不实现第二套游戏规则。
- **存档**：写入实体文件（建议扩展名 `.sav`），必须包含 `gameVersion`，采用原子写入；支持有限向前兼容。

## 3. 现状与迁移建议（基于当前仓库）

当前仓库已存在：

- `0-docs/`：文档根目录。
- `assets/`：资源根目录。
- `gamedata/`：运行时数据根目录。
- `game/`：游戏主逻辑模块，目前仍在逐步补齐权威运行时。
- `client/`：原生客户端应用层。
- `ui/`：原生 UI 层。
- `lwjgl3/`：桌面端启动与打包模块。
- `webnet/`：后续联机网络管理与控制网关。
- `web/`：后续 AI 控制台 / 管理控制台。

建议迁移路径（不强制一次到位）：

1. **阶段 1：原生本机 Host MVP**
   - `client` 创建/持有 `game` 运行时。
   - `client` 读取 `game` 只读快照并原生渲染。
   - 输入转换为 `Command` 后提交到运行时。

2. **阶段 2：web AI 控制台 MVP**
   - `web` 收敛为 AI 控制台 / 管理控制台。
   - `webnet` 暴露受控 API / tool gateway。
   - AI/API 写操作统一转换为 `Command`。

3. **阶段 3：原生联机 MVP**
   - `webnet` 增加账号、权限、房间、原生联机 WebSocket。
   - Dedicated Server 持有唯一 `game` 权威运行时。
   - 原生客户端接收状态帧、提交命令请求。

4. **阶段 4：engine 抽象与工具化**
   - 若通用资产、事件、IO、调度、数学工具增长到足够规模，再恢复/引入 `engine/` 模块。
   - 不为“目录完整”提前拆出空模块。

## 4. 资源目录规范（assets）

### 4.1 UI / 控制台资源

- UI 资源位于：`assets/ui/`。
- 用于原生 UI、控制台 UI、图标、字体、皮肤、HUD 图片等。
- 必须按功能分类组织，建议：
  - `assets/ui/common/`：通用图标、边框、按钮、背景等。
  - `assets/ui/hud/`：HUD 相关资源。
  - `assets/ui/menu/`：主菜单、设置、存档管理、国家选择、世界生成等页面资源。
  - `assets/ui/console/`：AI 控制台 / 管理控制台共享资源。
- 禁止把会改变游戏结果的规则数据混入 UI 资源目录。

### 4.2 资源加载口径

- 原生客户端运行时工作目录优先指向 `assets/`。
- UI、渲染和音频资源必须支持离线读取，禁止依赖外网资源。
- Mod 资源覆盖必须遵循 `gamedata/mods/mod-order.json` 定义的顺序。

## 5. 存档/配置/蓝图目录规范（gamedata）

### 5.1 存档（Save）

- 默认目录：`gamedata/saves/`。
- 推荐扩展名：`.sav`。
- 文件名建议包含：存档名 + 时间戳（便于管理）。
- 存档写入必须采用原子写入策略，避免崩溃导致主存档损坏。

### 5.2 用户设置（Config / Setting）

- 当前仓库已有目录：`gamedata/setting/`。
- 若后续统一为 `gamedata/config/`，需要同步迁移代码与文档。
- 用于保存：分辨率、最大帧数、是否全屏、画质选项、音量、语言等。

### 5.3 账号与国家数据

- 账号相关运行时数据：`gamedata/accounts/`。
- 国家相关运行时数据：`gamedata/nations/`。
- 多人联机上线后，账号、token、权限、玩家与国家绑定关系应由 `webnet` 管理，`game` 只接受已授权后的玩家命令。

### 5.4 舰船蓝图（Blueprint）

- 默认目录：`gamedata/blueprints/`。
- 蓝图与存档解耦，可独立导入/导出。
- 蓝图在进入游戏规则计算前必须由 `game` 校验合法性。

### 5.5 日志（Logs）

- 推荐目录：`gamedata/logs/`。
- 如模块已有独立日志配置，应逐步统一到该目录或在文档中明确例外。

### 5.6 Mod 加载与覆盖规则（Mods）

- Mod 目录：`gamedata/mods/`。
- Mod 启用与排序唯一权威：`gamedata/mods/mod-order.json`。
- 加载顺序：本体 → `mod-order.json` 中启用的 Mod 顺序。
- 覆盖规则：同一资源/数据 key 冲突时，后加载覆盖先加载（last-wins）。
- 建议结构（最小约定）：
  - `gamedata/mods/<modId>/`：单个 Mod 根目录。
  - `gamedata/mods/<modId>/assets/`：该 Mod 提供的运行时资源（与 `assets/` 保持相对路径一致）。
  - `gamedata/mods/<modId>/data/`：该 Mod 提供的数据文件（如数值表/定义）。
  - `gamedata/mods/<modId>/i18n/`：该 Mod 提供的语言包。
- Mod 的功能/规则注入必须发生在 `game` 权威模拟内；`web`、`webnet`、`ui` 不得注入第二套会改变游戏结果的逻辑。

## 7. 命名与提交约定

- **目录命名**：优先使用英文 `kebab-case`（例：`world-gen/`）。
- **代码标识符**：英文；文档与注释使用简体中文。
- **用户数据目录（gamedata）**：默认不提交到仓库（应加入 `.gitignore` 或仅提交必要模板）。
- **文档同步**：新增模块、移动目录、改变职责边界时，必须同步更新：
  - `0-docs/总目录.md`
  - `0-docs/游戏文件目录.md`
  - `0-docs/快速上手.md`
  - 本文档
