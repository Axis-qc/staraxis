# AGENTS 工作日志 - 2026-06-09

> **摘要**：修复打包后舰船移动缓慢、O键无法打开调试窗口的问题。优化前后端数据流架构：移除旧版快照、分离高/低频快照职责、异步化低频序列化、修复前端CPU高占用问题喵。

## 已完成的任务

### 1. O键打开调试窗口修复
- **问题描述**：打包后按O键无法打开测试工具窗口
- **解决方案**：`useInGameDebugWindow.ts` 中 `import.meta.env.DEV` 在生产构建为 `false`，改为默认 `true`。同时支持 `?debug=1` URL参数和 `localStorage sa.debugMode` 开关喵
- **相关文件**：`web/src/features/inGame/composables/useInGameDebugWindow.ts`

### 2. 旧版快照移除 + 高/低频快照职责分离
- **问题描述**：每tick发送3个消息（高频+低频+旧版），每个都包含1935个实体全量JSON，远超50ms间隔
- **解决方案**：
  - 移除旧版快照（`type: 'snapshot'`）的发送和前端处理
  - 高频快照（50ms）只含动态实体（舰船），不再包含恒星/行星
  - 低频快照（1s）携带公开实体基线（恒星/行星/重心）
  - 低频JSON序列化+WebSocket发送异步到后台线程，不阻塞gameTicker
- **相关文件**：
  - `webnet/.../SnapshotBroadcaster.java`
  - `webnet/.../SnapshotMessageFactory.java`
  - `webnet/.../SnapshotLowFreqMessageDto.java`
  - `webnet/.../WebPlayerWebSocketHandler.java`
  - `webnet/.../WebNetServer.java`

### 3. 前端渲染管线优化
- **问题描述**：前端每tick将1935个实体全部传入渲染管线，导致多次全量遍历
- **解决方案**：
  - 高频快照处理不再合并低频实体到渲染缓存（低频基线一次性设置）
  - 移除重复的 `syncEntitiesFromWorld()` 调用（之前每tick调2次 = 40次/秒）
  - `frameBuilder.build()` 直接引用 Map 而非 `new Map(entitiesById)` 复制
  - `entityQuerySystem` 新增 `addEntities` 增量方法，不清除基线
  - 移除 `frameStateBuilder.build()` 中重复的 `defaultGameTimeManager.update()` 调用
  - 移除 `entityQuerySystem` 行星计算中每行星调一次 `defaultGameTimeManager.update()`（1451次/帧 → 0次）
  - 行星渲染器先以轨道中心做粗略剔除，再算精确轨道位置
- **相关文件**：
  - `web/src/views/InGameView.vue`
  - `web/src/features/inGame/composables/useInGameDataHub.ts`
  - `web/src/rendering/worldRenderManager.ts`
  - `web/src/rendering/systems/frameStateBuilder.ts`
  - `web/src/rendering/systems/entityQuerySystem.ts`
  - `web/src/rendering/layers/celestial/renderers/planetRenderer.ts`

### 4. 后端广播计时日志 + 调试窗口按钮
