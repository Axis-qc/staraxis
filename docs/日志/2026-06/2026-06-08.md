## 舰船移动节奏抖动修复喵

### 问题描述喵
- 舰船移动呈现明显的"快-慢-快-慢"节奏抖动喵。
- 30帧捕获数据显示每3帧有1帧 blend=1.000 位置完全停住喵。

### 根因喵
- [snapshotInterpolationBuffer.ts](web/src/game/world/interpolation/snapshotInterpolationBuffer.ts) 的 `getWindow` 方法中，执行顺序为：
  1. `syncCurrentCycleState()` — 查找下一帧喵。
  2. `buildWindow()` — 计算 `renderAlpha = clamp01(elapsed / 50)`，返回窗口喵。
  3. `promoteCompletedCycles()` — 升格喵。
- 当 elapsed ≥ 50ms 时，`buildWindow` 先返回 `renderAlpha=1.0` 的卡帧窗口（舰船停在终点），然后 `promoteCompletedCycles` 才执行升格喵。
- 下一帧 promote 已完成，`renderAlpha` 从 0 开始 —— 就产生了"停一帧→跳一下"的节奏抖动喵。

### 修复喵
- 把 `promoteCompletedCycles` 调用移到 `buildWindow` 之前喵。这样 elapsed ≥ 50ms 时，先升格再构建窗口，`renderAlpha` 从 0 开始，舰船直接进入新段插值，不再卡帧喵。
- 同时让 `promoteCompletedCycles` 在升格后如果 `nextSnapshotBuffer` 为空，主动从帧缓存查找下一帧，避免进入冻结/外推模式喵。

### 改动文件喵
- [snapshotInterpolationBuffer.ts](web/src/game/world/interpolation/snapshotInterpolationBuffer.ts)：
  - `getWindow` 中 promote 调用移到 buildWindow 之前喵。
  - `promoteCompletedCycles` 中增加空 nextSnapshotBuffer 的回退查找逻辑喵。

## 舰船移动节奏抖动 - 第二轮修复喵

### 问题喵
- 第一轮修复（promote 前移）后仍有"快-慢-快-慢"节奏抖动喵。
- 根因不是 promote 时机，而是**固定 50ms 插值周期**与**实际帧到达时间不对齐**喵。
- 帧间隔有抖动（40ms~55ms），但插值周期固定 50ms，导致：
  - 帧间隔 40ms 时：alpha 提前到 1.0 → 等待 → 快喵。
  - 帧间隔 55ms 时：alpha 还没到 1.0 → 速度偏慢喵。

### 修复喵
- 把固定 `logicFrameDurationMs`（50ms）替换为动态 `cycleDurationMs` 喵。
- `cycleDurationMs` 通过两帧之间的**游戏时间差**计算：`deltaGameSeconds × 1000` 喵。
- 因为后端每 Tick 推进固定游戏时间增量（0.05s），所以游戏时间差 = 真实时间差，不受网络抖动影响喵。
- 钳位到 [20ms, 200ms] 范围，避免异常帧导致周期过短或过长喵。
- 在 `seedInitialWindow`、`resetToLatestFrame`、`syncCurrentCycleState`、`promoteCompletedCycles` 中都更新 `cycleDurationMs` 喵。

### 改动文件喵
- [snapshotInterpolationBuffer.ts](web/src/game/world/interpolation/snapshotInterpolationBuffer.ts)：新增 `cycleDurationMs` 字段和 `calculateCycleDurationMs` 方法，所有插值周期计算从固定值改为动态值喵。
- ✅ 用户确认修复后舰船移动流畅喵。

## 渲染坐标精度修复喵

### 问题喵
- 在大世界坐标（±3 亿 GU）处，Three.js float32 精度只有 ±16 GU喵。
- 行星轨迹成块、物体抖动喵。

### 根因喵
- 后端 `Vec2d(double, double)` = float64，JSON 传输无损喵。
- 但 Three.js `Vector3` 内部是 float32，大坐标直接写入导致精度崩溃喵。
- 文档 `坐标系与尺度.md` 要求"表现坐标原点为相机所在的权威世界坐标"，但之前未实现喵。

### 修复喵
- [worldRenderContext](web/src/rendering/worldRenderManager.ts) 新增 `toRenderPos(worldPos)` 工具函数喵。
  - 在 float64（JS number）端做 `entityPos - cameraPos` 减法喵。
  - 结果（小数值）写入 float32，精度完美喵。
- [cameraSystem.ts](web/src/rendering/systems/cameraSystem.ts)：相机固定 `(0,0,h)`，撤销 `worldGroup.position` 偏移喵。
- 所有渲染器（行星/恒星/舰船/选中环/网格/六边形轮廓）统一使用 `ctx.toRenderPos()` 转换坐标喵。

### 精度对比喵
```
修复前：float32 在 3 亿处精度 ≈ ±16 GU（±16 像素抖动）
修复后：渲染坐标 ≈ 视口内几千 GU，float32 精度 ≈ ±0.0003 GU
```
