## 问题与解决方案

### 问题1：AI 系统架构耦合度高
- **现象描述**：`ai_system` 作为独立 Python 进程，需要单独维护和启动，AI 模型配置硬编码
- **原因分析**：初始设计将 AI 作为内置功能，未考虑玩家自定义需求
- **解决方案**：设计插件化架构，暴露 REST/WebSocket API，让玩家通过浏览器扩展接入
- **验证结果**：架构设计文档已完成，`ai_system` 自动启动已禁用

### 问题2：Copilot 指令文件过长
- **现象描述**：`copilot-instructions.md` 约 150 行，token 消耗大
- **原因分析**：所有规范都内联在一个文件中，未利用模块化结构
- **解决方案**：精简主文件，创建模块特定的 `.instructions.md` 和任务特定的 `.prompt.md`
- **验证结果**：主文件减少到约 80 行，创建了 7 个模块/任务文件

## 技术要点

### AI 插件化架构核心设计
1. **API 暴露原则**：不影响游戏逻辑的 API 都可以暴露
2. **权限隔离**：AI 使用玩家 token 认证，只能访问该玩家有权限的数据
3. **插件形态**：支持浏览器扩展或玩家魔改前端
4. **迁移策略**：保留 `ai_system` 代码但默认禁用，后续可移除
5. **简化决策**：只在前端暴露API，不考虑完整插件系统，未来插件直接复用

### Copilot 自定义配置优化
1. **精简主文件**：从约 150 行减少到约 80 行
2. **模块化指令**：通过 `applyTo` 模式自动应用到特定文件
3. **任务模板**：创建常用任务的 prompt 文件，加速开发流程
