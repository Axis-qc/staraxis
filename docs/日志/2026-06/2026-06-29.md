## GPU 渲染问题诊断 + 独立启动器开发

### 问题背景
用户反馈游戏渲染时 CPU 占用高，怀疑未使用 GPU 硬件加速。

### 诊断过程
1. 在 `Lwjgl3Launcher.populateGpuListPostGl()` 临时加诊断代码，把 `GL_VENDOR/GL_RENDERER/GL_VERSION` 写到独立文件 `gamedata/logs/gpu_diag.txt`（避免被 `GameLog.initTruncate()` 清空）
2. 运行游戏读取诊断文件，发现：
   ```
   GL_VENDOR:   Intel
   GL_RENDERER: Intel(R) Iris(R) Xe Graphics      ← 实际渲染用的是集显
   Available GPUs: Intel Iris Xe Graphics, NVIDIA GeForce RTX 3050 Ti Laptop GPU
   ```
3. 根因：双显卡笔记本，Windows 默认让 Java 进程走集显（节能模式），独显闲置

### 解决方案：独立启动器（launcher/ 模块）
不修改游戏代码，新建独立 Python 启动器，通过写 Windows 注册表 `HKCU\Software\Microsoft\DirectX\UserGpuPreferences` 设置 GPU 偏好。

#### 技术选型决策
- **技术栈**：Python + Tkinter（跨平台、开发快、复用现有 Python 环境）
- **分发方案**：开发用系统 Python，发布用 PyInstaller 打包成单 exe（玩家无需装 Python）
- **GPU 设置方式**：写注册表 `GpuPreference=2`（高性能），用户无感

#### 启动器架构
```
launcher/
├── src/staraxis_launcher/
│   ├── __init__.py          # 包定义
│   ├── gpu_detector.py      # GPU 检测（PowerShell Win32_VideoController）
│   ├── gpu_preference.py    # 注册表 GPU 偏好读写
│   ├── game_launcher.py     # 游戏启动（dev/release 双模式）
│   ├── gui.py               # Tkinter GUI 界面
│   └── main.py              # 入口（GUI/CLI 双模式）
├── build_exe.bat            # PyInstaller 打包脚本
└── requirements.txt         # 依赖（仅打包需 PyInstaller）
```

#### 关键设计
- **GPU 检测**：调用 PowerShell `Get-CimInstance Win32_VideoController`，JSON 解析，识别集显/独显，排除虚拟显示器
- **GPU 偏好**：写注册表 `GpuPreference=2`（高性能）/ `1`（节能）/ 清除（系统默认）
- **启动模式**：自动检测 dev（gradlew run）和 release（StarAxis.bat）两种模式，从 `gradle.properties` 读取 JDK 路径
- **GUI**：GPU 列表展示 + 偏好单选 + 启动模式下拉 + 应用/启动按钮

### 验证结果
- CLI 模式：检测到 2 块 GPU（NVIDIA RTX 3050 Ti + Intel Iris Xe），2 个启动模式
- GUI 模式：窗口正常显示，GPU 列表和按钮可用
- 注册表写入：`HKCU\...\UserGpuPreferences` 中 `C:\Users\hp\.jdks\openjdk-21.0.2\bin\java.exe REG_SZ GpuPreference=2` 写入成功

### 技术要点
- **GPU 偏好注册表**：`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`，值名=exe路径，值数据=`GpuPreference=2`，仅 Win10 1903+ 支持
- **GpuPreference 限制**：只能选"高性能"或"节能"，不能指定具体哪块 GPU；要指定具体 GPU 需用户手动在 Windows 设置 > 系统 > 显示 > 图形 操作

- **GameLog.initTruncate() 冲突**：`game.log` 会被 GameLog 在游戏运行时清空，导致 logback 写入的启动期日志丢失，诊断时需用独立文件
