## 工作摘要
修复暂停菜单（PauseMenu）的多项缺陷：UI 闪烁由深度测试状态泄漏导致、点击按钮触发射线拾取的竞态问题、退回主界面后世界状态泄漏导致新游戏异常。全面排查根因后集中修复。

## 已完成的任务

### 1. UI 闪烁全面排查
- **问题**：暂停菜单 UI 闪烁、消失又出现
- **排查范围**：ClientGame 渲染循环、PauseMenu draw()、Gui switchScreen、深度测试状态、InGameHudScreen 冲突
- **定位 5 个根因**：
  1. `renderGalaxyView()` 中的 `isButtonJustPressed(LEFT)` 在 `stage.act()` 之前执行，点击暂停按钮同时触发射线拾取
  2. PauseMenu / VectorButton draw() 未禁用深度测试，片元被 3D 场景深度值切割
  3. InGameHudScreen 和 PauseMenu 同时在 stage 上，HUD 透出遮罩
  4. `switchScreen()` 的 `stage.clear()` 移除 PauseMenu，返回后未恢复
  5. 暂停时仅停 runtime，3D 场景仍全帧渲染浪费性能
- **相关文件**：`ClientGame.java`、`PauseMenu.java`

### 2. 暂停冻结 3D 场景
- **问题**：暂停时 3D 场景仍渲染，深度测试泄漏到 UI，输入事件被场景抢先处理
- **修复**：`renderSpaceScene(dt)` 移入 `if (!paused)` 块内；暂停时跳过天空盒/星系/行星渲染和相机更新
- **效果**：上一帧画面留在缓冲中作为静态背景

### 3. UI 始终在最上层
- **问题**：`stage.draw()` 执行时深度测试仍开启，UI 片元与 3D 深度值比较导致闪烁
- **修复**：`stage.draw()` 前加 `glDisable(DEPTH_TEST)`
- **相关文件**：`ClientGame.java`

### 4. PauseMenu 状态泄漏
- **问题**：点击"返回主界面"时 `dispatchAction` 直接跳转，`menuVisible` 留在 true 状态，下次进游戏 PauseMenu 立即弹出显示在 InGameHud 上
- **修复**：所有按钮回调先调 `hide()`（`menuVisible = false` + 清子 actor），再执行动作
- **相关文件**：`PauseMenu.java`

### 5. 退回主界面世界状态泄漏
- **问题**：`dispatchAction("RETURN_TO_MAIN_MENU")` 只清了 `gui.runtime`，`ClientGame.runtime` 未清。开新游戏时旧世界仍在后台运行，新游戏读取旧数据
- **修复**：`renderPlaying()` 入口加 `gui.getRuntime() == null` 检查，同步停掉 `ClientGame.runtime`
- **相关文件**：`ClientGame.java`

## 问题与解决方案

### 问题1：暂停时 3D 场景深度泄漏到 UI
- **现象**：暂停菜单遮罩闪烁、按钮部分不可见
- **原因**：`renderSpaceScene()` 开启深度测试，`stage.draw()` 未关闭，UI 片元被 3D 深度值过滤
- **解决方案**：暂停时跳过整个 `renderSpaceScene()`；UI 绘制前 `glDisable(DEPTH_TEST)`
- **验证结果**：遮罩和按钮完美覆盖在静态 3D 背景上，无闪烁

### 问题2：暂停按钮点击触发多重动作
- **现象**：一次点击触发两个动作（如点"返回主界面"时先切换到 System View 再返回主菜单）
- **原因**：`renderGalaxyView()` 中的 `isButtonJustPressed(LEFT)` 在 `stage.act()` 之前检查，抢走鼠标事件
- **解决方案**：暂停时跳过 `renderSpaceScene()`，射线拾取的点击检测不再执行
- **验证结果**：暂停按钮点击只触发对应动作

### 问题3：返回主界面后旧世界残留
- **现象**：开新游戏仍显示旧世界数据
- **原因**：`gui.runtime` 被清但 `ClientGame.runtime` 未同步清理
- **解决方案**：`renderPlaying()` 入口同步检查 `gui.getRuntime()`
- **验证结果**：返回主界面后旧游戏彻底停止，新游戏正常创建新世界

## 技术要点

1. **渲染顺序与输入冲突**：自定义渲染（`renderPlaying` → `renderSpaceScene`）和 Scene2D UI（`stage.act/draw`）在同一帧内先后执行，自定义渲染中的输入检查会抢先于 Scene2D 处理。解决方案是按功能隔离——暂停时跳过自定义渲染。
2. **深度测试状态泄漏**：OpenGL 状态机模型中，开启的状态（深度测试、混合模式等）不会自动恢复。自定义渲染和 Scene2D UI 切换时需显式管理 GL 状态。
3. **双 runtime 指针同步**：`Gui.runtime` 和 `ClientGame.runtime` 分别持有游戏实例引用，`dispatchAction` 只清理 Gui 侧导致状态不一致。加同步检查统一清理路径。
