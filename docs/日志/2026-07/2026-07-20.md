### 4. 舰船移动指令未到 game 执行 BUG 修复
- **问题描述**: 用户反馈"舰船移动系统有问题，指令似乎没有到 game 执行"。右键设移动目标 + 左键确认后，舰船不移动。
- **根因诊断**:
  - 测试舰船生成（`StarAxisGameRuntime.java:232-250`）未设置 `ownerNationId`，导致 `ship.ownerNationId == null`
  - 客户端守卫（`ShipMoveController.java:154`）`if (shipSnap != null && shipSnap.ownerNationId != null)` 因 `ownerNationId` 为 null 直接跳过，**命令从未提交到 CommandBus**
  - 即使命令进入队列，`MoveShipHandler.java:31` 的 `if (!nationId.equals(ship.ownerNationId)) return;` 也会因 `nationId.equals(null)` 返回 false 而静默丢弃
  - 同时存在 NPE 风险：若 `nationId` 为 null，`nationId.equals(...)` 会抛 NPE
- **设计原则**（用户明确指示）: 鉴权与指令执行分离 -- 舰船有 owner 时校验发起者是否匹配；无 owner 时（无主舰船）任何指令直接执行
- **修复方案**（仅桌面路径，webnet 路径暂不动）:
  - `MoveShipHandler.java:31` 改为 `if (ship.ownerNationId != null && !ship.ownerNationId.equals(nationId)) return;` -- 短路保护 + 无主舰船直接执行
  - `ShipMoveController.java:154` 去掉 `shipSnap.ownerNationId != null` 守卫，允许 `ownerNationId` 为 null 传入命令
- **验证**: `gradlew :game:compileJava :client:compileJava :lwjgl3:compileJava` 编译通过，class 文件时间戳 9:51 确认新生成
- **相关文件**:

## 技术要点

- `GenPhase` 枚举模式：将散落进度比例与对应中文标签绑定，一处修改全局同步。用于加载进度条等"阶段-比例-标签"三元组场景。
- `SimulationClock.TICKS_PER_SECOND`：已有常量直接复用，避免 `% 20` 这种隐含"每秒 20 tick"假设。
- `TimeUnit` 优于裸除法：`TimeUnit.NANOSECONDS.toMillis()` 比 `/ 1_000_000L` 更具可读性。
- **鉴权与执行分离原则**：指令到达后先尝试执行，鉴权是"有 owner 且不匹配才拒绝"的负向校验，而非"必须匹配才允许"的正向校验。无主实体（`ownerNationId == null`）默认开放操作权限。写法：`if (owner != null && !owner.equals(actor)) reject;` -- 短路保护避免 NPE，且无主实体直接放行。
- **静默丢弃是反模式**：`MoveShipHandler` 原版的 `if (!nationId.equals(ship.ownerNationId)) return;` 既会因 null 比较失败而误拒，又没有日志输出，调试时只能靠堆栈推断。鉴权失败应明确拒绝或日志记录，禁止静默 return。

### 5. 客户端矢量UI测试场景 BUG 修复

- **问题描述**: 用户反馈"测试场景的UI BUG，滚动文本框无法滚动，文本输入框无法输入文本"。
- **测试场景入口**: `Gui.showVectorComponentsTestScreen()` → `JsonScreen` 加载 `assets/ui/gameui/vector-ui-test/test_screen.json`；事件分发走标准 libGDX Scene2D（`Stage` 作为 `InputProcessor`）。

#### BUG A: 文本输入框无法输入（`VectorTextField`）

- **根因**: `VectorTextField` 的 `InputListener` 只重写了 `touchDown`/`touchUp`，虽然 `touchUp` 里调了 `setKeyboardFocus` 让 `FocusListener` 把 `focused` 置 true，但 `handleKeyDown(int)` / `handleKeyTyped(char)` 是自定义方法，**没有任何地方调用它们**。Scene2D 的 `Stage` 分发键盘事件时调用的是 `InputListener.keyDown(InputEvent, int)` / `keyTyped(InputEvent, char)`，这两个方法没被重写，键盘事件被静默丢弃。
- **修复**: 在 `InputListener` 中重写 `keyDown` / `keyUp` / `keyTyped`，转发到 `handleKeyDown` / `handleKeyTyped`。`keyUp` 返回 `focused` 占用键盘焦点避免事件冒泡，但不影响 ESC 返回主菜单（ESC 用 `Gdx.input.isKeyJustPressed` 轮询，不依赖 `InputProcessor`）。
- **文件**: `ui/src/main/java/staraxis/ui/widgets/VectorTextField.java`

#### BUG B: 滚动文本框无法滚动（`VectorScrollPane`）

- **根因**: `updateLayout()` 中 content 高度计算错误。`test_screen.json` 的 `scroll_content` 是 `container`（Table），无 `fillParent`、无 `width/height`，初始 `getHeight() = 0`。原代码 `content.setSize(max(content.getWidth(), w), content.getHeight())` 把高度设为 0，`validate()` 不会改 Table 的 size；`getContentHeight()` 返回 `max(0, viewH) = viewH`，`clampScrollOffset()` 中 `contentH > viewH` 不成立 → `scrollYOffset` 被 clamp 回 0，滚轮滚动无效。
- **修复**: `updateLayout()` 改为取 `Layout.getPrefWidth()` / `getPrefHeight()`（validate 后反映子元素累加尺寸）作为 content 真实尺寸，再 `max` 视图尺寸。这样 `getContentHeight()` 返回真实内容高度，`clampScrollOffset()` 正常工作，滚轮滚动生效。
- **文件**: `ui/src/main/java/staraxis/ui/widgets/VectorScrollPane.java`

- **验证**: `./gradlew :ui:compileJava` 编译通过（EXIT=0）。`VectorScrollPane` 残留的未使用字段警告（`scrollX`/`scrollXOffset`/`contentWidth`/`contentHeight`/`lastKnownWidth`/`lastKnownHeight`/`getContentWidth`）为预先存在，非本次修改引入。
