## 架构决策记录

### 决策 1：WorldState 禁止外部访问
- **规则**：WorldState 只能由 game 模拟层读写。客户端、webnet、渲染器等外部模块不得以任何形式直接访问。
- **理由**：线程安全（HashMap resize 风险）+ 职责清晰（game 是唯一权威）
- **例外**：无。没拿到数据等 1 tick 或 20 tick，禁止回退。

### 决策 2：按频率划分双快照
- **高频**（RealTimeWorldState，每 tick）：时间元信息 + 动态实体（SHIP/STATION）
- **低频**（DailySettlementState，每 20 tick）：恒星基线 + 国家资产 + 玩家映射 + 预计算可见性 + 预计算情报

### 决策 3：外部访问唯一通道为 CommandBus
- webnet 与 game 的交互只能通过 `CommandBus.submit(cmd)` 进行
- 禁止直接调 game 内部方法读写 WorldState
- 存档加载/玩家出生等遗留直读直写需 Command 化改造

## 技术要点
- webnet 与 game 同进程内是 Java 方法调用，不是网络通信
- `EntitySnapshot` 不是纯粹的跨进程 DTO——桌面渲染器直接读双缓冲
- `RealTimeWorldState.getEntitiesByIdView()` 返回的是 Entity 原始引用，不是深拷贝——有可见性风险，标记为已知问题
- `DailySettlementStateBuffer` 需要从单缓冲 synchronized 升级为双缓冲 volatile swap
