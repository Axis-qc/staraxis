## 问题与解决方案

### 问题1：生成期行星位置不是当前轨道位置
- **现象描述**：行星 `posWorldGU` 可能仍为恒星中心，直接用它校验殖民距离会使真实轨道附近的殖民舰无法殖民。
- **原因分析**：System View 使用轨道参数实时解算行星位置，game 命令原先没有采用同一口径。
- **解决方案**：`ColonizePlanetHandler` 使用行星轨道参数和 `OrbitSolver` 计算当前位置；无有效轨道参数时保留手动位置回退。
- **验证结果**：真实轨道附近 100GU 可殖民，轨道位置外 1500GU 被拒绝。

### 问题2：G2 工业状态只做独立脚手架
- **现象描述**：库存、设施和运输模型存在，但殖民成功后不会自动形成生产链。
- **原因分析**：工业注册表尚未由殖民流程初始化。
- **解决方案**：殖民成功时幂等创建行星 `LocalInventory`、水采集设施、电解槽和临时初始能源；每日结算先采集再加工。
- **验证结果**：殖民测试覆盖库存/设施创建，同日日结算可产出氢气和氧气。

### 问题3：结算报告只在 `settleDay` 返回后丢失
- **现象描述**：`ProductionSettlementService.settleDay`（工业日结算服务）的返回报告未持久化，UI 无法读取最近结算结果。
- **原因分析**：`update`（游戏主循环）中结算原先在基线快照发布之后执行，报告若只存局部变量会被丢弃。
- **解决方案**：将日结算移到基线发布之前，`StarAxisGameRuntime` 用 `lastSettlementReport` 保存报告并按行星拆分写入同 tick 的 `PlanetSurfaceDailySnapshot`；无相关条目时返回 null，避免新殖民地继承旧报告。
- **验证结果**：同 tick 结算快照和新殖民地无旧报告污染测试通过。

### 问题4：行星窗口空数据时尺寸收缩且信息层次不足
- **现象描述**：行星窗口宽高由当前分页文本行数驱动；没有工业或物流数据时只剩一行空态，窗口明显缩小，所有字段也以同一纯文本层级显示。
- **原因分析**：`PlanetInfoLayout.compute` 按字段宽度和行数计算窗口尺寸，`PlanetInfoPanel.applyLayout` 在每次切页/重建时重新应用该尺寸；分组标题只是普通文本。
- **解决方案**：固定内容区尺寸，新增 `FieldEntry.section` 分组标记；面板使用分隔线、key/value 层级、状态色和空态卡片渲染。
- **验证结果**：短页与长页尺寸断言一致，布局/组装及全部 UI 测试通过。

### 问题5：镜头朝向改变导致行星向阳面/背光面明暗反转
- **现象描述**：相机只改变朝向时，同一行星地表的向阳面变暗、背光面变亮，明暗效果表现出镜头相关性。
- **原因分析**：行星沿用通用 `DefaultShader`（默认着色器）和共享方向光环境，缺少独立的行星世界空间光照输入，无法对行星光照坐标空间形成明确隔离。
- **解决方案**：新增 `PlanetLightAttribute` 和 `PlanetShader`，将恒星到行星的世界空间传播方向、光色和世界空间法线直接送入行星着色器；行星渲染不再提交共享 `Environment`。
- **解决方案补充**：为 `PlanetLightAttribute.color` 使用匹配的 GLSL `vec4` uniform，避免运行时光色写入失败；同时保留运行时属性兜底和共享环境光照回退。
- **验证结果**：行星 vertex/fragment shader 编译通过；待进入 System View 旋转镜头进行人工视觉确认。

### 问题6：需要确认行星光照 uniform 是否真正写入
- **诊断方案**：`SystemViewRenderer` 记录 `PlanetLightAttribute` 是否存在及方向/光色；`PlanetShader` 记录 `u_planetLightDirection` 和 `u_planetLightColor` 的 `written` 结果。
- **当前状态**：已移除兜底逻辑，等待 System View 实际日志后再修复具体断点。

### 问题7：日志被写到项目目录外的 gamedata
- **现象描述**：logback 的日志出现在 `G:\games\gamedata\logs`，而不是项目内 `gamedata/logs`。
- **原因分析**：`logback.xml` 使用 `${user.dir}/../gamedata/logs`，开发运行时 `user.dir` 为项目根目录，`../` 导致日志逃逸到上级目录；与 `GameLog`/`WebNetLog` 等 CWD 相对约定不一致。
- **解决方案**：改为 `${user.dir}/gamedata/logs`，与项目其他日志类保持一致。

### 8. F3 调试面板新增「模型法向」开关
- 新增 `NormalDebugRenderer`（法向线段可视化）：从 `ModelInstance` 顶点缓冲读取位置与法线，沿法线方向画亮青色线段，线段固定长度 20 GU（不随模型缩放）。
- `SystemViewRenderer` 增加 `setDebugNormalsEnabled`/`isDebugNormalsEnabled`，开启后对恒星、行星（高/低 LOD）、舰船渲染法向线段；`StarEaterShipRenderer` 暴露 `getInstances()` 供法向渲染遍历。
- `UiDebug`（F3 面板）新增「模型法向」按钮，点击切换并同步 `SystemViewRenderer` 开关；`debug_panel.json` 增加按钮行并将面板高度调整为 320。
- `ClientGame` 将 `systemViewRenderer` 注入 `UiDebug`。

## 技术要点

- `IndustryRegistry` 使用确定性插入顺序，避免多设施/多运输争抢资源时依赖 `HashMap` 迭代顺序。
- `CargoTransfer` 出发前校验源和目标库存，抵达时容量不足则保持在途。
- 第一阶段能源通过 `ColonialStartupKit.INITIAL_ENERGY` 明确注入库存，不允许配方凭空生成能源。
- G2.7 工业快照归属口径统一为库存 ID：设施按 `inventoryId`、运输按源/目标 `inventoryId`、报告结果按设施/运输所属库存筛选，保证与 `LocalInventory.ownerEntityId` 一致。
- 快照 Map/List 统一经 `deepCopyAmounts` / `deepCopyList` 包装为不可变视图，双缓冲下 UI 不可见 game 可变对象。
- 行星 UI 以 `planetEntityId` 作为唯一上下文键，四分页切换和行星 A/B 切换均从快照重新组装，不持有 game 权威对象。
- G1.1 命令栏：`EntityInfoAssembler` 为舰船组装"移动"action、为宜居无主行星组装"殖民"action；`InGameHudScreen` 追踪 `lastSelectedShipId`（选中行星时不清除），殖民按钮使用该值判断可用性并提交 `ColonizePlanetCommand`。
- G1.2 命令反馈：`CommandBus` 在 `executeCommand` 后记录 `CommandResult`（成功/失败/错误码/tick），有界队列 128 条；UI 通过 `StarAxisGameRuntime.pollCommandResults()` 只读消费，不直接访问 `CommandBus`；`ToastWidget` 右上角显示 3 秒通知，`CommandErrorMessages` 将英文错误码映射为中文。
- 行星窗口固定内容区为 600x440，空态卡片和滚动内容共用同一视口；分组标题使用 `FieldEntry.section` 标记，避免依赖装饰性连字符判断。
- 行星光照方向统一使用世界空间的恒星到行星向量；PlanetShader 只用相机矩阵做投影，不使用相机方向计算明暗。
