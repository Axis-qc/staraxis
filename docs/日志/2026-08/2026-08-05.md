## 问题与解决方案

### 问题1：SelectionService 模块归属导致编译失败
- **现象描述**：`SelectionService` 初建于 client 模块，`InGameHudScreen`（ui 模块）引用报「找不到符号」；另 `getDailySettlementStateReadonly()` 方法不存在
- **原因分析**：模块依赖方向为 client → ui → game，ui 模块无法引用 client 的类；日结算快照实际通过 `DailySettlementStateBuffer.getActive()` 获取
- **解决方案**：`SelectionService` 移至 `ui` 模块（与 `UiWindowManager` 同级，client 反向引用）；改用 `rt.getDailySettlementStateBufferForReadonly().getActive()`
- **验证结果**：全模块编译通过

### 问题2：PlanetDetails 构造参数兼容
- **现象描述**：`PlanetDetails` 加新字段后需要 3 处构造点同步修改，且存在旧构造函数被其他调用点使用
- **原因分析**：字段为 `final`，新增字段必须走构造器
- **解决方案**：保留旧 13 参构造函数委托到新 16 参构造函数（新字段传默认值 0/null），`StarAxisGameRuntime` 3 处改用新构造并传真实值；`webnet` 直接复用 game 的 `EntitySnapshot`（无独立 DTO），Jackson 枚举序列化为字符串无兼容问题

### 技术要点
- 单一归属原则落地：3D 层只调 `pointerService.isMouseOverUi()`，UI 区域集中注册，Y 翻转只此一处
- 模态语义保留：`UiWindowManager` blocker 含"任意模态窗口打开全屏拦截"；`closeModalIfClickedOutside` 仍由 ClientGame 左键轮询先行调用（点击模态外关闭窗口）
- 动态注册防失效：所有 blocker 判定含 `getStage() == null` 检查，切屏（`stage.clear()`）后守卫自动失效，无需手动注销
- SELECTING_HOME 弹窗点击行为变化：原弹窗打开时点击其他恒星无效，现可切换到新恒星（重新 show 弹窗）——更符合直觉，非回归
