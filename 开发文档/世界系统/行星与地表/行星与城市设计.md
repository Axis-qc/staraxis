# 行星与城市设计

> 目标：定义以“宏观城市建设”为核心的行星玩法，并引入地表划分、城市专精、文明形态变体城市、星球首都与两级财政等机制。

## 1. 核心概念

- **取消网格**：行星不做微观网格管理。
- **聚焦城市**：行星发展围绕“城市”这一宏观单位。
- **地表划分驱动**：行星地表由若干“地表区域”组成（大陆/海洋等），城市只能在地表区域的“可开发空间”内建设。
- **城市专精**：城市可指定专精方向，显著倾向某类产出。
- **文明形态变体**：财政系统明确分为三个独立计算模型：通用税收模型 / 蜂巢模型 / 机械模型，彼此不耦合、不互相干扰（见第 6 节）。
- **星球首都与财政**：每个行星有一个首都城市，管理星球财政账户，并按政策向国家账户上缴。

## 2. 地表划分（Surface Partition）

> 术语说明：本文档不再使用“地表特征”，统一改称 **地表划分**；其中的基本单位称为 **地表区域**。

每个行星由多个随机命名的地表区域组成，它们共同构成行星 100% 的地表空间。

### 2.1 地表区域（大陆 / 海洋）

- **类型**：大陆（Continent）、海洋（Ocean）。
- **属性**：
  - `name`：随机生成名称（例如“希望大陆”“宁静之海”）。
  - `surfacePercentage`：该区域占行星地表总面积的百分比。

**示例（总计 100%）**：
- `宁静之海`（海洋）：16%
- `风暴洋`（海洋）：12%
- `小型内海`（海洋）：8%
- `希望大陆`（大陆）：32%
- `荣耀大陆`（大陆）：24%
- `遗忘之地`（大陆）：8%

### 2.2 区域内部的地貌构成（次级地貌）

每个地表区域内部还可细分为若干“次级地貌”，用于影响产出与可开发空间。

- **类型**：山脉（Mountains）、平原（Plains）、浅海（Shallow Sea）、深海（Deep Sea）等。
- **属性**：
  - `percentageOfRegion`：该地貌占其所属地表区域面积的百分比。

**示例**：
- `宁静之海`（16%）内部：`浅海` 10%（占海域），其余为深水。
- `希望大陆`（32%）内部：`山脉` 12%（占大陆），其余为平原/丘陵等。

### 2.3 可开发空间（科技限制）

- **概念**：玩家在某个地表区域上可用于建设城市的最大可用空间。
- **限制来源**：科技水平/政策/文明形态共同决定。

**示例**：
- `宁静之海` 总计 16%，但当前科技只允许开发其中 2%（指“海洋区域自身的 2%”），用于建立海上城市。

> 注：是否将“可开发空间”理解为“可建立城市的总规模上限”或“可建立城市数量上限”，由实现阶段结合数值设计决定；本文档要求口径一致。

## 3. 城市设计

### 3.1 建立城市

- 玩家可在地表区域的“可开发空间”内建立城市。
- 一个行星可以有多个城市。
- 行星上建立的**第一个城市**自动成为该行星的**星球首都城市**（见第 5 节）。

### 3.2 城市成长阶段（统一命名）

> 说明：阶段名称用于 UI 展示与设计沟通；内部数值可用 `cityTier` 或 `cityStage` 表示。

推荐阶段命名（从小到大）：

1. **前哨殖民地**（最小形态）
2. **定居点**
3. **城镇**
4. **城市**
5. **巨型都市**（最高形态）

### 3.3 城市功能（住房/岗位/产出）

- **住房与岗位**：城市阶段越高，提供的 `housing` 与 `jobSlots` 越多。
- **岗位填充**：人口自动填充岗位。
- **消耗与产出**：岗位消耗原料并产出资源。产出类型与效率受以下因素影响：
  - 城市专精
  - 城市阶段
  - 城市所在地表区域的类型与次级地貌（例如山脉更适合采矿）

### 3.4 城市专精（示例）

城市专精决定“重点产出”，并可影响岗位结构。

- **科研城市**：重点产出科研点数
- **采矿城市**：重点产出矿物/稀有矿
- **工业城市**：重点产出工业品/合金
- **行政都市**：重点产出行政效率/治理相关收益（并可能影响税收）
- **农业城市**：重点产出食物

> 注：是否允许专精重置、重置成本、以及专精对其他产出的减益幅度，后续在数值文档中明确。

## 4. 星球开发规模与地表灯光

### 4.1 星球大小加成（Planet Size Modifier）

- **概念**：体现“同等城市规模在不同大小星球上代表的开发程度不同”。
- **规则**：星球越大，`planetSizeModifier` 越小。

**示例**：
- 小星球：`planetSizeModifier = 1.0`
- 中等星球：`planetSizeModifier = 0.5`
- 大星球：`planetSizeModifier = 0.1`

### 4.2 总开发规模计算

`totalDevelopmentScale = Σ (city_i.scale * planetSizeModifier)`

**示例**：
- 城市规模 10：小星球贡献 `10 * 1.0 = 10`
- 城市规模 10：大星球贡献 `10 * 0.1 = 1`

### 4.3 地表灯光表现

- 行星纹理上叠加一层“地表灯光”。
- 灯光的亮度/范围与 `totalDevelopmentScale`（总开发规模）正相关。

## 5. 星球首都与两级财政

### 5.1 星球首都城市（Planetary Capital City）

- 每个星球有且仅有一个首都城市。
- 默认：星球上建立的第一个城市即为首都城市（也可在后续允许迁都，需另行定义成本与规则）。

### 5.2 星球财政账户 → 国家财政账户（上缴）

- **星球财政账户**：
  - 星球进出口盈余、税收等收入，优先结算到星球财政账户。
- **国家财政账户**：
  - 按政策上缴固定比例进入国家账户。

> 具体结算流水线与示例见：`经济系统/结算/经济系统口径.md` 与 `经济系统/结算/经济日结算示例.md`。

## 6. 文明形态与财政三模型（隔离）

为防止耦合与互相干扰，文明形态相关的财政系统明确分为以下 **三个独立计算模型**：

1. **通用税收模型**：`税收 (taxRevenue)` + `贸易盈余 (tradeSurplus)`
2. **蜂巢模型**：`巢群供给/贡赋 (hiveTithe)` + `贸易盈余 (tradeSurplus)`（若蜂巢允许对外贸易）
3. **机械模型**：`产能分配 (productionAllocation)` + `贸易盈余 (tradeSurplus)`（若机械允许对外贸易）

约束：
- 三个模型在计算上 **互不引用、互不转换、互不混合**。
- 同一局游戏、同一个国家/势力，只能选择其中 **一个** 模型作为财政结算口径。

### 6.1 蜂巢文明（Hive）城市

- **城市形态**：建议称为“孵化巢群/巢群节点”等（UI 名称）。
- **人口口径**：蜂巢使用 **子个体数量**（个体单位）作为主要计量与展示口径。
- **岗位逻辑**：以“子个体岗位”与“生物质维护”为核心；子个体增长与岗位填充更强耦合。
- **产出倾向**：偏向生物质、繁育、特化生物工坊等。
- **财政口径**：
  - 保留星球财政账户概念。
  - 将“税收”口径替换为 **巢群供给/贡赋**。

### 6.2 机械智能（Machine Intelligence）城市

- **城市形态**：建议称为“算力节点/机械聚落/工业节点”等（UI 名称）。
- **人口口径**：机械智能使用 **单元数量**（Unit Count）作为主要计量与展示口径。
- **岗位逻辑**：以“算力/维护能耗/装配线”作为关键约束；单元数量与算力容量共同决定可用岗位。
- **产出倾向**：偏向工业、算力、能源与维护效率。
- **财政口径**：
  - 保留星球财政账户概念。
  - 将“税收”口径替换为 **产能分配/能耗预算**。
