# 行星与城市设计

> 目标：定义以“宏观城市建设”为核心的行星玩法，并引入地表划分、城市专精、文明形态变体城市、星球首都与两级财政、国家域订单市场与跨星球履约等机制。

## 1. 核心概念

- **取消网格**：行星不做微观网格管理。
- **聚焦城市**：行星发展围绕“城市”这一宏观单位。
- **地表划分驱动**：行星地表由若干“地表区域”组成（大陆/海洋等），城市只能在地表区域的“可开发空间”内建设。
- **城市专精**：玩家仅指定城市主要专精方向，这决定城市生产力分配的主要类别。
- **生产力模型**：城市不再有“岗位”，生产力由劳动力比例与效率加成计算，并叠加自然资源直接提供的生产力。
- **国家域订单市场**：A 星球发布订单进入国家订单市场；B/C 星球基于成本与运费选择接单；接单星球分配给其城市生产；通过运输舰交付回需求星球。
- **文明形态变体**：财政系统明确分为三个独立计算模型：通用税收模型 / 蜂巢模型 / 机械模型，彼此不耦合、不互相干扰（见第 11 节）。
- **星球首都与财政**：每个行星有一个首都城市，管理星球财政账户，并按政策向国家账户上缴。

## 2. 地表划分（Surface Partition）

> 术语说明：本文档不再使用“地表特征”，统一改称 **地表划分**；其中的基本单位称为 **地表区域**。

每个行星由多个随机命名的地表区域组成，它们共同构成行星 100% 的地表空间。

### 2.1 地表区域（大陆 / 海洋）

- **类型**：大陆（Continent）、海洋（Ocean）。
- **属性**：
  - `name`（区域名：随机生成名称，例如“希望大陆”）
  - `surfacePercentage`（区域占比：该区域占行星地表总面积的百分比）

**示例（总计 100%）**：
- `宁静之海`（海洋）：16%
- `风暴洋`（海洋）：12%
- `小型内海`（海洋）：8%
- `希望大陆`（大陆）：32%
- `荣耀大陆`（大陆）：24%
- `遗忘之地`（大陆）：8%

### 2.2 区域内部的地貌构成（次级地貌）

每个地表区域内部还可细分为若干“次级地貌”，用于影响资源发现倾向。

- **类型**：山脉（Mountains）、平原（Plains）、浅海（Shallow Sea）、深海（Deep Sea）等。
- **属性**：
  - `percentageOfRegion`（地貌占比：该地貌占其所属地表区域面积的百分比）

**示例**：
- `宁静之海`（16%）内部：`浅海` 10%（占海域），其余为深水。
- `希望大陆`（32%）内部：`山脉` 12%（占大陆），其余为平原/丘陵等。

### 2.3 可开发空间（科技限制）

- **概念**：玩家在某个地表区域上可用于建设城市的最大可用空间。
- **限制来源**：科技水平/政策/文明形态共同决定。

**示例**：
- `宁静之海` 总计 16%，但当前科技只允许开发其中 2%（指“海洋区域自身的 2%”），用于建立海上城市。

> 注：是否将“可开发空间”理解为“可建立城市的总规模上限”或“可建立城市数量上限”，由实现阶段结合数值设计决定；本文档要求口径一致。

## 3. 城市设计

### 3.1 建立城市

- 玩家可在地表区域的“可开发空间”内建立城市。
- 一个行星可以有多个城市。
- 行星上建立的**第一个城市**自动成为该行星的**星球首都城市**（见第 10 节）。

### 3.2 城市成长阶段（统一命名）

> 说明：阶段名称用于 UI 展示与设计沟通；内部数值可用 `cityStage`（城市阶段）表示。

推荐阶段命名（从小到大）：

1. **前哨殖民地**（最小形态）
2. **定居点**
3. **城镇**
4. **城市**
5. **巨型都市**（最高形态）

### 3.3 城市功能（住房/生产力：全自动）

- **住房**：城市阶段越高，提供的 `housing`（住房）越多，作为人口容量 `populationCap` 的软约束，主要影响吸引力。
- **生产力**：城市不再有“岗位”，而是将劳动力与自然资源转换为可分配的 `productionPower`（生产力），用于履约订单。
- **玩家操作**：玩家仅需设置 `citySpecializationId`（城市专精），以指导生产力的分配方向。

### 3.4 城市专精（示例）

城市专精决定城市总生产力的**分配倾向**。

- **科研专精**：将大部分生产力分配为“科研生产力”。
- **采矿专精**：将大部分生产力分配为“采矿生产力”。
- **工业专精**：将大部分生产力分配为“工业生产力”。
- **农业专精**：将大部分生产力分配为“农业生产力”。
- **行政专精**：将大部分生产力分配为“行政生产力”，影响治理/财政等。
- **军工专精**：将大部分生产力分配为“军工生产力”，用于制造舰船装备、舰船补给、军用部件等。

> 注：专精重置应有成本。

### 3.5 专精生产力与通用生产力（90% / 10% 规则）

为防止因供给短缺导致星球经济崩溃，城市生产力在分配上采用统一口径：

- **90%** 的 `baseProductionPower` 转换为该城市专精对应的 **专精生产力**（例如 `miningPower / industryPower / farmingPower / researchPower / militaryPower`）。
- **10%** 的 `baseProductionPower` 保留为 **通用生产力**（`generalPower`）。

通用生产力用途：
- 当某资源出现短缺（例如食物、能源、基础民用品），星球可以用 `generalPower` 生成紧急订单并履约，以避免“供给断裂 → 吸引力崩溃 → 人口流失”的连锁反应。

> 注：该 90/10 是默认口径，后续可由政策/文明形态/科技调整。

## 4. 城市基础设定（人口 → 生产力）

> 目标：明确“城市规模增长 → 人口容量增长 → 劳动力 → 生产力增长 → 订单履约”的全自动闭环。

### 4.1 城市规模（cityScale）与人口容量

- `cityScale`（城市规模：整数档位，表示城市宏观规模）
- `populationCap`（人口容量：城市可容纳人口上限）

建议口径：
- `populationCap = cityScale * 10_000`（每 1 规模提供 1 万人口容量）

> 示例：`cityScale = 5` → `populationCap = 50_000`。

### 4.2 生产力来源

城市生产力由两部分构成：**劳动力生产力** 和 **自然资源生产力**。

#### 4.2.1 劳动力生产力

- `laborParticipationRate`（劳动力比例：0~1，可工作人口占总人口比例，默认 `0.65`）
- `laborForce = floor(population * laborParticipationRate)`（劳动力）
- `baseProductionPower = laborForce * basePowerPerLabor`（基础生产力，`basePowerPerLabor` 为平衡系数）

#### 4.2.2 自然资源生产力

- 已开发的 `resourceSites`（自然资源点）直接提供固定值的、特定类别的生产力。
- `naturalResourcePowerByCategory[cat] = Σ (power from all resource sites of category 'cat')`

**示例**：
- 一个“富饶铁矿脉”资源点，在被城市开发后，直接为该城市提供 `+500` 采矿生产力。

#### 4.2.3 分配与效率

- `specializationId` 决定 `baseProductionPower` 的分配：
  - `specializedPowerByCategory`（专精生产力，默认占 `90%`）
  - `generalPower`（通用生产力，默认占 `10%`）
- `efficiencyBonusByCategory`（效率加成）来源于科技、政策等。

建议口径：
- `specializedPowerByCategory[cat] = baseProductionPower * 0.9 * allocation[cat]`
- `generalPower = baseProductionPower * 0.1`
- `totalPowerByCategory[cat] = (specializedPowerByCategory[cat] + naturalResourcePowerByCategory[cat]) * efficiencyBonusByCategory[cat]`

> 注：`generalPower` 可被“转换/委托”为任何类别的订单履约能力，但其单位成本更高（体现临时转产的低效率）。

## 5. 国家域订单市场（跨星球履约）

> 目标：将订单从“星球内部消耗与产出”升级为“国家级订单市场”，允许跨星球以更低成本履约，并通过运输舰交付。

### 5.1 结算节奏

- 权威落账（强一致）：以 `simulationDay`（模拟日）进行日结算。

### 5.2 需求 → 订单发布

- **人口需求**：
  - `demandPerResource = population * consumptionPerCapita[resource]`
  - `consumptionPerCapita` 是每单位人口每日消耗各类资源的系数表。
- 当需求星球 A 的 `planetStorage[resource]` 低于 `demandPerResource * bufferDays`（例如 10 天缓冲量）时，A 星球自动生成订单。

### 5.3 国家订单市场（National Order Market）

- `nationalOrders[]`（国家域订单市场中的订单池）

订单发布：
- A 星球发布订单 → 进入 `nationalOrders[]`。

订单接单：
- B/C 星球会评估是否接单。
- 评估因素（建议）：
  - **履约成本**：由对应类别生产力的有效供给（`totalPowerByCategory[cat]`）与效率决定
  - **运输成本**：从 B/C 到 A 的运费与时间
  - **机会成本**：接单会占用本地生产力，可能影响本地需求

> 口径要求：订单最终应由“综合成本最低（或报价最低）”的星球接收。

### 5.4 接单星球分配到城市生产

- B 星球接单后，订单进入 B 的 `acceptedOrders[]`。
- B 星球将订单拆分/分配给本星球城市：
  - `cityAssignedOrders[]`

### 5.5 订单履约（消耗生产力 → 产出资源）

- 城市在日结算中消耗生产力履约：
  - `maxUnitsByPower = floor(powerAvailable / powerCostPerUnit)`
  - `fulfilledUnits = min(remainingQuantity, maxUnitsByPower)`
  - `powerConsumed = fulfilledUnits * powerCostPerUnit`
  - `resourceProduced = fulfilledUnits`

履约产物：
- 产物进入接单星球 B 的 `planetStorage`（或临时 `exportStagingStorage`）。

### 5.6 运输交付（运输舰）

- B 星球创建运输任务：
  - `shipment { fromPlanetId, toPlanetId, resourceId, quantity, etaDay, transportCost }`
- 运输舰把产物送达 A 星球。

到货结算：
- 在 `etaDay`，资源从 B 扣减并计入 A 的 `planetStorage`。
- 资金结算：A 支付给 B（支付来源优先从 A 星球财政账户结算，或走国家账户，具体见经济系统口径）。

## 6. 城市资源发现（能力增强）

### 6.1 资源发现

- 城市在满足任一条件时触发资源发现判定：
  - `cityStage`（城市阶段）提升
  - `population`（人口）跨越阈值
  - 区域科技解锁 `developableSpace`（可开发空间）提升

- 可发现类型（示例）：矿脉、农田、渔业、森林、景观等。

### 6.2 自动开发

- 城市会自动开发其范围内的资源点。
- 开发后的资源点直接提供**自然资源生产力**（见 4.2.2 节）。

### 6.3 景观效果

- `landmark`（自然景观）不提供生产力，但提供 `attractivenessBonus`（吸引力加成）。

## 7. 城市吸引力与人口迁移

### 7.1 吸引力 `attractiveness` 公式（建议口径）

`attractiveness = (housingScore * w1 + supplyScore * w2 + landmarkBonus) * policyModifier`

- `housingScore`（住房充足度）：`min(housing / population, 1.0)`
- `supplyScore`（民生供给充足度）：根据民生订单履约率/到货延迟计算（0~1）。例如食物订单长期缺口或运输频繁延误，则 `supplyScore` 下降。
- `landmarkBonus`（景观加成）：来自景观建筑的固定加成。
- `policyModifier`（政策/税负修正）：高税率降低吸引力。
- `w1, w2`（权重）：可调参数，例如 `w1=0.6, w2=0.4`。

### 7.2 人口增长与迁移

- 按 `simulationDay`（模拟日）结算。
- `populationGrowth = baseGrowthRate * attractiveness`
- 迁移：从低吸引力城市向高吸引力城市迁移，速率受吸引力差值、距离等影响。

## 9. 星球开发规模与地表灯光

### 9.1 星球大小加成（Planet Size Modifier）

- **概念**：体现“同等城市规模在不同大小星球上代表的开发程度不同”。
- **规则**：星球越大，`planetSizeModifier`（星球大小加成）越小。

### 9.2 总开发规模计算

`totalDevelopmentScale = Σ (city_i.scale * planetSizeModifier)`

### 9.3 地表灯光表现

- 行星纹理上叠加一层“地表灯光”。
- 灯光的亮度/范围与 `totalDevelopmentScale`（总开发规模）正相关。

## 10. 星球首都与两级财政

### 10.1 星球首都城市（Planetary Capital City）

- 每个星球有且仅有一个首都城市。
- 默认：星球上建立的第一个城市即为首都城市。

### 10.2 星球财政账户 → 国家财政账户（上缴）

- **星球财政账户**：星球进出口盈余、税收等收入，优先结算到此账户。
- **国家财政账户**：按政策上缴固定比例进入国家账户。

> 具体结算流水线见：`经济系统/结算/经济系统口径.md`。

## 11. 文明形态与财政三模型（隔离）

为防止耦合与互相干扰，文明形态相关的财政系统明确分为以下 **三个独立计算模型**：

1. **通用税收模型**：`税收 (taxRevenue)` + `贸易盈余 (tradeSurplus)`
2. **蜂巢模型**：`巢群供给/贡赋 (hiveTithe)` + `贸易盈余 (tradeSurplus)`（若蜂巢允许对外贸易）
3. **机械模型**：`产能分配 (productionAllocation)` + `贸易盈余 (tradeSurplus)`（若机械允许对外贸易）

约束：三个模型在计算上互不引用、互不转换、互不混合。

### 11.1 蜂巢文明（Hive）城市

- **城市形态**：建议称为“孵化巢群/巢群节点”等（UI 名称）。
- **人口口径**：蜂巢使用 **子个体数量**（个体单位）作为主要计量与展示口径。
- **生产力逻辑**：子个体直接提供生产力，与生物质维护强耦合。
- **产出倾向**：偏向生物质、繁育、特化生物工坊等。
- **财政口径**：
  - 保留星球财政账户概念。
  - 将“税收”口径替换为 **巢群供给/贡赋**。

### 11.2 机械智能（Machine Intelligence）城市

- **城市形态**：建议称为“算力节点/机械聚落/工业节点”等（UI 名称）。
- **人口口径**：机械智能使用 **单元数量**（Unit Count）作为主要计量与展示口径。
- **生产力逻辑**：以“算力/维护能耗”作为关键约束；单元数量与算力容量共同决定可用生产力。
- **产出倾向**：偏向工业、算力、能源与维护效率。
- **财政口径**：
  - 保留星球财政账户概念。
  - 将“税收”口径替换为 **产能分配/能耗预算**。
