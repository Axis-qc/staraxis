# 行星与城市设计

> 目标：定义以“宏观城市建设”为核心的行星玩法，并引入地表划分、城市专精、文明形态变体城市、星球首都与两级财政等机制。

## 1. 核心概念

- **取消网格**：行星不做微观网格管理。
- **聚焦城市**：行星发展围绕“城市”这一宏观单位。
- **地表划分驱动**：行星地表由若干“地表区域”组成（大陆/海洋等），城市只能在地表区域的“可开发空间”内建设。
- **城市专精**：玩家仅指定城市主要专精方向（专精：城市发展的宏观倾向），其余建设与生产逻辑全自动。
- **文明形态变体**：财政系统明确分为三个独立计算模型：通用税收模型 / 蜂巢模型 / 机械模型，彼此不耦合、不互相干扰（见第 11 节）。
- **星球首都与财政**：每个行星有一个首都城市，管理星球财政账户，并按政策向国家账户上缴。

## 2. 地表划分（Surface Partition）

> 术语说明：本文档不再使用“地表特征”，统一改称 **地表划分**；其中的基本单位称为 **地表区域**。

每个行星由多个随机命名的地表区域组成，它们共同构成行星 100% 的地表空间。

### 2.1 地表区域（大陆 / 海洋）

- **类型**：大陆（Continent）、海洋（Ocean）。
- **属性**：
  - `name`（区域名：随机生成名称，例如“希望大陆”）
  - `surfacePercentage`（区域占比：该区域占行星地表总面积的百分比）

**示例（总计 100%）**：
- `宁静之海`（海洋）：16%
- `风暴洋`（海洋）：12%
- `小型内海`（海洋）：8%
- `希望大陆`（大陆）：32%
- `荣耀大陆`（大陆）：24%
- `遗忘之地`（大陆）：8%

### 2.2 区域内部的地貌构成（次级地貌）

每个地表区域内部还可细分为若干“次级地貌”，用于影响资源发现倾向与可开发空间。

- **类型**：山脉（Mountains）、平原（Plains）、浅海（Shallow Sea）、深海（Deep Sea）等。
- **属性**：
  - `percentageOfRegion`（地貌占比：该地貌占其所属地表区域面积的百分比）

**示例**：
- `宁静之海`（16%）内部：`浅海` 10%（占海域），其余为深水。
- `希望大陆`（32%）内部：`山脉` 12%（占大陆），其余为平原/丘陵等。

### 2.3 可开发空间（科技限制）

- **概念**：玩家在某个地表区域上可用于建设城市的最大可用空间。
- **限制来源**：科技水平/政策/文明形态共同决定。

**示例**：
- `宁静之海` 总计 16%，但当前科技只允许开发其中 2%（指“海洋区域自身的 2%”），用于建立海上城市。

> 注：是否将“可开发空间”理解为“可建立城市的总规模上限”或“可建立城市数量上限”，由实现阶段结合数值设计决定；本文档要求口径一致。

## 3. 城市设计

### 3.1 建立城市

- 玩家可在地表区域的“可开发空间”内建立城市。
- 一个行星可以有多个城市。
- 行星上建立的**第一个城市**自动成为该行星的**星球首都城市**（见第 10 节）。

### 3.2 城市成长阶段（统一命名）

> 说明：阶段名称用于 UI 展示与设计沟通；内部数值可用 `cityStage`（城市阶段）表示。

推荐阶段命名（从小到大）：

1. **前哨殖民地**（最小形态）
2. **定居点**
3. **城镇**
4. **城市**
5. **巨型都市**（最高形态）

### 3.3 城市功能（住房/岗位/产出：全自动）

- **住房与岗位**：城市阶段越高，提供的 `housing`（住房）与 `jobSlots`（岗位槽）越多。
- **岗位填充**：人口并非全部可工作；使用 `laborParticipationRate`（劳动力比例）确定可工作人口。
- **产出与消耗**：以“资源点 + 城市建筑”按 `simulationDay`（模拟日）日结算。
- **玩家操作**：玩家仅需设置 `citySpecializationId`（城市专精），不需要手动建造。

### 3.4 城市专精（示例）

城市专精决定城市优先开发的资源与岗位结构。

- **科研城市**：优先科研岗位与科研点产出
- **采矿城市**：优先开发矿脉、提升矿业岗位与矿物产出
- **工业城市**：优先工业岗位与中间品/终端品产出
- **行政都市**：优先治理/行政相关收益（并可能影响税收）
- **农业城市**：优先开发农业资源并产出食物

> 注：专精重置成本、以及专精对其他产出的权重影响，后续在数值设定中明确。

## 4. 城市基础设定（玩家只选专精，系统全自动）

> 目标：明确“城市规模增长 → 人口容量增长 → 岗位增长 → 自动建设与资源开发”的全自动闭环。

### 4.1 城市规模（cityScale）与人口容量

- `cityScale`（城市规模：整数档位，表示城市宏观规模）
- `populationCap`（人口容量：城市可容纳人口上限）

建议口径：
- `populationCap = cityScale * 10_000`（每 1 规模提供 1 万人口容量）

> 示例：`cityScale = 5` → `populationCap = 50_000`。

### 4.2 岗位来源（jobs）

岗位来源分两类：

- `governmentJobs`（政府岗位：由城市规模、政策曲线与科技决定）
- `buildingJobs`（城市建筑岗位：由城市建筑提供）

### 4.3 劳动力比例（劳动力参与率）

- `laborParticipationRate`（劳动力比例：0~1，可工作人口占总人口比例）
- `laborForce = floor(population * laborParticipationRate)`（劳动力：可工作的实际人口数量）

推荐默认：
- 通用文明：`laborParticipationRate = 0.65`

> 注：该机制替代复杂的“赡养人口”系统，保留人口结构约束但不引入年龄/家庭细分。

### 4.4 岗位填充与产出缩放

- `totalJobs = governmentJobs + Σ(buildingJobs)`
- `filledJobs = min(laborForce, totalJobs)`
- `jobFillRate = filledJobs / totalJobs`

## 5. 星球生产逻辑（按日结算，简化掉生产线）

> 目标：用“资源点 → 自动建造城市建筑 → 提供岗位 → 每日产出”的模型，取代生产线。

### 5.1 结算节奏

- 权威落账（强一致）：以 `simulationDay`（模拟日）进行日结算。

### 5.2 资源点与城市建筑

- `resourceSites[]`（资源点列表：城市可开发的资源/景观集合）
- `buildings[]`（城市建筑列表：自动建造的产出/功能性建筑）

口径：
- 发现 `resourceSite`（资源点）后，城市 AI 自动建造对应的 `building`（城市建筑）。
- 示例：`ironVein`（铁矿脉）→ `miningOutpost`（采矿站点）；`farmLand`（肥沃土壤）→ `farmland`（农田）；`ranch`（养殖资源）→ `ranchFacility`（养殖业设施）。

每个 `building`（城市建筑）提供：
- `buildingJobs`（岗位数）
- `baseOutputPerDay`（基础日产出）
- `jobEfficiency`（岗位效率：受科技影响）

### 5.3 岗位效率（科技进步）

- `jobEfficiency`（岗位效率：0~∞，产出倍率）
- 日产出计算更新为：`actualOutputPerDay = baseOutputPerDay * jobFillRate * jobEfficiency`
- `jobEfficiency` 可按行业区分，由科技提供加成。

### 5.4 政府岗位（政策曲线与科技）

- `governmentJobs`（政府岗位）由以下因素决定：
  - `policyCurve`（政策曲线：决定基础岗位供给）
  - `cityScale`（城市规模）
  - `techJobMultiplier`（科技岗位倍率）

### 5.5 消耗、存储与流动

- 逻辑保持不变，但与生产线解耦。

## 6. 城市吸引力与人口迁移

### 6.1 吸引力 `attractiveness` 公式（建议口径）

`attractiveness = (housingScore * w1 + employmentScore * w2 + supplyScore * w3 + landmarkBonus) * policyModifier`

- `housingScore`（住房充足度）：`min(housing / population, 1.0)`
- `employmentScore`（就业充足度）：`min(filledJobs / laborForce, 1.0)`
- `supplyScore`（民生供给充足度）：根据食物/民用品缺口计算（0~1）
- `landmarkBonus`（景观加成）：来自景观建筑的固定加成
- `policyModifier`（政策/税负修正）：高税率降低吸引力
- `w1, w2, w3`（权重）：可调参数，例如 `w1=0.4, w2=0.4, w3=0.2`

### 6.2 人口增长与迁移

- 按 `simulationDay`（模拟日）结算。
- `populationGrowth = baseGrowthRate * attractiveness`
- 迁移：从低吸引力城市向高吸引力城市迁移，速率受吸引力差值、距离等影响。

## 7. 星球 UI 设计

### 7.1 行星总览面板（Planet Summary Panel）

> 目标：提供全星球宏观数据，用于快速决策。

- **核心数据字段清单**：
  - `planetProductionByResource`（全星球各资源日产出）
  - `planetConsumptionByResource`（全星球各资源日消耗）
  - `planetNetFlowByResource`（净流：产出-消耗）
  - `planetStorage`（行星库存汇总）
  - `planetPriceByResource`（行星价格：参考/本地市场价）
  - `planetImportExport`（进出口变化：按资源/总额）
  - `planetPopulationTotal`（星球总人口）
  - `planetPopulationTrend`（人口增长曲线：近 N 日）
  - `planetAttractiveness`（星球吸引力：城市吸引力聚合）

### 7.2 地表区域视图

- 优先级 1：与 `citySpecializationId`（城市专精）一致的资源点（效率最高）
- 优先级 2：基础民生必需资源（食物/民用品相关）
- 优先级 3：其他资源点（避免浪费，但投入较低）

### 6.3 景观效果

- `landmark`（自然景观）不提供产出岗位，但提供：
  - `attractivenessBonus`（吸引力加成：提升人口迁入）

  - `name`（区域名）、`surfacePercentage`（占比）、`developableSpace`（可开发空间）

### 7.2 地表区域视图（Surface Region View）

- 显示区域内城市卡片：

## 8. 星球开发规模与地表灯光

### 8.1 星球大小加成（Planet Size Modifier）

- **概念**：体现“同等城市规模在不同大小星球上代表的开发程度不同”。
- **规则**：星球越大，`planetSizeModifier`（星球大小加成）越小。

**示例**：
- 小星球：`planetSizeModifier = 1.0`
- 中等星球：`planetSizeModifier = 0.5`
- 大星球：`planetSizeModifier = 0.1`

### 8.2 总开发规模计算

`totalDevelopmentScale = Σ (city_i.scale * planetSizeModifier)`

**示例**：
- 城市规模 10：小星球贡献 `10 * 1.0 = 10`
- 城市规模 10：大星球贡献 `10 * 0.1 = 1`

### 8.3 地表灯光表现

- 行星纹理上叠加一层“地表灯光”。
- 灯光的亮度/范围与 `totalDevelopmentScale`（总开发规模）正相关。

## 9. 星球首都与两级财政

### 9.1 星球首都城市（Planetary Capital City）

- 每个星球有且仅有一个首都城市。
- 默认：星球上建立的第一个城市即为首都城市（也可在后续允许迁都，需另行定义成本与规则）。

### 9.2 星球财政账户 → 国家财政账户（上缴）

- **星球财政账户**：
  - 星球进出口盈余、税收等收入，优先结算到星球财政账户。
- **国家财政账户**：
  - 按政策上缴固定比例进入国家账户。

> 具体结算流水线与示例见：`经济系统/结算/经济系统口径.md` 与 `经济系统/结算/经济日结算示例.md`。

## 10. 文明形态与财政三模型（隔离）

为防止耦合与互相干扰，文明形态相关的财政系统明确分为以下 **三个独立计算模型**：

1. **通用税收模型**：`税收 (taxRevenue)` + `贸易盈余 (tradeSurplus)`
2. **蜂巢模型**：`巢群供给/贡赋 (hiveTithe)` + `贸易盈余 (tradeSurplus)`（若蜂巢允许对外贸易）
3. **机械模型**：`产能分配 (productionAllocation)` + `贸易盈余 (tradeSurplus)`（若机械允许对外贸易）

约束：
- 三个模型在计算上 **互不引用、互不转换、互不混合**。
- 同一局游戏、同一个国家/势力，只能选择其中 **一个** 模型作为财政结算口径。

### 10.1 蜂巢文明（Hive）城市

- **城市形态**：建议称为“孵化巢群/巢群节点”等（UI 名称）。
- **人口口径**：蜂巢使用 **子个体数量**（个体单位）作为主要计量与展示口径。
- **岗位逻辑**：以“子个体岗位”与“生物质维护”为核心；子个体增长与岗位填充更强耦合。
- **产出倾向**：偏向生物质、繁育、特化生物工坊等。
- **财政口径**：
  - 保留星球财政账户概念。
  - 将“税收”口径替换为 **巢群供给/贡赋**。

### 10.2 机械智能（Machine Intelligence）城市

- **城市形态**：建议称为“算力节点/机械聚落/工业节点”等（UI 名称）。
- **人口口径**：机械智能使用 **单元数量**（Unit Count）作为主要计量与展示口径。
- **岗位逻辑**：以“算力/维护能耗/装配线”作为关键约束；单元数量与算力容量共同决定可用岗位。
- **产出倾向**：偏向工业、算力、能源与维护效率。
- **财政口径**：
  - 保留星球财政账户概念。
  - 将“税收”口径替换为 **产能分配/能耗预算**。
