# 科技树与分类

> 目标：定义一个数据驱动的、基于前置科技的传统科技树，并采用更细分的科技领域分类，以支持深度的策略选择和便捷的Mod扩展。

## 1. 核心原则

- **传统科技树**：彻底取代“抽卡”机制，采用基于**前置科技 (Prerequisites)** 的依赖关系图，玩家可以清晰地看到研究路线。
- **细分领域**：将科技划分为多个具体的功能领域，而不是宽泛的“物理/社会/工程”。
- **数据驱动**：所有科技及其关系都必须**数据化存储**（如JSON/YAML文件）。游戏启动时读取这些数据，在内存中构建完整的科技树图。
- **支持Mod扩展**：整个系统必须设计为易于扩展，允许Mod添加新的科技、分类，甚至修改现有科技关系。

---

## 2. 细分科技领域 (Technology Categories)

以下为推荐的基础科技领域分类，此列表**必须是可扩展的**，Mod可以自由添加新的分类。

| 领域（中文） | 建议英文ID | 核心解锁内容（口径） |
|---|---|---|
| **材料学** | `materials` | 解锁更高级的资源（如战略资源）、更坚固的装甲模块和船体结构。 |
| **工业技术** | `industry` | 增强城市的生产能力、解锁更高级的工业建筑和生产配方。 |
| **宇航技术** | `astronautics` | 解锁更高级的太空设施（船坞、空间站）、舰船的核心模块和推进器。 |
| **物理学** | `physics` | 解锁更强大的护盾、反应堆、传感器和能量武器。 |
| **社会学** | `society` | 解锁新的政策、政体形式、外交选项和行星管理能力。 |

---

## 3. 科技树结构

- **前置关系**：科技树是一个**有向无环图 (DAG)**，其结构完全由科技之间的**前置依赖**定义。
- **解锁规则**：一个科技只有在其`prerequisites`列表中的所有前置科技都已被研究完成后，才变为“可研究”状态。

## 4. 数据驱动设计

所有科技都必须通过一个标准化的数据结构来定义，游戏将读取这些数据文件来构建科技树。

### 4.1 科技数据结构（口径）

```typescript
// 概念性数据结构
interface Technology {
  id: string; // 唯一ID，如 "tech_advanced_materials_1"
  name: string; // 显示名称，如“高级复合装甲”
  description: string; // 描述

  category: string; // 所属领域的ID，如 "materials"

  cost: number; // 研究成本（科研点数）

  prerequisites: string[]; // 前置科技的ID列表

  unlocks: any; // 解锁的效果（如新的舰船模块ID、建筑ID、政策ID等）
}
```

### 4.2 数据加载流程

1.  游戏启动时，扫描所有科技数据文件（包括核心游戏和所有已激活的Mod）。
2.  将所有科技数据读入内存。
3.  根据每个科技的`prerequisites`列表，构建出完整的科技依赖关系图。
4.  游戏中的科技界面将根据这个图来动态展示可研究的科技及其路线。

## 5. Mod扩展支持

- **添加新科技**：Mod作者只需按照数据结构，创建新的科技定义文件并放入指定目录即可。
- **添加新分类**：Mod可以定义新的科技分类ID，并在其科技文件中使用。
- **修改现有科技**：游戏应支持Mod通过“补丁”或“覆盖”的方式，修改核心游戏中的科技（例如，改变其成本、前置或解锁效果），但这需要加载系统提供支持。
