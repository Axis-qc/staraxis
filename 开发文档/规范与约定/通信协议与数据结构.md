# 通信协议与数据结构

> 目标：定义客户端与服务端之间通信的核心数据结构，包括指令（Commands）、事件（Events）和快照（Snapshots），确保通信的明确性、可扩展性和确定性。

## 1. 核心原则

- **单向数据流**：客户端发送指令，服务端执行并返回事件/快照。客户端不直接修改状态。
- **确定性**：所有指令的执行必须是确定性的。相同的指令序列在任何时候都应产生相同的结果。
- **可序列化**：所有通信数据结构都必须是可序列化的，以便在网络上传输和存入存档。

---

## 2. 指令（Commands）

指令是客户端向服务端表达“意图”的唯一方式。

### 2.1 基础指令结构（口径）

所有指令都应包含一个通用的头部，用于追踪和排序。

```typescript
// 概念性数据结构
interface CommandHeader {
  commandId: string;      // 唯一ID，用于追踪和确认
  commandType: string;    // 指令类型，如 "MoveFleet"
  timestamp: number;      // 客户端发送时的时间戳
  sequenceNumber: number; // 客户端发送的指令序号，用于排序和防重放
}

interface BaseCommand {
  header: CommandHeader;
  payload: any; // 具体指令的负载
}
```

### 2.2 核心指令示例

#### 移动舰队 (`MoveFleetCommand`)

- **意图**：将指定的舰队移动到目标位置。
- **负载 (`payload`)**：
  ```typescript
  {
    fleetId: string;              // 要移动的舰队ID
    destinationWorldPos: { x: number, y: number }; // 目标点的世界坐标
    targetObjectId?: string;      // （可选）如果目标是某个对象（如行星、敌方舰队），则提供其ID
  }
  ```

#### 建立城市 (`EstablishCityCommand`)

- **意图**：在指定行星的某个地表区域上建立一个新城市。
- **负载 (`payload`)**：
  ```typescript
  {
    planetId: string;             // 目标行星ID
    surfaceRegionName: string;    // 目标地表区域的名称（如“希望大陆”）
  }
  ```

#### 指定城市专精 (`SetCitySpecializationCommand`)

- **意图**：为指定城市设置一个新的专精方向。
- **负载 (`payload`)**：
  ```typescript
  {
    cityId: string;               // 目标城市ID
    specializationId: string;     // 新的专精ID（如 "mining", "research"）
  }
  ```

### 2.3 扩充指令清单

#### 建造指令

- **`QueueBuildingCommand`**
  - **意图**：在指定城市的建筑队列中添加一个新项目。
  - **负载 (`payload`)**：
    ```typescript
    {
      cityId: string;       // 目标城市ID
      buildingId: string;   // 要建造的建筑类型ID
      position: number;     // 在队列中的位置（-1表示末尾）
    }
    ```
- **`QueueShipCommand`**
  - **意图**：在指定船坞的造船队列中添加一艘新舰船。
  - **负载 (`payload`)**：
    ```typescript
    {
      shipyardId: string;   // 目标船坞ID
      shipDesignId: string; // 要建造的舰船设计ID
      quantity: number;     // 数量
    }
    ```

#### 科研指令

- **`SelectTechnologyCommand`**
  - **意图**：选择一个科技进行研究。
  - **负载 (`payload`)**：
    ```typescript
    {
      technologyId: string; // 要研究的科技ID
    }
    ```

#### 外交指令

- **`DeclareWarCommand`**
  - **意图**：对另一个派系宣战。
  - **负载 (`payload`)**：
    ```typescript
    {
      targetFactionId: string; // 目标派系ID
    }
    ```
- **`ProposePeaceCommand`**
  - **意图**：向另一个派系提出和平提议。
  - **负载 (`payload`)**：
    ```typescript
    {
      targetFactionId: string; // 目标派系ID
      terms: any;              // 和平条款的数据结构
    }
    ```
- **`ProposeTradeDealCommand`**
  - **意图**：向另一个派系提出贸易协定。
  - **负载 (`payload`)**：
    ```typescript
    {
      targetFactionId: string; // 目标派系ID
      dealTerms: any;          // 贸易条款的数据结构
    }
    ```

## 3. 事件（Events）与快照（Snapshots）

事件和快照是服务端向客户端同步“世界状态变化”的方式。

### 3.1 基础事件结构（口径）

所有事件也应包含一个通用的头部。

```typescript
// 概念性数据结构
interface EventHeader {
  eventId: string;        // 唯一ID
  eventType: string;      // 事件类型，如 "FleetMoved"
  simulationDay: number;  // 事件发生时的游戏天数
  timestamp: number;      // 服务端生成事件时的时间戳
}

interface BaseEvent {
  header: EventHeader;
  payload: any; // 具体事件的负载
}
```

### 3.2 核心事件示例

#### 舰队位置更新 (`FleetMovedEvent`)

- **意图**：通知客户端某舰队的位置已更新。
- **负载 (`payload`)**：
  ```typescript
  {
    fleetId: string;
    newWorldPos: { x: number, y: number }; // 新的世界坐标
    path?: { x: number, y: number }[];   // （可选）新的移动路径，用于客户端平滑预测
  }
  ```

#### 资源储量变化 (`ResourceUpdatedEvent`)

- **意图**：通知客户端某个节点的资源储量发生了变化。
- **负载 (`payload`)**：
  ```typescript
  {
    nodeId: string; // 节点ID（如行星ID）
    resourceId: string; // 变化的资源ID
    newAmount: number; // 新的储量
    changeAmount: number; // 变化的量（正或负）
  }
  ```

### 3.3 扩充事件清单

#### 建造事件

- **`BuildingQueueUpdatedEvent`**
  - **意图**：通知客户端一个城市的建筑队列发生了变化。
  - **负载 (`payload`)**：
    ```typescript
    {
      cityId: string;
      queue: { buildingId: string, progress: number }[]; // 整个新的队列状态
    }
    ```
- **`ShipQueueUpdatedEvent`**
  - **意图**：通知客户端一个船坞的造船队列发生了变化。
  - **负载 (`payload`)**：
    ```typescript
    {
      shipyardId: string;
      queue: { shipDesignId: string, quantity: number, progress: number }[]; // 整个新的队列状态
    }
    ```

#### 科研事件

- **`TechnologyStatusChangedEvent`**
  - **意图**：通知客户端科技研究的状态发生了变化。
  - **负载 (`payload`)**：
    ```typescript
    {
      technologyId: string;
      status: 'InProgress' | 'Completed';
      progress?: number; // 当前研究点数 / 总需求点数
    }
    ```

#### 外交事件

- **`DiplomaticStatusChangedEvent`**
  - **意图**：通知客户端与其他派系的外交关系发生了变化。
  - **负载 (`payload`)**：
    ```typescript
    {
      factionA_Id: string;
      factionB_Id: string;
      newStatus: 'War' | 'Peace' | 'Alliance';
    }
    ```
- **`DiplomaticProposalReceivedEvent`**
  - **意图**：通知客户端收到了一个新的外交提议。
  - **负载 (`payload`)**：
    ```typescript
    {
      fromFactionId: string;
      proposalId: string;
      proposalType: 'Peace' | 'TradeDeal';
      terms: any; // 提议的具体条款
      expiresInDays: number; // 过期天数
    }
    ```

### 3.4 快照（Snapshot）

- **概念**：某个时间点世界状态的“摘要”。用于初次加载、断线重连或强制同步。
- **按需发送**：快照的内容应根据客户端的“兴趣范围”（如当前视角所在的恒星系）动态生成，而不是发送整个世界状态。
- **数据结构（口径）**：快照的结构会比较复杂，通常是一个嵌套的对象，反映了世界状态树的一部分。其具体结构将在后续实现阶段定义，但必须遵循“按需”原则。
