# 命名规范（标识符英文 + 示例覆盖）

> 目标：统一代码/数据/配置的命名风格，减少歧义与随意缩写。

## 1. 总原则

- **标识符必须为英文**（禁止拼音）。
- **语义清晰优先**：宁可长一点，不要随意缩写。
- **与术语表对齐**：核心概念命名尽量采用术语表中的规范英文名。

## 2. 大小写与风格

- 变量/函数：`camelCase`
- 类/接口/组件：`PascalCase`
- 常量：`UPPER_SNAKE_CASE`
- 文件/文件夹：建议 `kebab-case`（若目录与文档要求中文命名，仅限文档；代码目录仍按宪章 kebab-case）

## 3. 禁止项

- 拼音（例如 `xingQuId`）
- 过度缩写（例如 `cfgMgr`, `ecoSys`，除非项目统一定义）
- 同义不同名（同一概念出现多个英文名）

## 4. 文档字段注释规范（全项目适用）

> 目标：让文档可“单篇自洽”。读者无需到处查找，即可理解字段/结构/缩写的含义与用途。

### 4.1 适用范围

- 适用于所有开发文档（含：总目录、系统设计、协议、示例、缺口清单等）。
- “字段/代码名”包括但不限于：
  - 协议字段：如 `cmdId`、`clientSeq`、`serverTick`、`simulationDay`
  - 结构名：如 `CommandHeader`、`CommandAck`、`SecurityAuditEvent`
  - 枚举值/原因码：如 `Rejected`、`OutOfWindow`
  - 关键集合/变量：如 `pendingCommands`、`processedCmdIds`

### 4.2 正文写法（行内字段必须注释）

- 在正文中出现字段/结构名时，必须采用以下格式之一：
  - **推荐**：`fieldName`（一句话解释它是什么/做什么用）
  - 或：`fieldName`（是什么）+（用于什么/由谁维护）
- 示例：
  - `clientSeq`（客户端递增序号，用于排序与乱序/丢包检测）
  - `serverTick`（服务端权威 tick，用于联机对齐与预测回滚）

> 约束：为保证“直接读得懂”，不要求只在首次出现时解释；允许重复解释。

### 4.3 代码块写法（每个字段都要行内注释）

- `interface`/`type`/结构体等代码块中：
  - **每个字段必须有行内注释**，说明：含义、用途、权威来源（客户端/服务端）、是否可为空。
- 示例：
  - `cmdId: string; // 指令全局唯一 ID：用于幂等/去重/追踪`

### 4.4 枚举/状态/原因码写法

- 枚举值必须附带中文解释：
  - `OutOfWindow`（超出窗口：乱序缓存/追帧窗口外）
  - `Unauthorized`（未认证：会话无效/登录失效）

### 4.5 允许的例外（必须很少）

- 广为人知的通用缩写可不解释（如 CPU、GPU、JSON），但若用于项目关键逻辑仍建议补一句。
- 大段“完整字段表”可将解释移到表格中，但必须保证同页可见。

## 5. 示例（覆盖指定类别，≥ 20）

> 下列示例仅作命名参考；实际字段以具体系统设计为准。

### A. 坐标

1. `worldPosition`（世界坐标位置）
2. `localPosition`（本地坐标位置）
3. `sectorCenterWorldPosition`（星区中心的世界坐标）
4. `toLocalPosition()`（转换为本地坐标）

### B. 时间

5. `simulationTime`（模拟时间）
6. `secondsPerGameHour`（每游戏小时对应的现实秒）
7. `advanceSimulationBySeconds()`（按秒推进模拟）

### C. 地图层级

8. `sectorId`（星区 ID）
9. `starSystemId`（恒星系 ID）
10. `planetId`（行星 ID）
11. `regionId`（星域/区域 ID）

### D. 经济资源

12. `resourceStockpile`（资源库存）
13. `dailyProduction`（日生产量）
14. `dailyConsumption`（日消耗量）
15. `dailySettlement()`（日结算）
16. `planetMarketPrice`（行星市场价格）

### E. 舰队战斗

17. `fleetId`（舰队 ID）
18. `weaponDamage`（武器伤害）
19. `shieldHitPoints`（护盾生命值）
20. `armorMitigation`（装甲减伤）
21. `supplyRemaining`（剩余补给）

### F. UI 模型

22. `SectorSummaryViewModel`（星区摘要 UI 模型）
23. `PlanetPanelViewModel`（行星面板 UI 模型）

### G. 配置与常量

24. `MAX_FLEET_SIZE`（最大舰队规模）
25. `DEFAULT_ZOOM_FACTOR`（默认缩放因子）

### H. 事件与状态

26. `isUnderSupply`（是否处于补给状态）
27. `onDailySettlementCompleted`（日结算完成事件）
28. `simulationState`（模拟状态）
