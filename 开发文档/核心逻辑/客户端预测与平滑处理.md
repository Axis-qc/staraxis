# 客户端预测与平滑处理

> 目标：明确客户端在收到服务端权威状态前的视觉表现口径，以及如何处理预测与实际状态的偏差。

## 1. 核心原则

- **预测是纯视觉的**：客户端预测**仅限于视觉表现**，其预测结果**绝不能**用于触发任何游戏逻辑（如战斗、采集、碰撞等）。所有逻辑判断必须以服务端状态为准。
- **主要服务于多人模式**：此机制主要用于处理未来多人模式下的网络延迟，以提升操作手感。在单人本地游戏中，由于服务端与客户端一体，基本不会出现预测偏差。

## 2. 允许预测的操作

- **玩家直接控制单位的移动**：当玩家发出移动指令后，客户端可在视觉上立即开始移动，无需等待服务端确认。

## 3. 纠正机制：线性拉回

- **触发**：当客户端收到来自服务端的、关于该单位的权威位置状态更新时，若该位置与客户端预测的视觉位置不符。
- **行为**：客户端**直接线性地**将单位的视觉表现“拉回”到服务端的权威位置上。无需复杂的平滑插值算法。

## 4. 验收口径

- **Given** 在模拟的网络延迟环境下，玩家发出移动指令，**When** 单位开始移动后，服务端发送一个修正位置，**Then** 客户端上的单位视觉表现应从当前位置线性移动到修正后的位置。
