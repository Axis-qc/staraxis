# 数据记录与结算分析

> 目标：定义一种高效的数据记录机制，用于追踪整局游戏的关键指标变化，并在游戏结束后为玩家提供一份可供分析的汇总报告。

## 1. 核心思想

放弃记录玩家的每一个操作指令（会导致文件过大），改为在固定的时间间隔（每日）记录帝国的关键宏观指标快照。这种方式数据量小，且能完美满足游戏结束后的复盘分析需求。

## 2. 记录的数据点（Data Points）

以下为必须追踪的关键指标列表。此列表可在后续开发中扩展。

- **领土**：
  - `planetCount`: 已殖民星球数量
- **人口**：
  - `totalPopulation`: 总人口（所有星球人口之和）
- **经济**：
  - `economicScore`: 经济实力综合得分（可由总产值、科技水平等加权计算）
  - `resourceProduction`: 各类主要资源的日产出（例如：`energy`, `minerals`, `food` 等）
  - `resourceConsumption`: 各类主要资源的日消耗
- **军事**：
  - `totalFleetSize`: 总舰船数量（或按吨位计算的总规模）
  - `totalFleetPower`: 总舰队实力（综合战斗力评估）
  - `totalKills`: 累计击杀单位数（按舰船等级或实力加权）

## 3. 记录机制（Recording Mechanism）

- **触发时机**：**每个“日结算”** (`DailySettlement`) 流程**完成之后**。
- **执行者**：**服务端**。在每个游戏日结束时，服务端采集上述所有数据点，形成一个“每日快照 (Daily Snapshot)”。
- **数据结构**：所有每日快照被追加到一个时间序列列表中。
  ```typescript
  // 概念性数据结构
  type DailySnapshot = {
    day: number;
    planetCount: number;
    totalPopulation: number;
    // ... 其他数据点
  }

  let gameHistory: DailySnapshot[] = [];
  ```

## 4. 数据存储（Data Storage）

- **位置**：`gameHistory` 这个时间序列数据将作为**存档文件**的一部分进行序列化和存储。
- **优点**：
  - **数据量可控**：即使游戏进行 1000 天，也只是 1000 条记录，远小于指令日志。
  - **存档一体化**：读取存档时，历史数据一并恢复，无需管理额外文件。

## 5. 最终呈现（Presentation）

- **触发**：游戏结束（胜利、失败、或玩家选择“退出并查看统计”）。
- **形式**：游戏切换到一个专用的“结算分析 (Post-Game Analysis)”界面。
- **内容**：
  - **概览**：展示最终得分、游戏时长、关键成就等总结性信息。
  - **图表**：将 `gameHistory` 中的时间序列数据渲染成**曲线图**，X 轴为游戏天数，Y 轴为对应指标（如人口、经济实力等），允许多个指标在同一图表中对比。
  - **表格**：提供详细的每日数据表格供玩家查阅。
