## 0-docs/01-底层架构/11客户端设计方案.md（单机客户端架构）

- **P0 - RealTimeWorldState 发布口径已敲定：双缓冲 + 全量填充发布** [已落文档]
  - 已在 `0-docs/01-底层架构/11客户端设计方案.md` 约定：
    - 每个 `simulationTick` 结束时，模拟层在 `inactive` 缓冲中对 `RealTimeWorldState` 进行全量填充。
    - 填充完成后进行一次性交换（swap）发布为 `active`，UI/渲染始终读取 `active`，保证一致视图。

- **P0 - 指令（Intent/Command）消费时序与顺序规则已敲定：tick 开始批量取出 + FIFO；错过则下 tick** [已落文档]
  - 已在 `0-docs/01-底层架构/11客户端设计方案.md` 约定：
    - UI 的 `Intent/Command` 进入指令队列。
    - 模拟层在每个 tick 开始时批量取出指令并按入队顺序执行。
    - 若指令在本 tick 开始后才入队，则在下一 tick 执行。

- **P1 - UI 从 RealTimeWorldState 读取的范围/形态不明确** [待处理]
  - 需要明确：
    - UI 读取的是“最小展示字段集合/摘要投影”，还是完整实时态。
    - 禁止 UI 在展示侧做复杂聚合/推导（避免读扩散）。

- **P1 - DailySettlementState 的包含范围与分类原则不明确** [待处理]
  - 需要明确：
    - 哪些数据必须走日结算落账（避免 UI 日内抖动/中间态）。
    - 实时/非实时数据的分类规则（例如科技/建造/外交等边界项）。

- **P1 - 线程模型假设未明确** [待处理]
  - 需要明确：
    - 是否允许模拟/渲染/UI 分线程。
    - 若分线程：`RealTimeWorldState`/`DailySettlementState` 的发布与只读跨线程安全口径。

- **P0 - 读档后只读状态的初始化/发布口径不明确** [待处理]
  - 需要明确：
    - 读档完成后如何生成并发布 `RealTimeWorldState` 与 `DailySettlementState`（从存档恢复或由 `WorldState` 派生）。
    - 确保进入主界面时 UI/渲染有一致的数据源。

- **P2 - 文档措辞："管理 WorldState" 容易被误读为 UI/渲染可管理** [待处理]
  - 建议将职责表述限定为“模拟层管理 `WorldState`”或“客户端模拟模块管理 `WorldState`”。
