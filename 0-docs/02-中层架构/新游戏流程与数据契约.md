# 新游戏流程与数据契约

> 目标：定义从“点击新游戏”到“渲染世界地图”的端到端流程、API 接口与数据结构，作为前后端开发的权威依据。

## 0. 核心原则

- **严格遵循 `12条硬规则`**：特别是“模拟层权威”、“确定性优先”、“数据驱动”等。
- **前后端分离**：前端（`web`）负责 UI 展示与用户交互，后端（`game`+`webnet`）负责业务逻辑与数据处理。
- **接口先行**：先定义清晰的 API 契约，再进行具体实现。

## 1. 整体流程（三步口径）

### Step 1：前端选择国家 → 后端保存玩家国家选择

1. **[前端]** 用户在主菜单 (`MainMenuView.vue`) 点击“新游戏”。
2. **[前端]** 路由切换到“国家选择”界面 (`NationSelectionView.vue`)。
3. **[前端]** 前端调用 `GET /api/game/nations` 获取国家列表并展示。
4. **[前端]** 用户选定国家后点击“下一步”，前端调用 `POST /api/newgame/step1/selectNation`，提交 `username` 与 `nationId`。
5. **[后端]** `webnet` 在 `gamedata/saves/` 下创建/更新本次新游戏草稿文件（NewGameDraft，文件名固定为 `<username>_newgame.json`），并返回 `newGameDraftId`（本期口径：`newGameDraftId == username`，用于唯一定位草稿文件）。

### Step 2：前端世界设置 → 后端保存世界设置

6. **[前端]** 路由切换到“世界设置”界面 (`WorldSettingsView.vue`)。
7. **[前端]** 用户填写/调整 `worldGenConfig`（例如 `worldSeed`、`sectorCount`、密度参数等）。
8. **[前端]** 用户点击“下一步/保存”，前端调用 `POST /api/newgame/step2/worldSettings`，提交 `newGameDraftId`（即 `username`）与 `worldGenConfig`。
9. **[后端]** `webnet` 将 `worldGenConfig` 保存到对应的 NewGameDraft。

### Step 3：前端确认开始 → 后端生成世界 → 返回快照 → 前端渲染（three.js 2.5D）

10. **[前端]** 路由切换到“确认开始”界面 (`NewGameConfirmView.vue`)（或在世界设置页直接提供确认步骤）。
11. **[前端]** 用户点击“开始生成”，前端调用 `POST /api/newgame/step3/confirm`，提交 `newGameDraftId`。
12. **[后端]** `webnet` 读取草稿中的 `playerId`、`nationId`、`worldGenConfig`，调用 `game` 模块启动异步世界生成。
13. **[后端]** `game` 模块作为权威模拟层，根据 `nationId`（开局偏好/母星设定等）与 `worldGenConfig`（含 `worldSeed`）生成世界；生成过程严格遵循确定性与《世界生成流程.md》。
14. **[后端]** `webnet` 通过 WebSocket 推送 `world_gen_progress` 进度。
15. **[后端]** 生成完成后，`game` 产出 `InitialWorldSnapshot`（用于渲染的最小快照）。
16. **[后端]** `webnet` 通过 WebSocket 推送 `initial_world_snapshot`。
17. **[前端]** 前端进入 `InGameView.vue`，使用 three.js 将世界快照渲染为 **2.5D** 世界地图。

## 2. 草稿存储与所有权口径（NewGameDraft）

- **存储目录**：项目根目录 `gamedata/saves/`
- **草稿文件（每个 username 仅 1 份，覆盖写入）**：`gamedata/saves/<username>_newgame.json`
  - `username` 来自账号文件名 `gamedata/accounts/<username>.json`（示例：`AXIS`）。
  - 草稿文件中仍保存权威 `playerId`（例如 `p_edef2619-33a3-420f-aacf-89147133cb08`），用于所有权校验与索引。
- **所有权识别（强制）**：所有读写都必须携带 `username` 与 `playerId`。
  - 服务端必须加载 `gamedata/accounts/<username>.json`，校验其中 `playerId` 与请求的 `playerId` 完全一致。
  - 草稿文件名使用 `username`（`gamedata/saves/<username>_newgame.json`），但**所有权以 `playerId` 为权威**，防止仅凭 `username` 伪造/越权。
- **“只保存上一次修改”**：
  - Step 1/2 的保存行为均为**覆盖写入**该草稿文件。
  - 草稿文件只代表该玩家最近一次新游戏配置草稿。
- **世界生成读取口径**：Step 3 生成世界时，服务端必须从磁盘读取该草稿文件作为权威输入（而不是使用内存缓存）。

### 2.1 草稿文件结构（最小）

```json
{
  "schemaVersion": 1,
  "playerId": "p_edef2619-33a3-420f-aacf-89147133cb08",
  "updatedAtUnixMs": 1730000000000,
  "nationId": "human_republic",
  "worldGenConfig": {
    "worldSeed": "optional_seed_string",
    "sectorCount": 200,
    "starSystemDensity": 0.6
  }
}
```

## 3. API 接口设计（`webnet` 模块）

### 3.1 HTTP API

- **`GET /api/game/nations`**: 获取可选国家列表。
    - **响应 (200 OK)**: `application/json`
    ```json
    {
      "ok": true,
      "nations": [
        {
          "id": "human_republic",
          "name": "人类共和国",
          "description": "...",
          "traits": [{"id": "trait_industrial", "name": "工业主义"}]
        }
      ]
    }
    ```

- **`POST /api/newgame/step1/selectNation`**: Step 1：保存玩家国家选择，并创建/更新新游戏草稿（NewGameDraft）。
    - **请求体**: `application/json`
    ```json
    {
      "username": "AXIS",
      "playerId": "p_edef2619-33a3-420f-aacf-89147133cb08",
      "nationId": "human_republic"
    }
    ```
    - **响应 (200 OK)**: `application/json`
    ```json
    {
      "ok": true,
      "newGameDraftId": "AXIS"
    }
    ```

- **`POST /api/newgame/step2/worldSettings`**: Step 2：保存世界设置（worldGenConfig）到新游戏草稿。
    - **请求体**: `application/json`
    ```json
    {
      "username": "AXIS",
      "playerId": "p_edef2619-33a3-420f-aacf-89147133cb08",
      "newGameDraftId": "AXIS",
      "worldGenConfig": {
        "worldSeed": "optional_seed_string",
        "sectorCount": 200,
        "starSystemDensity": 0.6
      }
    }
    ```
    - **响应 (200 OK)**: `application/json`
    ```json
    { "ok": true }
    ```

- **`POST /api/newgame/step3/confirm`**: Step 3：确认开始生成世界。服务端读取草稿中的 `playerId`、`nationId`、`worldGenConfig` 并启动权威生成。
    - **请求体**: `application/json`
    ```json
    {
      "username": "AXIS",
      "playerId": "p_edef2619-33a3-420f-aacf-89147133cb08",
      "newGameDraftId": "AXIS"
    }
    ```
    - **响应 (202 Accepted)**: `application/json`（表示已接受任务，开始异步生成）
    ```json
    {
      "ok": true,
      "gameSessionId": "session_1730000000000_abcdef"
    }
    ```

### 3.2 WebSocket 消息（双向）

- **连接**: `GET /ws`

- **前端 -> 后端**: (暂无，启动流程由 HTTP 发起)

- **后端 -> 前端**: 
    - **世界生成进度更新**
    ```json
    {
      "type": "world_gen_progress",
      "progress": 0.25,
      "step": "Generating sectors"
    }
    ```
    - **世界生成完成，推送初始数据**
    ```json
    {
      "type": "initial_world_snapshot",
      "snapshot": {
        "sectors": [
          {"id": 0, "q": 0, "r": 0, "type": "star-system", "ownerNationId": "human_republic"},
          {"id": 1, "q": 1, "r": 0, "type": "deep-space"}
        ],
        "starSystems": [
          {"sectorId": 0, "name": "Sol", "starType": "G"}
        ]
      }
    }
    ```

## 4. 国家数据存储（gamedata/nations）

> 口径：采用方案 A（一个国家一个文件）。

- **根目录**：`gamedata/nations/`
- **预设国家（Presets）**：`gamedata/nations/presets/<nationId>.json`
- **玩家自定义国家（Players）**：`gamedata/nations/players/<username>/<nationId>.json`

### 4.1 文件格式（最小）

```json
{
  "schemaVersion": 1,
  "nation": {
    "id": "human_republic",
    "nameKey": "nation.human_republic.name",
    "descriptionKey": "nation.human_republic.desc",
    "governmentId": "gov_republic",
    "speciesIds": ["species_human"],
    "startingTechIds": ["tech_basic_mining_1"]
  }
}
```

### 4.2 所有权与校验（Players）

- 玩家自定义国家的保存/读取请求必须携带 `username` 与 `playerId`。
- 服务端必须加载 `gamedata/accounts/<username>.json` 并校验 `playerId` 一致。
- 目录隔离：玩家国家文件必须写入 `gamedata/nations/players/<username>/` 下，禁止跨目录写入。

## 5. 数据与资源最小规范（本体 + Mod）

> 目标：在“暂时没有既定规范”的前提下，定义一个**最小、可演进、数据驱动**的资源规范，满足国家表与世界生成配置的加载，并与现有 i18n 的“本体 → Mod 顺序覆盖”理念一致。

### 3.1 目录与加载顺序（强制口径）

- **本体资源根**：项目根目录 `assets/`
- **Mod 资源根**：`gamedata/mods/<modId>/assets/`
- **Mod 启用与顺序**：唯一权威 `gamedata/mods/mod-order.json`
- **合并规则**：按“**本体 → Mod 顺序**”加载并合并，**后加载覆盖先加载**（同 `id` 覆盖；同文件名不做覆盖依赖）。

### 3.2 配置文件格式（强制口径）

- **唯一格式**：JSON
- **推荐表封装结构**（与《配置系统与表结构.md》一致）：

```json
{
  "meta": {
    "configVersion": "0.0.0-dev",
    "module": "nation",
    "generatedAtUnixMs": 0
  },
  "tables": {
    "nation": [
      {
        "id": "human_republic",
        "nameKey": "nation.human_republic.name",
        "descriptionKey": "nation.human_republic.desc",
        "startingBias": {
          "homeworldPreferredSectorTypeId": "star-system"
        }
      }
    ]
  }
}
```

### 3.3 模块目录（本期最小集合）

- `assets/nation/*.json`
- `assets/worldgen/*.json`

Mod 侧对应：
- `gamedata/mods/<modId>/assets/nation/*.json`
- `gamedata/mods/<modId>/assets/worldgen/*.json`

### 3.4 校验与确定性约束（本期最小约束）

- 所有记录必须有稳定主键 `id`（string）。
- 合并后 `id` 必须唯一；若重复则以“后加载覆盖”处理，并记录诊断日志。
- 影响世界生成确定性的配置（例如 `worldgen`）在生成开始后不得热更。

## 5. 后端职责与实现要点（`webnet` / `game`）

- **`webnet`**：
    1. 负责实现 `GET /api/game/nations` 与 `/api/newgame/step1..3` 三步接口。
    2. Step 1/2 负责将草稿覆盖写入 `gamedata/saves/<username>_newgame.json`。
    3. Step 3 必须从磁盘读取草稿文件作为权威输入，并调用 `game` 启动异步世界生成。
    4. 生成过程中通过 WebSocket 推送 `world_gen_progress`；完成后推送 `initial_world_snapshot`。
- **`game`**：
    1. 作为权威模拟层，基于 `nationId` 与 `worldGenConfig` 生成世界（确定性：同输入同输出）。
    2. 提供世界生成服务（例如 `WorldGeneratorService`）并暴露进度回调/事件。
    3. 生成完成后产出 `InitialWorldSnapshot`（前端渲染最小快照）。
    4. 提供 `NationService`：从 `assets/nation/*.json` 与 Mod 覆盖加载国家定义。

## 6. 前端视图实现（`web`）

- **`views/NationSelectionView.vue`**: 
    - `onMounted` 时调用 `GET /api/game/nations`。
    - 渲染国家列表，提供选择功能。
- **`views/WorldSettingsView.vue`**:
    - 提供表单让用户调整 `worldGenConfig`。
    - 点击“下一步/保存”时调用 `POST /api/newgame/step2/worldSettings`；在确认界面点击“开始生成”时调用 `POST /api/newgame/step3/confirm`。
- **`views/LoadingView.vue`**:
    - 监听 WebSocket 的 `world_gen_progress` 消息，更新进度条/提示信息。
    - 监听到 `initial_world_snapshot` 消息后，将数据存入状态管理（如 Pinia），并跳转到游戏主界面。
- **`views/InGameView.vue`**:
    - 从状态管理中获取 `initialWorldSnapshot`。
    - 使用 `three.js` 或 `pixi.js` 等渲染六边形星区地图和其中的恒星系。
