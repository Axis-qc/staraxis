## 0. 核心架构（Web 渲染 + Java 模拟）

当前项目已转为 **浏览器 Web 渲染 + Java 后端模拟** 模式：

- **Java (webnet)**：作为本地权威服务器，负责游戏模拟、规则计算，并通过 WebSocket 推送状态。
- **Web (浏览器)**：作为客户端，负责 UI、画面渲染（WebGL/Canvas），并通过 WebSocket 接收状态、发送指令。
- **LibGDX 原生端**：已精简为空壳，未来重做时会复用同一套网络协议。

## 3. 需要牢记的 12 条硬规则

1.  **模拟层权威**：所有改变游戏结果的逻辑只在 `game` 模块执行。
2.  **确定性优先**：相同输入与初始状态必须得到相同结果（为存档对账服务）。
3.  **模拟时间驱动**：推进与结算绑定 `simulationTick`（本地模拟 Tick） / `gameDatetimeDay`，不能由 FPS 驱动。
4.  **多核并行是强制项**：可并行计算要拆 Job；但权威写入必须在“落账点”串行化。
5.  **双快照口径**：
    -   `上一日结算状态（DailySettlementState）`：UI 层展示经济/生产/人口等具有固定结算周期（按“日”）的数据（避免读取计算中间态）。
    -   `实时世界状态（RealTimeWorldState）`：战斗、移动、即时事件等实时系统；以及需要即时数据的 UI 展示。
6.  **命名/术语统一**：所有字段写法必须一致，正文出现字段必须用 `fieldName`（解释）格式。
7.  **代码必须带注释**：所有代码都必须带注释，禁止不写注释。
8. **模块化、可维护性与数据驱动**：所有功能必须以模块化方式设计。在创建新方法或字段前，必须先检索现有代码库以避免重复。
9. **禁止硬编码**：禁止硬编码 (Hardcoding) 与硬枚举 (Hard Enums)。
10. **数据驱动优先**：游戏行为与内容应由外部数据（如 JSON/表）定义，而不是硬编码在代码中。
11. **配置加载口径**：所有可配置项（如数值、ID、路径）必须通过配置系统加载，禁止散落的魔法数字 (Magic Numbers) 与硬编码字符串。
12. **可演进性**：配置与数据结构需要允许未来迭代与 Mod 扩展。

## 4. 游戏运行逻辑

### 4.1 当前 Web 版本

- **游戏启动入口（发行/一键启动）**：`StarAxis.jar`
  - 该 Jar 位于项目根目录（由 Gradle 任务拷贝/重命名生成）。
  - 运行：`java -jar StarAxis.jar`

- **常用启动方式**：
  - `./gradlew :webnet:run`（仅启动后端；默认托管 `web/dist`）
  - `./gradlew runWeb`（同上：仅启动后端；托管 `web/dist`）
  - `./gradlew runWebDev`（开发态一键启动：后端 + 前端 dev server；**主界面访问仍为** `http://127.0.0.1:17890/`）
  - `web/` 下 `npm run dev`（仅启动前端；访问 Vite 输出的地址，例如 `http://127.0.0.1:5173/`）

- **执行流程**：
  1.  `webnet` 模块启动，运行 `WebNetLauncher`。
  2.  `WebNetServer` 创建一个本地 HTTP/WebSocket 服务器（默认 `127.0.0.1:17890`）。
  3.  自动打开系统默认浏览器访问 `http://127.0.0.1:17890/`。
  4.  浏览器加载 `index.html`，并通过 WebSocket 与 `webnet` 通信。

- **核心数据流**：
  - **UI → 模拟**：Web 前端将玩家操作封装为 `Command` (JSON)，通过 WS 发送给 `webnet`。
  - **模拟 → UI**：`webnet` 将游戏状态 `Snapshot` (JSON) 推送给 Web 前端进行渲染。

### 4.2 未来原生 Java 版本 (LibGDX)

- **启动入口**：`./gradlew :lwjgl3:run` (当前已精简为空壳)
- **执行流程**：
  - `lwjgl3` 启动器创建 LibGDX 窗口。
  - `client` 模块将作为“原生客户端”，通过网络协议（与 Web 版相同）连接到 `webnet` 或独立的专用服务器。
  - `ui` 模块将使用 Scene2D 或其他原生 UI 库渲染界面。

  - `java -jar StarAxis.jar`

## 5. 资源依赖（Web 版）

### 5.0 Mod 启用/顺序与 UI 扩展（硬规则）

- **唯一权威**：`gamedata/mods/mod-order.json` 是 Mod **是否读取（启用）** 与 **读取顺序** 的唯一权威。
- **统一口径**：该顺序同时用于：
  - **资源覆盖**：本体 → Mod 顺序覆盖（后加载覆盖先加载）。
  - **i18n 合并**：本体 → Mod 顺序覆盖（后加载覆盖先加载）。
  - **UI 扩展注册表（UI Registry）合并**：本体 → Mod 顺序合并（冲突按后加载覆盖）。
- **UI 扩展边界**：Mod 的“功能/规则”注入必须发生在 `game`（权威模拟）内；Web 前端只负责 UI 渲染与数据展示，不在前端注入会改变游戏结果的逻辑。
- **层级菜单支持**：UI Registry 必须支持层级菜单与多挂载点（Menu Slots），至少包括：
  - `mainMenu`（主菜单）
  - `inGame.sidebar`（游戏内侧边栏）
  - `inGame.context.*`（右键上下文菜单，按场景/实体类型区分）

### 5.1 Web 静态资源
- **HTML/CSS/JS**：由 `webnet` 的 HTTP 服务托管，**仅**从项目根目录 `web/dist/`（前端构建产物）提供。
- **开发态**：前端可独立启动 dev server（独立端口）并通过 HTTP/WebSocket 连接 `webnet`；`webnet` 仍保留托管 `web/dist/` 用于一键启动/发行态。
- **图片/音频等**：同样通过 HTTP 托管，建议放在 `assets/` 目录。

### 5.2 国际化 (i18n) 资源
- **API 驱动**：Web 前端通过 `GET /api/i18n/{lang}` 获取合并后的 JSON 语言包。
- **合并规则**：`webnet` 服务端按“本体 → Mod 顺序”加载并覆盖 `.properties` 文件。
  - 本体：`assets/i18n/`
  - Mods：`gamedata/mods/*/i18n/`
- **Mod 顺序**：由 `gamedata/mods/mod-order.json` 决定。
