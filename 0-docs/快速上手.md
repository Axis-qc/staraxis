## 1. 项目一句话

**StarAxis** 是一个以“单机权威模拟”为中心的 2D 俯视角太空 4X 大战略游戏项目：

- **权威世界状态**：单机进程内维护权威世界状态（未来为 `WorldState`）。
- **客户端职责**：负责窗口/输入/渲染/UI 表现，不决定模拟结果。
- **game**：游戏模拟层，负责游戏实际推进，接收ui层指令影响游戏推进。

## 3. 你需要牢记的 7 条硬规则

1. **模拟层权威**：所有改变游戏结果的逻辑只在模拟层执行。
2. **确定性优先**：相同输入与初始状态必须得到相同结果（为存档对账服务）。
3. **模拟时间驱动**：推进与结算绑定 `simulationTick`（本地模拟 Tick）` / `gameDatetimeDay`，不能由 FPS 驱动。
4. **多核并行是强制项**：可并行计算要拆 Job；但权威写入必须在“落账点”串行化。
5. **双快照口径**：
   - `上一日结算状态（DailySettlementState）`：UI 层展示经济/生产/人口等具有固定结算周期（按“日”）的数据（避免读取计算中间态）。
   - `实时世界状态（RealTimeWorldState）`：战斗、移动、即时事件等实时系统；以及需要即时数据的 UI 展示。
6. **命名/术语统一**：所有字段写法必须一致，正文出现字段必须用 `fieldName`（解释）格式。
7. **代码必须带注释**：所有代码都必须带注释，禁止不写注释。

## 4. 游戏运行逻辑（当前工程口径）

> 本节描述“应用启动链路”和“模块调用关系”，便于快速定位入口与职责边界。

### 4.1 启动链路（lwjgl3 → client → ui → game）

- `lwjgl3`（桌面端启动器）负责创建桌面窗口与启动 LibGDX 应用。
- `client`（客户端应用层）负责组织游戏运行：
  - 启动/管理 UI（调用 `ui` 模块）
  - 启动/驱动游戏模拟（调用 `game` 模块；当前仅接入固定 tick 循环，无实际模拟）
- `ui`（UI 层）只负责 UI 展示与交互（Scene2D），不包含模拟规则。
- `game`（游戏逻辑层）负责权威模拟（当前仅空壳），不依赖渲染库或 UI。

### 4.2 当前可运行入口

- **桌面启动入口**：`lwjgl3/src/main/java/staraxis/lwjgl3/Lwjgl3Launcher.java`
- **客户端应用入口（LibGDX ApplicationListener）**：`client/src/main/java/staraxis/ClientGame.java`

## 5. UI 资源依赖（离线加载）

> UI 必须完全离线加载，不得依赖外网资源。运行时 workingDir 以 `assets/` 为准（`lwjgl3` 已配置）。

### 5.1 Scene2D 皮肤资源（uiskin）

- `assets/ui/uiskin.json`（Scene2D Skin 定义）
- `assets/ui/uiskin.atlas` / `assets/ui/uiskin.png`（Skin 贴图资源）

### 5.2 UI 字体资源（TTF）

- 默认中文字体：`assets/fonts/chinese/AlibabaPuHuiTi-3-65-Medium.ttf`
- UI 会先使用 LibGDX 默认 `BitmapFont` 作为兜底字体，再尝试用 TTF 生成字体并覆盖；若 TTF 生成失败则保持兜底字体，避免启动崩溃。

### 5.3 国际化（i18n）资源

- **语言文件识别**：通过文件名后缀识别语言（例如 `strings_zh.properties`）。
- **扫描路径**：启动时扫描 `assets/i18n/` (基础) 与 `gamedata/mods/*/i18n/` (Mod)。
- **覆盖规则**：按 Mod 加载顺序（当前为目录名排序），后加载的 Mod 会覆盖先加载的。
- **缺失 Key**：若当前语言找不到某个 key，则返回 key 本身。

## 6. 核心数据流（读懂这段就能开始干）

> 注意：本节描述的是“最终目标口径”。当前工程阶段优先打通 UI 主菜单，模拟层尚未接入。

### 6.1 从 UI 层到模拟层

- UI 层把玩家操作封装为 **Command（指令）** 发给模拟层。
- 模拟层校验/排队后，在主循环 tick 内执行该指令，改变权威 `WorldState`。

### 6.2 从模拟层回到 UI 层

- 模拟层把权威变化输出为：

- `实时世界状态（RealTimeWorldState）`
- 用于战斗、移动、即时事件等实时系统；以及需要即时数据的 UI 展示。

- `上一日结算状态（DailySettlementState）`
- 用于 UI 层展示经济/生产/人口等具有固定结算周期（按“日”）的数据。

### 6.3 UI 为什么“看上去慢一拍”

项目采用“日结算 0 点落账”的账本口径：

- UI 面板默认展示的是 **上一日结算状态（DailySettlementState）**。
- 今日正在计算中的账本数据不直接暴露给 UI（避免读到半成品、避免跨线程争用）。

## 7. 当前正在进行的开发任务（截至 2026-01-23 更新于 23:05）

> 本节用于同步当前进行中的主要任务，便于新加入的开发者快速跟进。

### 7.1 任务：声明式 UI 升级为 HTML-like 语义（并完成设置界面模组列表拖拽排序）

- **目标**：将当前“声明式 UI JSON”的布局语义升级为更接近 HTML/CSS 的直觉口径（HTML-like），并基于新语义完成“设置 → 模组”标签页的列表渲染与拖拽排序（松手即写入 `mod-order.json`），且该顺序影响实际 Mod 资源覆盖（后读覆盖）。

- **升级范围（不做向后兼容）**：目前工程内仅有两个 UI JSON 界面，允许一次性升级并同步迁移所有现有 JSON，旧语义不再保留。

- **HTML-like 语义规划（本期落地）**：
  - **默认 block 填充**：容器的直接子元素默认视为 block（块级），在纵向流式布局中默认 `width: 100%`（自动等价为 `fillX + growX`），避免出现“子行宽度小于父容器宽度”的反直觉行为。
  - **布局模型统一**：
    - `container`（布局容器）默认采用“纵向流”（类似 HTML `div` 的文档流）；需要横向布局时显式声明（例如 `layout: row`）。
    - `repeat`（列表容器）默认 block 填充，并且其每个 item 默认 block 填充。
  - **样式抽象（轻量）**：支持 `class`（样式类名）与基础样式合并（优先级：节点显式属性 > class 样式 > 默认值）。
  - **继承（轻量）**：支持常用表现属性的继承（例如 `color`），子节点未显式配置时从父节点继承。

- **迁移策略**：
  - 先升级 `UiFactory`/Schema 支持新语义；
  - 然后迁移现有两个 UI JSON，删除或调整不再需要的显式 `cell.fillX/growX` 等冗余配置；
  - 最后修正 Settings → Mods 列表的列宽/行宽、展开/拖拽交互与持久化。

- **新语义字段清单（本期约定）**：
  - `layout`（布局模式）：
    - 缺省为纵向流（vertical flow）
    - `row` 表示横向流
  - `class`（样式类名，空格分隔）：用于复用样式配置。
  - `style`（内联样式对象）：用于对单个节点覆盖样式（与 `properties` 合并）。
  - `inherit`（是否继承表现属性，boolean）：子节点未显式设置时，从父节点继承（本期先覆盖 `color`）。
  - `display`（显示类型）：本期仅支持 `block`（默认），用于触发“默认撑满父宽”的口径。

- **旧字段废弃（不再使用）**：
  - `horizontal`：已废弃。横向布局统一使用 `layout: row`，禁止继续在 UI JSON 中使用 `horizontal: true`。

- **属性合并与优先级规则（类似 CSS cascade，但更简单）**：
  - **优先级从低到高**：
    - 默认规则（HTML-like 默认值，例如纵向流、block 填充）
    - `class` 样式（按 class 顺序合并，后者覆盖前者）
    - `style`（内联样式）
    - 节点显式 `properties`（最终覆盖，视为最高优先级）
  - **继承规则**：若 `inherit: true`，则在合并后仍未指定的可继承属性（本期 `color`）从父节点继承。

- **当前完成情况（截至 2026-01-23）**：
  - **UIFactory & Schema**：已实现 HTML-like 布局、`class/style/inherit`、`include + params` 组件库机制，并同步放宽 `component.schema.json` 校验规则。
  - **组件库**：`assets/ui/common/components.json` 已收录 `btn-small / divider / divider-vert / row / panel-rounded / scroll-vert` 等常用模板，可被 `include` 复用。
  - **settings.json 迁移**：
    - 移除冗余 `fillX / growX / expand* / fillY` 字段。
    - 所有分隔线使用 `include: divider / divider-vert`。
    - 小按钮统一用 `btn-small`。
    - 模组行容器 `mod_row_template` 使用 `class: mod-row`，并修正 `mod_name` 列为 `cell.grow + fillX`，避免出现列间空洞。
  - **I18nService**：已按 `mod-order.json` 顺序加载，本地化覆盖符合预期。
  - **Mods 列表拖拽（DragAndDrop）**：已切换为使用 LibGDX `DragAndDrop` 机制实现拖拽排序与落盘写入 `gamedata/mods/mod-order.json`（目前仍存在交互与布局细节问题，见下一节“当前情况”）。

- **当前情况（截至 2026-01-23）**：
  - **拖拽预览仍会“脱离列表区域”**：`DragAndDrop` 的 `dragActor` 属于舞台级别的拖拽预览，默认可在屏幕任意位置移动；当前需要在逻辑上将 drop 限制在 `mods_repeat` 列表范围内，并在越界时取消/拒绝 drop。
  - **折叠详情仍可能占用高度**：`mod_detail_template` 即使 `visible=false`，在某些 `Table`/布局组合下仍可能影响 `prefHeight`，导致行间出现多余间隔；需要改为折叠时从父节点 `remove()`，展开时再 `addActor()`，确保不参与布局。

- **下一步规划（截至 2026-01-23）**：
  - **拖拽限制**：在 `Target#drag` 中判断指针是否位于列表区域（`mods_repeat`）内，越界时返回 `false` 并在 `dragStop` 中恢复状态；只允许列表内垂直排序。
  - **折叠高度修复**：展开/折叠不再仅用 `visible`，改为 `remove/addActor`，并在切换后 `invalidateHierarchy()` 触发布局刷新。
  - **交互反馈**：拖拽经过目标行时增加目标高亮/插入位置提示；drop 时根据指针落点决定插入到目标行上方/下方。
  - **回归验证**：拖拽不越界、无闪烁、折叠不留空隙、松手写 `mod-order.json`、重启顺序保持、i18n 覆盖顺序不变。

- **验收标准**：
  - Settings → Mods 列表每行宽度与父容器一致（无“缩短一截”）。
  - 拖拽时有明确的视觉反馈（dragActor 预览 + 目标提示），松手即写入 `gamedata/mods/mod-order.json`，重启后顺序保持。
  - i18n 按新顺序加载，后加载 Mod 能覆盖先加载 Mod 的同 key。
