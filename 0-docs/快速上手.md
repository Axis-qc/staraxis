## 0. 环境与依赖概览

- **Java 版本**：JDK 21（`java.sourceCompatibility = 21`）。
- **构建工具**：Gradle 多模块；已默认应用 `eclipse`、`idea`、`java-library` 插件，并使用 `org.gradle.toolchains.foojay-resolver-convention` 自动解析 JDK。
- **主要 UI 组件 / 库**：
  - LibGDX Scene2D & GDX 核心（`com.badlogicgames.gdx:gdx`）
  - VisUI（`com.kotcrab.vis:vis-ui`）
  - Typing-Label（`com.rafaskoberg.gdx:typing-label`）
  - ShapeDrawer（`space.earlygrey:shapedrawer`）
  - Box2D / Box2DLights（`com.badlogicgames.gdx:gdx-box2d`、`com.badlogicgames.box2dlights:box2dlights`）
  - FreeType 字体支持（`com.badlogicgames.gdx:gdx-freetype`）
- **其他关键依赖**：Artemis-ODB ECS（`net.onedaybeard.artemis:artemis-odb`）、Regexodus 正则（`com.github.tommyettinger:regexodus`）、Blade-Ink 剧本解析（`com.bladecoder.ink:blade-ink`）、Apache Commons-Collections 等。
- **可选插件**：当 `enableGraalNative = true` 时，使用 `io.github.berstanio:gdx-svmhelper-annotations` 提供 GraalVM 原生镜像辅助。

## 1. 项目一句话

**StarAxis** 是一个以“JAVA为主编写的服务端权威模拟”为中心的太空4X大战略游戏项目：

- 服务端维护世界权威状态并推进模拟时间。
- 客户端只负责输入与表现（可做预测，但不决定结果）。
- 联机语义以 Command / Event / Snapshot 为核心（具体实现方案当前为推荐口径，仍可调整）。

## 3. 你需要牢记的 6 条硬规则

1. **模拟层权威**：所有改变游戏结果的逻辑只在模拟层执行。
2. **确定性优先**：相同输入与初始状态必须得到相同结果（为存档对账服务）。
3. **模拟时间驱动**：推进与结算绑定 `simulationTick`（本地模拟 Tick）` / `gameDatetimeDay`，不能由 FPS 驱动。
4. **多核并行是强制项**：可并行计算要拆 Job；但权威写入必须在“落账点”串行化。
5. **双快照口径**：
   - `上一日结算状态（DailySettlementState）`：UI 层展示经济/生产/人口等具有固定结算周期（按“日”）的数据（避免读取计算中间态）。
   - 实时世界状态（RealTimeWorldState）`：斗、移动、即时事件等实时系统；以及需要即时数据的 UI 展示。
6. **命名/术语统一**：所有字段写法必须一致，正文出现字段必须用 `fieldName`（解释）格式。

## 4. 核心数据流（读懂这段就能开始干）

### 4.1 从UI层到模拟层

- UI层把玩家操作封装为 **Command（指令）** 发给模拟层。
- 模拟层校验/排队后，在主循环 tick 内执行该指令，改变权威 `WorldState`。

### 4.2 从模拟层回到UI层

-模拟层把权威变化输出为：

-实时世界状态（RealTimeWorldState）
-用于战斗、移动、即时事件等实时系统；以及需要即时数据的 UI 展示。

-上一日结算状态（DailySettlementState）
-用于 UI 层展示经济/生产/人口等具有固定结算周期（按“日”）的数据。

### 4.3 UI 为什么“看上去慢一拍”

项目采用“日结算 0 点落账”的账本口径：

- UI 面板默认展示的是 **上一日结算状态（DailySettlementState）**。
- 今日正在计算中的账本数据不直接暴露给 UI（避免读到半成品、避免跨线程争用）。
