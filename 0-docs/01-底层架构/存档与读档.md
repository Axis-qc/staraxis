# 存档与读档系统（单机模式，最终敲定）

> 目标：定义存档的**权威结构**、**写入与读取流程**、**版本校验规则**、**自动/手动存档策略**与**失败处理口径**。
> 
> 本文档为单机模式下存档系统的唯一权威来源，取代所有历史文档。

---

## 1. 核心结论（先读这一段即可落地）

- **存档文件**：扩展名建议为 `.sav`，但内部必须包含自描述的文件头（版本、校验等）。
- **版本策略**：采用“有限向前兼容”：
  - 存档必须记录 `gameVersion`。
  - 新版本游戏可加载旧版本存档（但需提示）。
  - 旧版本游戏**绝不能**加载新版本存档。
- **存档内容**：必须完整保存可恢复模拟的 `WorldState`，并与 `DailySettlementState`（上一日结算态）分离。
- **写入流程**：必须采用“临时文件 + 原子替换”策略，保证写入安全。
- **自动存档**：按“游戏日”间隔触发，并有数量上限。

---

## 2. 存档版本策略（有限向前兼容）

### 2.1 `gameVersion`（版本判定口径）

- **`gameVersion`**：推荐采用语义化版本（SemVer），格式为 `MAJOR.MINOR.PATCH`（例如 `1.2.3`）。
- **写入**：每次保存时，必须写入当前运行的游戏版本 `currentGameVersion`。
- **读取**：加载时，必须用于兼容性判定。

### 2.2 兼容性规则（强制）

- 若 `save.gameVersion == currentGameVersion`（版本一致）：允许加载。
- 若 `save.gameVersion < currentGameVersion`（存档更旧）：
  - **允许加载**，但必须在 UI 明确提示“版本不一致”。
  - **提示文案建议**：“存档版本（`save.gameVersion`）与当前版本（`currentGameVersion`）不一致，已尝试加载。若出现异常建议开新档。”
- 若 `save.gameVersion > currentGameVersion`（存档更新）：
  - **拒绝加载**。
  - **提示文案建议**：“该存档版本（`save.gameVersion`）高于当前版本（`currentGameVersion`），当前版本无法加载新存档。请升级游戏后再尝试。”

> **注**：本项目不维护自动迁移链。若某次更新为破坏性更新（如 `MAJOR` 版本变更），应在发布说明中明确该版本将拒绝加载更旧存档。

---

## 3. 存档格式选择（推荐方案）

- **推荐主格式**：**二进制（MessagePack/CBOR）**。体积比 JSON 小，读写更快，且结构灵活。
- **建议保留调试导出**：支持将 `SaveFile` 导出为 JSON 格式，仅用于调试，不作为正式存档。
- **不推荐**：纯 JSON 作为正式存档（体积大、解析慢、精度易出问题）。

---

## 4. 存档文件结构（敲定）

### 4.1 顶层结构（字段带中文注释，强制）

```ts
interface SaveFile {
  meta: SaveMeta;             // 元信息：版本、时间、展示摘要
  world: WorldStateSave;      // 世界权威状态（用于恢复模拟推进）
  dailySnapshot: DailySnapshotSave; // 上一日快照（供 UI 直接读取）

  // 可选：索引/缓存（不影响规则，可丢弃重建）
  indices?: SaveIndices;
}

interface SaveMeta {
  gameVersion: string;        // 存档版本号（必须写入，用于读取判定）
  createdAtUnixMs: number;    // 创建时间（用于 UI 展示）
  updatedAtUnixMs: number;    // 最近保存时间（用于 UI 展示）
  saveName: string;           // 存档名（用于 UI 展示）

  // 展示摘要（不影响规则）
  summary?: {
    gameDatetimeDay: number;  // 当前日序号（用于展示进度）
    simulationTick: number;   // 当前模拟 tick（用于展示）
  };

  // 存档类型（用于区分自动/手动/退出前保存等）
  saveType: 'Auto' | 'Manual' | 'Shutdown';
}

interface WorldStateSave {
  simulationTick: number;     // 模拟 tick（恢复对齐基线）
  gameDatetimeDay: number;    // 日序号（恢复日历）
  accGameHoursInDay: number;  // 当日累计游戏小时数

  // 其余权威数据（实体/派系/经济/战斗状态等）
  // 具体字段由 WorldState 的权威结构决定
}
```

## 5. 写入流程（保存）（强制）

### 5.1 保存触发点

- **手动保存**：玩家主动触发，保存数量不受限制。
- **自动保存**：按“游戏日间隔”触发，见第 6 节。
- **停机保存**：游戏退出前触发一次保存。

### 5.2 保存的一致性与线程模型

- 存档内容必须来自主循环线程的稳定点（推荐在 `Commit` 阶段之后），通过复制/冻结数据快照，避免边写边改。
- 落盘 I/O 应由独立存储线程执行，避免阻塞主循环。

### 5.3 原子写入（强制）

- 必须采用“**临时文件 + 原子替换**”流程：
  1. 写入 `save.tmp`
  2. flush/fsync
  3. rename 为正式文件名（`.sav`）
- 写入失败时，不得破坏旧存档。

---

## 6. 自动存档策略（敲定）

### 6.1 自动保存档位

- 自动保存间隔以 `gameDatetimeDay`（日序号）为准，提供四个档位：
  - `7`（每 7 游戏日）
  - `30`（每 30 游戏日）
  - `90`（每 90 游戏日）
  - `180`（每 180 游戏日）

### 6.2 触发行为

- 当到达保存间隔时，**自动暂停**主循环推进，执行一次自动保存，保存完成后**自动恢复**。

### 6.3 自动存档保留数量

- 自动存档最多保留 **3** 个。超出后自动删除最旧的自动存档。

---

## 7. 读取流程（读档）（强制）

1. 读取文件并反序列化为 `SaveFile`。
2. 校验必要字段存在（`meta.gameVersion`、`world.simulationTick` 等）。
3. 执行版本判定（见第 2 节）。
4. 恢复 `WorldState` 与权威时间轴：`simulationTick`、`gameDatetimeDay`、`accGameHoursInDay`。
5. 恢复 `DailySnapshot`（用于 UI 查询）。
6. 进入正常游戏流程。

---

## 8. 失败处理（敲定）

- **读档失败**：提示“存档损坏/不可读”，拒绝加载。
- **版本过新**：提示“请升级版本后再加载”，拒绝加载。
- **自动保存失败**：
  - 记录日志。
  - 解除暂停并恢复游戏。
  - 向玩家提示“自动保存失败，请稍后重试或手动保存”。
