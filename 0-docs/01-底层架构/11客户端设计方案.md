# 客户端设计方案（单机模式，最终敲定，可直接落地）

> 本文档目标：给出一套**可直接实现**的 StarAxis 单机客户端架构与界面流程方案。
>
> 设计约束（强制）：
> - **项目定位（强制）**：本项目为 **2D 俯视角太空 4X 大战略**；不考虑 3D 渲染。
> - **单机权威（强制）**：本地进程内 `WorldState` 是唯一权威世界状态。
> - **内存交互（强制）**：模拟层将数据写入内存世界状态；UI 与渲染只通过 `id` + 只读视图/快照读取世界数据。
> - **ID 索引模型（强制）**：所有实体通过 ID 引用（如 `countryId`、`planetId`、`fleetId` 等）。
> - **对象引用生命周期（强制）**：对象引用生命周期为 **一个 tick**；跨 tick 必须仅持有 ID 或可失效引用结构。
> - **写入唯一入口（强制）**：除模拟层外，任何层不得写入 `WorldState`。UI 只能发送用户意图 `Intent/Command`，由模拟层在 tick 内消费并落账。
> - **UI 独立系统（强制）**：UI 必须是独立系统，界面在加载期完成创建（预构建），运行时只做数据绑定/状态切换，禁止“运行时临时拼 UI”。
> - **双层叠加渲染（强制）**：窗口分为两层叠加渲染：下层为 OpenGL 渲染的 2D 游戏画面，上层为 JCEF 嵌入 WebView 使用 HTML 渲染的游戏 UI。
>
> 参考：
> - `0-docs/总目录.md`
> - `0-docs/01-底层架构/模拟时间.md`（模拟时间与日结算的唯一权威口径）

---

## 0. 单机客户端在整体架构中的位置

单机客户端负责：

1. **启动与界面导航**：主菜单/流程切换/弹窗。
2. **世界状态与模拟推进**：管理 `WorldState`，驱动 `simulationTick` 推进。
3. **系统模块调度**：启动并驱动经济/战斗/AI 等系统在模拟节拍下运行。
4. **渲染与交互**：渲染世界与 UI，处理输入。
5. **存档读写**：保存/加载世界状态文件（存档系统具体设计见专门文档）。

> 本文档描述“客户端侧流程与边界”，并明确渲染分层：下层 OpenGL 原生画面 + 上层 JCEF WebView（HTML UI）。

---

## 1. 客户端分层（建议）

客户端代码建议按以下层次组织（尽量避免跨层直接写入内部状态）：

- **App Layer（应用层）**
  - 负责启动、页面导航（主菜单/新游戏/加载/设置等）、生命周期管理（退出、暂停）。

- **World Layer（世界层）**
  - 维护 `WorldState`（权威世界状态，常驻内存）。
  - `WorldState` 只能由模拟层读写；禁止 UI/渲染层读取。
  - 对外只发布只读状态：`RealTimeWorldState` 与 `DailySettlementState`（均为只读）。

- **Simulation Layer（模拟层）**
  - 维护并推进 `simulationTick` / `simulationDay` 等模拟时间。
  - 统一使用 `dtGameHours`（游戏小时增量）推进各系统模块。
  - `timeScale`、跨日判定与日结算触发口径以《模拟时间.md》为准。

- **Render Layer（渲染层）**
  - 将世界状态的派生表现态渲染到屏幕。
  - 渲染层必须仅从 `RealTimeWorldState` 按 `id` 索引读取数据；禁止读取 `WorldState`，禁止持有权威实体对象引用。

- **UI System（UI 独立系统）**
  - 独立于世界渲染对象的 HUD/面板系统。
  - **渲染技术**：采用 JCEF 嵌入 WebView，使用 HTML/CSS/JS 技术栈渲染。UI 层叠加在 OpenGL 原生画面之上。
  - **资源位置**：UI 资源位于 `assets/ui/` 目录下，并按功能分类组织（如 `gameui/`, `hud/` 等）。
  - **数据交互**：UI 通过订阅数据源（例如选择态、摘要快照）来更新显示，并通过与宿主的桥接通道发送用户意图。

### 1.1 UI 数据交互（强制）

- **读取通道（Read）**：
  - 经济/生产/人口等“非实时属性”：UI 必须读取 `DailySettlementState`。
  - 战斗/移动/即时事件等“实时属性”：UI 必须读取 `RealTimeWorldState`（按 `id` 索引读取）。
  - **禁止**：UI 读取 `WorldState`。
- **缓存规则（Cache）**：UI 只允许缓存 `id` 与 UI 自身状态（选中态、面板开关、滚动位置等），禁止缓存实体对象引用。
- **写入通道（Write）**：所有 UI 操作必须转换为 `Intent/Command` 发送给宿主（桥接通道），进入指令队列；模拟层在每个 tick 开始时批量取出并按入队顺序执行，更新 `WorldState`，并在 tick 结束时采用**双缓冲 + 全量填充发布**更新 `RealTimeWorldState`。禁止 UI 直接执行会改变游戏结果的规则计算。

## 2. 游戏世界状态分层（强制）

为同时满足“实时系统需求”与“UI 稳定展示需求”，世界内存数据必须分为三层状态/快照，并与模拟时间口径一致：

- `simulationTick`：驱动实时系统更新节拍。
- `accGameHoursInDay` / `dtGameHours` / `timeScale`：驱动跨日判定与日结算触发。

上述字段的计算与触发规则以《模拟时间.md》为准。

### 2.1 权威世界状态（WorldState）

- **用途**：游戏运行时的唯一权威世界状态容器，常驻内存；用于模拟层计算与控制游戏推进。
- **读写权限（强制）**：`WorldState` 只能由模拟层读写；禁止 UI/渲染层读取。

### 2.2 实时世界状态（RealTimeWorldState）

- **用途**：用于战斗、移动、即时事件等实时系统；以及需要即时数据的 UI 展示。
- **更新节拍**：每个 `simulationTick` 结束时更新。
- **更新方式（强制）**：采用**双缓冲 + 全量填充发布**：每个 `simulationTick` 结束时，模拟层在 `inactive` 缓冲中对
  `RealTimeWorldState` 进行全量填充；填充完成后进行一次性交换（swap）发布为 `active`。
- **读写权限（强制）**：`RealTimeWorldState` 为只读，对外按 `id` 索引读取；禁止任何系统绕过模拟层直接写入。

### 2.3 上一日结算状态（DailySettlementState）

- **用途**：用于 UI 层展示经济/生产/人口等具有固定结算周期（按“日”）的数据。
- **更新节拍**：每游戏日结算周期生成/更新，代表“上一日已落账结果”。
- **读写权限（强制）**：`DailySettlementState` 为只读；用于“不需要实时属性”的 UI 数据展示。

### 2.4 控制流闭环（强制）

- **玩家控制**：玩家操作必须以 `Intent/Command` 形式从 UI 发送给模拟层。
- **模拟推进**：模拟层在每个 tick 开始时从指令队列批量取出指令并按入队顺序执行，更新 `WorldState`。
- **对外发布**：每个 `simulationTick` 结束时，模拟层采用**双缓冲 + 全量填充发布**更新 `RealTimeWorldState`（`inactive` 填充完成后 swap 为 `active`）；跨日结算完成后更新 `DailySettlementState`。
- **渲染/UI 读取**：渲染层与 UI 层仅从 `RealTimeWorldState` / `DailySettlementState` 按 `id` 索引读取。

## 3. 启动流程与初始界面（主菜单）

### 3.1 启动进入主菜单

- 启动客户端后，默认进入**主菜单（开始界面）**。
- 主菜单需要显示以下入口（顺序可按 UI 设计调整）：
  - **新游戏**
  - **加载游戏**
  - **多人游戏（未来规划）**
  - **舰船设计器**
  - **设置**
  - **退出游戏**

### 3.2 主菜单入口行为

- **新游戏**：进入“国家选择界面”。
- **加载游戏**：进入“存档管理界面”。
- **多人游戏（未来规划）**：弹出“开发中”提示。
- **舰船设计器**：进入“舰船设计界面”。
- **设置**：进入“游戏设置界面”。
- **退出游戏**：点击后直接退出客户端。

---

## 4. 新游戏流程（国家选择 → 世界生成 → 进入游戏）

### 4.1 国家选择界面

目标：玩家选择或创建一个国家，然后进入世界生成。

功能要求：
- 支持 **选择预设国家**。
- 支持 **创建新国家**（最小字段可包括名称、旗帜/颜色、初始特性等）。
- 确认后进入“世界生成界面”。

产出：
- `countryId`（玩家国家 ID）
- 国家基础设定数据（写入 `WorldState` 或新游戏初始化上下文）

### 4.2 世界生成界面

目标：玩家调整世界生成参数，确认后生成世界并进入游戏。

功能要求：
- 展示并允许调整世界生成参数（示例）：
  - 星系数量/密度
  - 星球数量范围
  - 资源丰度/分布
  - 初始势力数量
  - 随机种子（可选：可输入/可随机）
- 点击“开始生成”后进入世界生成过程。

产出：
- 新的 `WorldState`（包含星区/恒星系/星球等实体集合，以 ID 索引）
- 初始 `simulationTick`/`simulationDay`

### 4.3 世界生成与进入游戏

- 世界生成完成后：
  1. 初始化核心系统模块（经济/战斗/外交/AI 等）。
  2. 启动模拟时间推进（开始递增 `simulationTick`）。
  3. 切换到“正常游戏流程”（进入主游戏界面）。

---

## 5. 加载游戏流程（存档管理 → 读档 → 进入游戏）

### 5.1 存档管理界面

目标：列出存档并提供基本管理能力。

功能要求：
- 列表显示存档条目（如存档名、时间、游戏进度摘要）。
- 支持：
  - 选择存档并加载
  - 删除/重命名（可选）

### 5.2 读档与进入游戏

- 读取存档后：
  1. 从存档文件恢复 `WorldState`（以 ID 索引的数据结构）。
  2. 恢复 `simulationTick`/`simulationDay`。
  3. 初始化/恢复系统模块运行状态。
  4. 进入“正常游戏流程”（主游戏界面）。

> 存档系统具体格式、版本迁移、原子性等要求见《存档系统》专门文档。

---

## 6. 多人游戏（未来规划）

- 当前点击“多人游戏”直接弹出 **开发中** 提示。
- 不进入任何实际流程。

## 7. 舰船设计器（游戏外蓝图编辑）

目标：允许玩家在游戏外设计舰船蓝图，并在游戏内使用。

功能要求：
- 进入舰船设计界面后：
  - 新建/编辑/保存舰船蓝图
  - 管理蓝图列表
- 蓝图数据应与游戏存档数据解耦：
  - 蓝图可作为独立资源文件或独立存档域（具体由“舰船蓝图系统”文档定义）。

---

## 8. 设置（基础图形/系统设置）

目标：提供基础游戏设置。

建议包含（不限于）：
- 渲染分辨率
- 最大帧数
- 是否全屏
- 画面质量/图形选项
- 音量/输入等基础设置（可选）

---

## 9. 退出游戏

- 点击“退出游戏”后直接退出客户端。

---

## 10. 正常游戏流程（进入游戏后）

本文档只给出单机模式下的最低边界：

- 游戏进行时：
  - `simulationTick` 按固定节拍推进。
  - 实时系统（战斗/移动等）更新 `RealTimeWorldState`。
  - 日结算系统基于 `accGameHoursInDay` 的跨日判定周期性生成/更新 `DailySettlementState`。
  - 渲染/UI 从对应的数据层读取数据展示。

---

## 11. 最小验收清单

- 启动进入主菜单，显示 6 个按钮：新游戏、加载游戏、多人游戏（开发中）、舰船设计器、设置、退出游戏。
- 新游戏流程可从：国家选择 → 世界生成参数 → 生成世界 → 进入主游戏流程。
- 加载游戏进入存档管理界面，选择存档后进入主游戏流程。
- 多人游戏按钮弹“开发中”提示。
- 舰船设计器进入独立设计界面。
- 设置界面可修改基础图形设置。
- 退出游戏可直接退出客户端。
