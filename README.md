# StarAxis（星轴）

一个基于 [libGDX](https://libgdx.com/) 框架开发的太空战略游戏，使用 [gdx-liftoff](https://github.com/libgdx/gdx-liftoff) 生成项目模板。

本项目是一个类《群星》(Stellaris) 的 4X 太空战略游戏，结合宏观大战略管理与微观舰船手控战斗。

## 项目结构

- `core`: 核心模块，包含所有平台共享的应用逻辑
- `lwjgl3`: 桌面平台主模块，使用 LWJGL3（旧文档中称为 'desktop'）
- `shared`: 客户端和服务端共享的数据模型和接口
- `server`: 服务端模块，负责游戏模拟演算

## 构建与运行

本项目使用 [Gradle](https://gradle.org/) 管理依赖。项目已包含 Gradle Wrapper，可直接使用 `gradlew.bat`（Windows）或 `./gradlew`（Linux/Mac）运行 Gradle 任务。

### 常用 Gradle 任务

- `build`: 构建所有项目的源代码和归档文件
- `clean`: 清理 `build` 文件夹（包含编译后的类和构建的归档文件）
- `lwjgl3:run`: 启动应用程序
- `lwjgl3:jar`: 构建可运行的 jar 文件，位于 `lwjgl3/build/libs`
- `test`: 运行单元测试
- `idea`: 生成 IntelliJ IDEA 项目文件
- `eclipse`: 生成 Eclipse 项目文件
- `cleanIdea`: 删除 IntelliJ IDEA 项目数据
- `cleanEclipse`: 删除 Eclipse 项目数据

### 常用 Gradle 参数

- `--continue`: 遇到错误时继续执行任务
- `--daemon`: 使用 Gradle 守护进程运行任务
- `--offline`: 使用缓存的依赖归档文件
- `--refresh-dependencies`: 强制验证所有依赖（对快照版本有用）

> 注意：大多数非特定项目的任务都可以使用 `name:` 前缀运行，其中 `name` 应替换为特定项目的 ID。例如，`core:clean` 仅清理 `core` 项目的 `build` 文件夹。

# 游戏大纲

## 1. 开发规范与原则

### 1.1 语言规范
- **语言**：使用中文进行对话与代码注释

### 1.2 代码设计原则
- **避免重复**：需要新方法时先查询是否已存在类似方法/字段
- **模块化设计**：便于修改和维护
- **禁止硬编码**：禁止硬编码和硬枚举
- **命名规范**：在名字/字段后面用括号简单说明其用途
- **文件头注释**：说明文件作用、使用的接口、提供的接口及作用

### 1.3 架构与兼容性
- **版本兼容**：不需要兼容旧版本
- **扩展性**：考虑未来扩展和 Mod 支持
- **客户端-服务端分离**：
  - 服务端负责模拟演算
  - 客户端负责渲染及交互
  - 为未来多人模式和服务器端奠定基础
- **UI 层分离**：UI 层单独层级，不在游戏逻辑内构建

### 1.4 游戏循环
- **性能优化**：非必要少用每帧更新
- **时间系统**：游戏推进要跟随游戏模拟时间

### 1.5 工作流程
- **模块隔离**：禁止对任务外其他模块进行随意修改
- **变更控制**：禁止在未经允许的情况下进行大范围修改
- **命令使用**：禁止在测试以外频繁使用终端命令
- **计划先行**：先制定修改计划，然后再一步一步开始修改

## 2. 技术标准

### 2.1 坐标系（世界角度）

**方向定义**：
  - 0°：向右（→）
  - 90°：向上（↑）
  - 180° / -180°：向左（←）
  - -90°：向下（↓）

**轴向定义**：
  - X 轴：向右为正（+X），向左为负（-X）
  - Y 轴：向上为正（+Y），向下为负（-Y）

### 2.2 人口与岗位单位约定

**内部存储**：
- 所有人口相关字段以 **"百万人"** 为单位
- 1 个体 = 0.000001 百万人

**岗位消耗**：
- 默认每个岗位槽位需要 1 个体人口

**建筑容量**：
- `岗位槽位数` × `workersPerSlot`（例：100 槽位 ≈ 100 个体人口）

**UI 显示**：
- 通过辅助函数转换为 **个 / K / M / G** 显示
- K = 1,000，M = 1,000,000，G = 1,000,000,000

## 3. 游戏概况

### 3.1 游戏类型
- **类型**：类《群星》(Stellaris) 的 4X 太空战略游戏
- **核心体验**：宏观的大战略管理 + 微观的舰船手控与战斗指挥

### 3.2 视觉表现
- **2.5D 模式**：舰船、空间站等实体使用 2D 平面（可交互）
- **3D 渲染**：恒星、星球、背景空间使用 3D 渲染（可交互）

## 4. 宇宙与地图系统

### 4.1 星图结构
- **大地图**：由六边形"星域单元"拼接而成
- **区域类型**：每个六边形区域可以是星系、深空、星云等

### 4.2 区域类型

**星系区域**：
- 包含恒星、行星及其轨道建筑

**深空区域**：
- 空无一物，用于远程航道与伏击

**星云区域**：
- 干扰探测，可采集特殊资源

**风暴区域**：
- 宇宙风暴，进入可能受损

**深空资源区**：
- 散布的额外资源点（星系内稀少资源的补充）

### 4.3 星系内部结构

**中心**：
- 恒星（A/B/O型、脉冲星、红矮星、黑洞等）

**引力范围**：
- 允许建造太空建筑（采矿站、防御平台、空间站、探测器等）

**边缘**：
- 可修建星际高速航道/环形加速器，连接其他星系、加速航行

### 4.4 星球分类

**有大气行星**：
- 大陆、海洋、荒漠、极地等

**无大气行星**：
- 小行星、岩石行星等

### 4.5 地表结构
- **网格系统**：采用六边形 + 五边形网格构成球面
- **地形类型**：平原、高原、山脉、森林、荒漠、浅海、深海等

## 5. 行星与城市建设

### 5.1 殖民与发展
- **殖民地建立**：在区块内建立殖民地，逐渐发展为城市
- **城市功能**：提供住房和岗位，人口填充岗位，消耗原料产出资源
- **城市成长**：城市规模随时间增长，地表灯光随规模增强
- **多城市系统**：一个星球可以有多个城市

### 5.2 区划功能

**城市区**：
- 提供住房与人口容量，需电力

**电力区**：
- 发电，支持周边运作

**农业区**：
- 生产粮食/畜牧，依赖肥沃土地

**采矿区**：
- 产出矿物，依赖地质储量

**蓄能区**：
- 提高能源存储上限，需要连接电力网络

**海洋区**：
- 海上发电/居住/养殖/渔业/海上蓄能等

### 5.3 基础设施

**电力网络**：
- 相邻区划自动连通，断电导致停工

**行星护盾**：
- 消耗能源充能，过低可能触发投降
- 被毁后轨道轰炸直接破坏地表

## 6. 经济与贸易系统

### 6.1 经济循环
- **核心链**：人口 → 岗位 → 资源 → 舰船/建筑维护/人口需求
- **消耗机制**：舰船消耗补给/维护；人口消耗生活资源

### 6.2 产业链分级

**初级产业**：
- 矿物采集（例：铁矿 → 钢铁）

**中级产业**：
- 工业品（例：钢铁 → 机械零件）

**高级产业**：
- 战略制品（例：零件 + 氦-3 → 聚变堆）

### 6.3 资源管理

**产出来源**：
- 地表区划 + 轨道建筑（小行星平台、气态采集环、恒星能源站）

**运输系统**：
- 运输舰负责星际运输（初始 5 艘，约 1k 容量/艘，可升级）

### 6.4 市场体系

**行星市场**：
- 每个星球独立市场，显示存储/产出/消耗/进出口
- 盈余自动出口，短缺自动进口

**星际市场**：
- 订单/合约交易（舰船合金、武器等）
- 国家间物物交换/信用结算

**价格机制**：
- P = 基础价 × (1 + 需求/供给)（参考《维多利亚 3》）

## 7. 舰船与战斗系统

### 7.1 舰船体系

**体型分级**：
- 小型 → 中型 → 大型 → 超大型 → 泰坦级

**设计系统**：
- 模块化拼装，可预设模块（特殊舰船）

**特殊类型**：
- **生物舰船（蜂巢）**：生物质修复，寄生夺船
- **补给舰**：隐形/低可见，无人机补给

### 7.2 港口等级
- **轨道港口**：S → M → L → XL → T，限制可造舰船尺寸

### 7.3 航行与引擎

**恒星际航行**：
- 空间扭曲/跳跃
- 大舰依赖跳跃，易被"空间干扰器"限制

**星系内航行**：
- 短距跳跃（突袭），可被干扰压制

**干扰器系统**：
- 对大船效果显著，需护航舰处理干扰源

### 7.4 武器与防御

**能量武器**：
- 无弹药，高能耗，破盾难（0%穿透），毁船快

**动能武器**：
- 需弹药，能耗低，穿盾约 50%

**导弹**：
- 超远制导，需扫描支援，基础命中 50%

**防御系统**：
- **护盾**：硬化抵消穿透，承受力抗高伤
- **装甲**：等级差减伤机制（高1级减伤约25%）

**命中机制**：
- 超出"最佳射程"衰减，保留最低命中

### 7.5 补给机制
- **战斗消耗**：战斗消耗弹药/食物
- **补给范围**：脱离补给范围或耗尽会导致战斗力剧降
- **补给来源**：本土/盟友境内可由运输舰补给，深空依赖补给舰

## 8. 空间建筑与设施

### 8.1 采集设施
- **气态轨道采集平台**：可升级为采集环

### 8.2 轨道船坞
- **可升级环形结构**
- **军用港**：建造/维护/补给舰队
- **民用港**：提供运输舰

### 8.3 交通设施
- **太空航道**：星系间高速通道
- **环形加速器**：星系间高速通道

## 9. 政治与外交

### 9.1 政体类型

**独裁/帝制**：
- 直接控制，领袖加成，效率依赖领袖

**民主/寡头**：
- 派系划分，母星由派系掌控
- 资源独立，市场共享

**机械格式塔**：
- 全自动，耗能大，算力限制产能

**蜂巢思维**：
- 依赖生物质维护子个体，短缺导致崩溃

### 9.2 战争与外交

**占领机制**：
- 占领方承担开支，仅获取盈余

**赔款系统**：
- 双倍成本计算，增加后果感

**信用体系**：
- **守约/宣战**：维护信用
- **突袭/毁约**：降低信用
- **信用影响**：影响交易接受度与贷款利率
