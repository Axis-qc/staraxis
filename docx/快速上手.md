# StarAxis 快速上手（给 AI 对话 / 新开发者）

> 目标：用一页文档说明“这是什么项目、权威规则在哪里、从哪里开始读、怎么不踩坑”。

---

## 1. 项目一句话

**StarAxis** 是一个以“JAVA为主编写的服务端权威模拟”为中心的太空策略/经营/战斗类项目：

- 服务端维护世界权威状态并推进模拟时间。
- 客户端只负责输入与表现（可做预测，但不决定结果）。
- 联机语义以 Command / Event / Snapshot 为核心（具体实现方案当前为推荐口径，仍可调整）。

## 3. 你需要牢记的 6 条硬规则

1. **服务端权威**：所有改变游戏结果的逻辑只在服务端执行。
2. **确定性优先**：相同输入与初始状态必须得到相同结果（为回放/存档/联机对账服务）。
3. **模拟时间驱动**：推进与结算绑定 `serverTick` / `simulationDay`，不能由 FPS 驱动。
4. **多核并行是强制项**：可并行计算要拆 Job；但权威写入必须在“落账点”串行化。
5. **双快照口径**：
   - `DailySnapshot`（上一日快照）：UI 只读它（避免读取计算中间态）。
   - `RealtimeSnapshot`（实时快照）：战斗/态势等高频系统使用它。
6. **命名/术语统一**：所有字段写法必须一致，正文出现字段必须用 `fieldName`（解释）格式。

## 4. 核心数据流（读懂这段就能开始干）

### 4.1 从客户端到服务端

- 客户端把玩家意图封装为 **Command（指令）** 发给服务端。
- 服务端校验/排队后，在主循环 tick 内执行该指令，改变权威 `WorldState`。

### 4.2 从服务端回到客户端

- 服务端把权威变化输出为：
  - **Event（事件）**：增量变化（推荐可靠传输）。
  - **Snapshot（快照）**：强制对齐状态（首次进入/重连/追帧失败等）。

### 4.3 UI 为什么“看上去慢一拍”

项目采用“日结算 0 点落账”的账本口径：

- UI 面板默认展示的是 **上次结算完成后的 `DailySnapshot`**。
- 今日正在计算中的账本数据不直接暴露给 UI（避免读到半成品、避免跨线程争用）。
