# 客户端预测与平滑处理（视觉层）

> 版本：V1 · 2026-01-12
> 
> 本文档描述 **StarAxis** 客户端在“仅做视觉预测”模式下的实现口径。客户端不参与权威逻辑计算，仅在本地渲染层对坦帧间位置进行外推；一旦收到服务端权威坐标并检测到明显偏移，则立即将对象**整体平移**到权威坐标（无插值拉回），确保数值与判定始终以服务端为准。

---

## 1. 术语

| 术语 | 说明 |
|------|------|
| Authority / 权威 | 由服务端计算、确认并广播给客户端的最终状态。 |
| Visual Prediction / 视觉预测 | 客户端仅根据上一次收到的权威状态 + 上报的本地输入，对渲染层做简单外推；不在本地执行游戏逻辑。 |
| Reconcile / 对账 | 客户端收到下一包权威数据后，将本地对象坐标直接对齐到权威结果。 |
| Correction Warp / 纠正平移 | 当本地渲染坐标与权威坐标的距离超过阈值，立刻把对象平移到权威位置，无动画插值。 |

---

## 2. 设计原则

1. **权威第一**：任何时间点，服务端坐标是唯一可信来源；客户端数值仅用于画面流畅。  
2. **零逻辑副本**：客户端不重演服务端逻辑，避免两套实现的确定性风险；仅做位置外推。  
3. **简单可验证**：偏移判定逻辑尽可能简单，方便日志与回放复现。  
4. **可选插值层**：若后续需要平滑拉回，可在视觉层增加 Lerp，但不改变本规范“数值瞬移”语义。

---

## 3. 数据结构

```ts
interface SnapshotMsg {
    tick: number;            // 权威 tick
    id: string;              // 实体唯一 ID
    posGU: Vector3d;         // GU 单位权威坐标
    velGUPerTick: Vector3f;  // 可选：服务端估计速度，供预测使用
}

interface PredictState {
    lastAuthorityTick: number;
    lastAuthorityPos: Vector3d;
    predictedPos: Vector3d;   // 当前帧用于渲染的坐标
}
```

---

## 4. 客户端 Tick 流程

```mermaid
graph TD
    A[收到权威 SnapshotMsg] --> B[更新 lastAuthorityPos/tick]
    B --> C[将 predictedPos = lastAuthorityPos] %% 纠正平移
    C --> D[开始本地视觉预测]
    D --> E[渲染帧]
    E -->|下一权威包| A
```

### 4.1 权威包处理

```pseudo
function onAuthority(snapshot):
    state.lastAuthorityTick = snapshot.tick
    state.lastAuthorityPos  = snapshot.posGU
    state.predictedPos      = snapshot.posGU   // 直接对齐，无插值
```

### 4.2 视觉预测（每渲染帧）

```pseudo
function updateLocalPredict(deltaTime):
    const tickDelta = currentTick - state.lastAuthorityTick
    // 仅做简单线性外推，可选使用 velGUPerTick
    state.predictedPos += snapshot.velGUPerTick * tickDelta
```

> ⚠️ **注意**：若 `velGUPerTick` 缺失，可直接跳过预测（保持权威坐标），由客户端输入驱动相机或 UI 动画即可。

---

## 5. 偏移检测与纠正

- **直接拉回**：本规范采用硬对齐策略，不做平滑插值。
- **阈值**：可设置视觉判定阈值，例如 `OFFSET_THRESHOLD_GU = 1.0`；若 `|predictedPos - authorityPos| > threshold` 则触发 `predictedPos = authorityPos`。  
- **日志**：每次纠正需输出日志 `type=CORRECTION`, `entityId`, `offsetGU`, 方便后期诊断。

```pseudo
function reconcileIfNeeded():
    const offset = distance(state.predictedPos, state.lastAuthorityPos)
    if offset > OFFSET_THRESHOLD_GU:
        logCorrection(entityId, offset)
        state.predictedPos = state.lastAuthorityPos
```

---

## 6. 相机与渲染

渲染层一律使用 `state.predictedPos` 转换到屏幕坐标：

```pseudo
screenPos = (state.predictedPos - camera.worldPosGU) / zoom
```

与《坐标系与尺度》中的 `guPerPixel`、`RenderPos` 函数保持一致。

---

## 7. 扩展点

| 扩展 | 说明 |
|-------|------|
| 平滑插值 | 若后期需要视觉平滑，可在 `state.correctionInProgress` 标记后，对渲染坐标做时间 Lerp | 
| 高阶预测 | 可选二阶预测（加速度）或与客户端输入结合，但仍不可影响数值判定 |
| 动态阈值 | 根据速度 / 帧率调整阈值，减少频繁 warp |

---

## 8. 日志字段规范

| 字段 | 类型 | 描述 |
|------|------|------|
| `timestamp` | int64 | 本地时间戳（ms） |
| `tick` | int | 当前渲染 tick |
| `entityId` | string | 实体 ID |
| `offsetGU` | float | 与权威坐标偏移量 |
| `worldPosGU` | Vector3d | 纠正前坐标 |
| `authorityPosGU` | Vector3d | 权威坐标 |

---

## 9. 验收标准

1. 断网 100 ms 内重连：客户端无报错，位置最多瞬移一次。  
2. 高丢包（30%）场景：对象不会长期漂移，最多 `OFFSET_THRESHOLD_GU` 偏差。  
3. 回放比对：同一回放文件多次重播 hash 一致。
