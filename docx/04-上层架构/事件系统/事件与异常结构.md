# 事件与异常结构

> 目标：定义一个标准化的、数据驱动的事件与异常数据结构，为内容创作和Mod扩展提供一个清晰、可复用的框架。

## 1. 核心理念

- **数据驱动**：所有的事件和异常都必须通过外部数据文件（如JSON/YAML）来定义，而不是在代码中硬编码。
- **模块化**：每个事件都是一个独立的单元，有自己的触发条件、描述、选项和效果。
- **可扩展**：Mod可以轻松地添加新的事件，或修改现有事件的触发条件和效果。

---

## 2. 事件/异常数据结构（口径）

每个事件或异常都应由一个包含以下核心属性的数据结构来定义。

```typescript
// 概念性数据结构
interface GameEvent {
  id: string; // 唯一ID，如 "anomaly_gas_giant_life"
  type: 'Event' | 'Anomaly'; // 类型，事件是主动推送给玩家的，异常是需要玩家主动探索的

  title: string; // 事件标题，如“气态巨行星上的生命迹象”
  description: string; // 事件的详细描述文本

  trigger: EventTrigger; // 触发条件（见下文）

  options: EventOption[]; // 玩家可选择的选项列表

  // （可选）事件发生时的即时效果，无论玩家选哪个选项都会触发
  immediate_effects?: Effect[];
}
```

### 2.1 触发条件 (`EventTrigger`)

定义了该事件在什么情况下可能发生。

```typescript
// 概念性数据结构
interface EventTrigger {
  type: 'OnDiscovery' | 'OnColonize' | 'OnTechCompleted' | 'Random'; // 触发类型
  conditions: Condition[]; // 一系列必须满足的条件
  chance?: { // 对于随机事件，定义其发生概率
    base: number; // 基础概率
    modifiers?: { condition: Condition; multiplier: number }[]; // 概率修正
  };
}

// 示例：当一艘科研船完成对一个气态巨行星的扫描时触发
const triggerExample: EventTrigger = {
  type: 'OnDiscovery',
  conditions: [
    { target: 'source_ship', has_component: 'ScienceLab' },
    { target: 'discovered_object', is_type: 'GasGiant' }
  ]
};
```

### 2.2 选项 (`EventOption`)

定义了玩家可以做出的选择。

```typescript
// 概念性数据结构
interface EventOption {
  id: string; // 选项的唯一ID，如 "option_study_life"
  text: string; // 选项的显示文本，如“派遣科学家深入研究”
  tooltip?: string; // （可选）鼠标悬停时显示的额外提示

  // （可选）选择此选项需要满足的额外条件
  requirements?: Condition[];

  effects: Effect[]; // 选择此选项后产生的效果（见下文）
}
```

### 2.3 效果 (`Effect`)

定义了事件或选项所带来的具体后果。效果系统必须是可组合和可扩展的。

```typescript
// 概念性数据结构
interface Effect {
  type: string; // 效果类型，如 "AddResource", "SpawnFleet", "AddModifier"
  params: any; // 该效果所需的参数
}

// 示例：
const effectExamples: Effect[] = [
  { type: 'AddResource', params: { resourceId: 'physics_research', amount: 500 } },
  { type: 'SpawnFleet', params: { at: 'target_object', fleetDesignId: 'ancient_drones' } },
  { type: 'AddModifier', params: { target: 'empire', modifierId: 'galaxy_admiration', duration_days: 365 } }
];
```

---

## 3. 与其他系统的关系

- **数据驱动**：本结构是数据驱动设计的基础，所有事件都应遵循此结构进行数据化存储。
- **脚本系统**：更复杂的效果（如触发后续事件链）可能需要一个轻量级的脚本系统来支持，但这超出了本基础结构的范围，可在后续设计中补充。
