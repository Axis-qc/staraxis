# 模块科技与升级

> 目标：定义舰船模块如何通过科技进行升级，并为“原地升级”机制提供清晰、数据驱动的设计口径。

## 1. 核心理念：科技树驱动的模块进化

- **线性升级**：每个可升级的模块都属于一个明确的**科技树分支**。玩家通过研究该分支上的科技，来解锁该模块的更高级版本。
- **数据驱动**：模块的升级路线完全由数据定义，而不是在代码中硬编码。这使得Mod可以轻松地添加新的升级路径或修改现有路径。

---

## 2. 模块升级的数据结构（口径）

为了实现数据驱动的升级，每个模块的定义中都需要包含以下与升级相关的属性：

```typescript
// 概念性数据结构
interface Module {
  id: string; // 模块的唯一ID，如 "laser_cannon_1"
  name: string; // 显示名称，如“1级激光炮”

  // ... 其他模块属性（质量、船体、耗电等）

  techTree: string; // 所属的科技树分支，如 "laser_weapons"
  tier: number; // 该模块在此科技树中的层级
}
```

### 2.1 科技解锁（口径）

在《科技树与分类.md》中定义的科技，其`unlocks`字段应包含解锁新模块的信息。

```typescript
// 科技解锁示例
const techExample: Technology = {
  id: "tech_lasers_2",
  name: "2级激光",
  // ... 其他科技属性
  unlocks: [
    { type: "Module", id: "laser_cannon_2" } // 解锁了2级激光炮
  ]
};
```

---

## 3. 原地升级机制 (In-Place Upgrade)

“原地升级”是玩家在解锁了新科技后，对现有舰船进行强化的核心机制。

### 3.1 触发条件

- 当一艘舰船停靠在**船坞**中。
- 且该舰船上安装的某个模块（如“1级激光炮”）存在一个**已解锁的、更高层级的版本**（如“2级激光炮”）。

### 3.2 升级流程

1.  **检测可升级项**：UI会高亮显示该舰船上所有可升级的模块。
2.  **玩家确认**：玩家选择“升级”该舰船。
3.  **资源消耗**：系统计算所有模块升级所需的**资源差价**和**时间**，并从国库中扣除。
4.  **模块替换**：在船坞中，旧模块被自动替换为对应科技树分支下的、当前已解锁的**最高级版本**。

**示例**：
- 一艘船上装有“1级激光炮”。
- 玩家先后研究了“2级激光”和“3级激光”。
- 当这艘船进入船坞并选择升级时，其“1级激光炮”会**直接被替换为“3级激光炮”**。

### 3.3 约束

- **不改变蓝图**：原地升级**不**会修改原始的舰船设计蓝图。如果玩家想让新造的船直接使用新模块，他们需要手动更新蓝图。
- **只升不降**：升级是单向的，不能将高级模块降级为低级模块。
