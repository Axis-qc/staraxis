# 客户端设计方案（单机模式，最终敲定，可直接落地）

> 本文档目标：给出一套**可直接实现**的 StarAxis 单机客户端架构与界面流程方案。
>
> 设计约束（强制）：
> - **单机权威**：本地进程内 `WorldState` 是唯一权威世界状态。
> - **ID 索引模型**：所有实体通过 ID 引用（如 `countryId`、`planetId`、`fleetId` 等）。
> - **对象引用生命周期**：对象引用生命周期为 **一个 tick**；跨 tick 必须仅持有 ID 或可失效引用结构。
> - **UI 独立系统（强制）**：UI 必须是独立系统，界面在加载期完成创建（预构建），运行时只做数据绑定/状态切换，禁止“运行时临时拼 UI”。
>
> 参考：
> - `docx/00-通用规范与治理/核心规范.md`

---

## 0. 单机客户端在整体架构中的位置

单机客户端负责：

1. **启动与界面导航**：主菜单/流程切换/弹窗。
2. **世界状态与模拟推进**：管理 `WorldState`，驱动 `simulationTick` 推进。
3. **系统模块调度**：启动并驱动经济/战斗/AI 等系统在模拟节拍下运行。
4. **渲染与交互**：渲染世界与 UI，处理输入。
5. **存档读写**：保存/加载世界状态文件（存档系统具体设计见专门文档）。

> 本文档只描述“客户端侧流程与边界”，不规定实现技术栈（例如 UI 方案/渲染方案）。

---

## 1. 客户端分层（建议）

客户端代码建议按以下层次组织（尽量避免跨层直接写入内部状态）：

- **App Layer（应用层）**
  - 负责启动、页面导航（主菜单/新游戏/加载/设置等）、生命周期管理（退出、暂停）。

- **World Layer（世界层）**
  - 维护 `WorldState`（权威世界状态，常驻内存）。
  - 提供基于 ID 的查询/修改入口（例如 `getPlanet(planetId)` / `updatePlanet(planetId, ...)`）。

- **Simulation Layer（模拟层）**
  - 维护 `simulationTick` / `simulationDay` 等模拟时间。
  - 驱动系统模块：经济、战斗、外交、AI、事件等。

- **Render Layer（渲染层）**
  - 将世界状态/派生表现态渲染到屏幕。

- **UI System（UI 独立系统）**
  - 独立于世界渲染对象的 HUD/面板系统。
  - UI 通过订阅数据源（例如选择态、摘要快照）来更新显示。

---

## 2. 启动流程与初始界面（主菜单）

### 2.1 启动进入主菜单

- 启动客户端后，默认进入**主菜单（开始界面）**。
- 主菜单需要显示以下入口（顺序可按 UI 设计调整）：
  - **新游戏**
  - **加载游戏**
  - **多人游戏（未来规划）**
  - **舰船设计器**
  - **设置**
  - **退出游戏**

### 2.2 主菜单入口行为

- **新游戏**：进入“国家选择界面”。
- **加载游戏**：进入“存档管理界面”。
- **多人游戏（未来规划）**：弹出“开发中”提示。
- **舰船设计器**：进入“舰船设计界面”。
- **设置**：进入“游戏设置界面”。
- **退出游戏**：点击后直接退出客户端。

---

## 3. 新游戏流程（国家选择 → 世界生成 → 进入游戏）

### 3.1 国家选择界面

目标：玩家选择或创建一个国家，然后进入世界生成。

功能要求：
- 支持 **选择预设国家**。
- 支持 **创建新国家**（最小字段可包括名称、旗帜/颜色、初始特性等）。
- 确认后进入“世界生成界面”。

产出：
- `countryId`（玩家国家 ID）
- 国家基础设定数据（写入 `WorldState` 或新游戏初始化上下文）

### 3.2 世界生成界面

目标：玩家调整世界生成参数，确认后生成世界并进入游戏。

功能要求：
- 展示并允许调整世界生成参数（示例）：
  - 星系数量/密度
  - 星球数量范围
  - 资源丰度/分布
  - 初始势力数量
  - 随机种子（可选：可输入/可随机）
- 点击“开始生成”后进入世界生成过程。

产出：
- 新的 `WorldState`（包含星区/恒星系/星球等实体集合，以 ID 索引）
- 初始 `simulationTick`/`simulationDay`

### 3.3 世界生成与进入游戏

- 世界生成完成后：
  1. 初始化核心系统模块（经济/战斗/外交/AI 等）。
  2. 启动模拟时间推进（开始递增 `simulationTick`）。
  3. 切换到“正常游戏流程”（进入主游戏界面）。

---

## 4. 加载游戏流程（存档管理 → 读档 → 进入游戏）

### 4.1 存档管理界面

目标：列出存档并提供基本管理能力。

功能要求：
- 列表显示存档条目（如存档名、时间、游戏进度摘要）。
- 支持：
  - 选择存档并加载
  - 删除/重命名（可选）

### 4.2 读档与进入游戏

- 读取存档后：
  1. 从存档文件恢复 `WorldState`（以 ID 索引的数据结构）。
  2. 恢复 `simulationTick`/`simulationDay`。
  3. 初始化/恢复系统模块运行状态。
  4. 进入“正常游戏流程”（主游戏界面）。

> 存档系统具体格式、版本迁移、原子性等要求见《存档系统》专门文档。

---

## 5. 多人游戏（未来规划）

- 当前点击“多人游戏”直接弹出 **开发中** 提示。
- 不进入任何实际流程。

---

## 6. 舰船设计器（游戏外蓝图编辑）

目标：允许玩家在游戏外设计舰船蓝图，并在游戏内使用。

功能要求：
- 进入舰船设计界面后：
  - 新建/编辑/保存舰船蓝图
  - 管理蓝图列表
- 蓝图数据应与游戏存档数据解耦：
  - 蓝图可作为独立资源文件或独立存档域（具体由“舰船蓝图系统”文档定义）。

---

## 7. 设置（基础图形/系统设置）

目标：提供基础游戏设置。

建议包含（不限于）：
- 渲染分辨率
- 最大帧数
- 是否全屏
- 画面质量/图形选项
- 音量/输入等基础设置（可选）

---

## 8. 退出游戏

- 点击“退出游戏”后直接退出客户端。

---

## 9. 正常游戏流程（进入游戏后）

本文档只给出单机模式下的最低边界：

- 游戏进行时：
  - `simulationTick` 按固定节拍推进。
  - 经济/战斗等系统根据 tick 更新 `WorldState` 中对应实体（通过 ID 索引）。
  - 渲染/UI 从世界状态或派生摘要中读取数据展示。

---

## 10. 最小验收清单

- 启动进入主菜单，显示 6 个按钮：新游戏、加载游戏、多人游戏（开发中）、舰船设计器、设置、退出游戏。
- 新游戏流程可从：国家选择 → 世界生成参数 → 生成世界 → 进入主游戏流程。
- 加载游戏进入存档管理界面，选择存档后进入主游戏流程。
- 多人游戏按钮弹“开发中”提示。
- 舰船设计器进入独立设计界面。
- 设置界面可修改基础图形设置。
- 退出游戏可直接退出客户端。
